# 프론트엔드 참여 테스트 (`/my/participations`)

테스터가 지원하고 참여한 테스트를 한곳에서 관리하는 화면이 지켜야 하는 요구사항(R)과 시나리오(S)를 모았다. S번호는 홈(S2~S82)과 겹치지 않게 S83부터 매기고(S103·S104는 나중에 더했다. 리뷰 반영으로 더한 S191·S192는 다른 문서와 겹치지 않게 비어 있는 다음 번호를 썼다), `frontend/e2e/participations.spec.ts`(상세는 `participation-detail.spec.ts`)의 테스트 이름과 1:1로 맞는다(S102는 grep으로 확인). 상세 시나리오 S193~S202와 리뷰 반영 S285도 비어 있는 다음 번호를 썼다. 테스트를 추가하거나 바꾸면 이 문서도 함께 고친다.

## 한눈에
- 누가: 로그인한 테스터. 비로그인은 로그인으로 보낸다.
- 무엇을: "다음에 뭘 해야 하지?"에 바로 답한다. 피드백 제출 마감, 크레딧 지급 시점, 선정 결과를 지원 순서가 아니라 급한 순서로 보여 준다.
- 화면 구성(위에서부터):
  1. 공통 헤더(홈과 같음). "참여 테스트" 탭이 현재 탭이다
  2. 페이지 제목 "참여 테스트"와 한 줄 요약(제출할 피드백 n개, 지급 대기 n크레딧)
  3. 다음 할 일: 피드백 제출 전 테스트를 마감 순으로 모은 카드 띠. 넓은 화면 2개, 좁은 화면 1개씩 보이고 위쪽 이전·다음 버튼으로 넘긴다. 주 버튼은 맨 앞 카드에만
  4. 탭 3개: 지원한 테스트 / 참여 중인 테스트 / 참여했던 테스트 (개수 표시)
  5. 선택한 탭의 참여 목록(행 카드)
  6. 상세(`/my/participations/:participationKey`): 진행 상황, 피드백 작성 또는 제출한 피드백, 테스트 정보
- URL: `page-urls.md`의 참여 테스트 섹션을 따른다. 탭은 `?tab=applied|ongoing|history`, 상세는 `/my/participations/:participationKey`(`page-urls.md`에서는 아직 후보).
- 디자인: `frontend/DESIGN.md`와 `docs/design-tokens.html`의 토큰·컴포넌트를 그대로 쓴다. 새 색이나 새 버튼 스타일을 만들지 않는다.
- 데이터: 목업이다. `demo-role`, `demo-data` 쿠키로 상태를 바꾼다(홈과 같은 장치).

## 참여 상태와 탭
README의 흐름(지원 → 참여 확정 → 테스트 → 피드백 제출 → 72시간 신고 대기 또는 운영자 검토 → 지급)을 아래 상태로 나눈다. 탭은 상태를 묶은 것이다.

| 탭 | 상태 | 화면 문구 | 행에서 보여 줄 날짜 | 행 동작 |
| --- | --- | --- | --- | --- |
| 지원한 테스트 `applied` | 선정 대기 | "선정 대기" | 모집 마감일 | 모집 글 보기 |
| | 미선정 | "미선정" | 모집 마감일 | 모집 글 보기 |
| 참여 중인 테스트 `ongoing` | 제출 전 | "피드백 제출 전" + D-day | 피드백 제출 마감일 | 피드백 쓰기 |
| | 지급 대기 | "지급 대기" | 지급 예정 일시(제출 + 72시간) | 제출 내용 보기 |
| | 운영자 검토 | "운영자 검토 중" | 제출일 | 제출 내용 보기 |
| 참여했던 테스트 `history` | 지급 완료 | "지급 완료" + 받은 크레딧 | 지급일 | 상세 보기 |
| | 미완료 | "기한 내 미제출" | 피드백 제출 마감일 | 상세 보기 |
| | 보상 제외 | "보상 제외" | 검토 완료일 | 상세 보기 |

- 무료 모집은 선착순 확정이라 지원과 동시에 "참여 중"으로 간다. "지원한 테스트"에는 구독 모집(개발자가 직접 선정)만 남는다.
- 상태 문구는 존댓말 해요체로 쓰고, 운영 용어(신고, 제재)는 행에서 직접 쓰지 않는다.

## 1. 접근과 역할 (R1)
로그인한 사용자만 들어오고, 데모 테스터에게는 샘플 참여 내역이 보인다.

S83 비로그인
- Given `demo-role=guest`
- When  `/my/participations?tab=history`에 접속한다
- Then  URL이 `/login?next=%2Fmy%2Fparticipations%3Ftab%3Dhistory`이다 (탭까지 기억한다)

S84 테스터
- Given `demo-role=tester` (또는 쿠키 없음)
- Then  HTTP 200이고 제목 "참여 테스트"가 보인다
- Then  헤더의 "참여 테스트" 탭에 `aria-current="page"`가 있다

S85 개발자·운영자
- Given `demo-role=developer`
- Then  HTTP 200이고 빈 상태 "아직 참여한 테스트가 없어요"와 "테스트 둘러보기"(`/recruitments`)가 보인다

## 2. 탭 (R2)
탭 상태는 URL `tab`에 남고, 탭은 링크다. 각 탭에 개수를 보여 준다.

S86 기본 탭
- When  `/my/participations`에 접속한다
- Then  "참여 중인 테스트" 탭이 현재 탭이다 (`aria-current="page"`)
- Then  탭 3개가 순서대로 있다: 지원한 테스트 `?tab=applied`, 참여 중인 테스트 `?tab=ongoing`, 참여했던 테스트 `?tab=history`

S87 개수
- Then  탭 이름 옆에 개수가 보인다: 지원한 2, 참여 중 6, 참여했던 3

S88 탭 이동
- When  "참여했던 테스트"를 누른다
- Then  URL이 `/my/participations?tab=history`이고 그 탭이 현재 탭이다
- When  뒤로 가기를 누른다
- Then  "참여 중인 테스트" 탭으로 돌아온다

S89 알 수 없는 탭
- Given `?tab=foo`로 연다
- Then  HTTP 200이고 기본 탭(참여 중)을 보여 준다

## 3. 다음 할 일 (R3)
피드백 제출 전인 참여를 모두 마감이 가까운 순서로 카드 띠에 담는다. 한 화면에 md 이상은 2개, 그보다 좁으면 1개가 보이고, 넘치면 제목 오른쪽의 이전·다음 버튼으로 한 화면씩 넘긴다. 띠에는 스크롤바가 없고 손으로(스와이프·트랙패드) 넘기지 않는다. 넘치지 않으면 버튼이 없다. 위치는 맨 앞에 보이는 카드 번호로 기억해서, 화면 폭이 바뀌어 한 화면의 카드 수나 카드 폭이 달라져도 그 카드가 띠 왼쪽 끝에 맞는다. 모션 줄이기(`prefers-reduced-motion: reduce`)에서는 애니메이션 없이 바로 넘긴다. 제목 옆에 전체 개수를 둔다. 이 화면의 주 버튼(강조색)은 맨 앞 카드의 버튼 하나뿐이고, 나머지 카드는 보조 버튼이다.

S90 맨 앞 카드
- Then  첫 카드에 "회의록 정리"와 "D-8"이 보이고, 주 버튼 "피드백 쓰기"가 그 참여의 상세(`/my/participations/:participationKey`)를 가리킨다
- Then  화면의 강조색 바탕 버튼은 이것 하나다

S103 넓은 화면 2개
- Then  너비 1440px에서 앞의 두 카드("회의록 정리", "중고책 장터")가 같은 줄에 모두 화면 안에 보인다
- Then  "중고책 장터 피드백 쓰기"는 보조 버튼이고 그 참여의 상세를 가리킨다

S104 버튼으로 넘기기
- Then  제목이 "다음 할 일 4"이고 카드 4개가 회의록 정리(D-8) → 중고책 장터(D-12) → 가계부 노트(D-14) → 모아플랜(D-16) 순서다
- Then  띠의 `overflow-x`가 `hidden`이다 (스크롤바·손으로 넘기기 없음)
- Then  처음에는 "이전 할 일"이 비활성이고 셋째 카드는 보이지 않는다
- When  "다음 할 일"을 누른다
- Then  셋째·넷째 카드가 보이고 "다음 할 일"이 비활성이다
- When  "이전 할 일"을 누른다
- Then  첫 카드가 다시 보이고 "이전 할 일"이 비활성이다

S191 화면 폭이 바뀌어도 카드 정렬 유지
- Given 너비 500px (한 화면 1개)
- When  "다음 할 일"을 눌러 둘째 카드를 본 뒤 너비를 900px(한 화면 2개)로 넓힌다
- Then  둘째·셋째 카드가 모두 보이고 둘째 카드가 띠 왼쪽 끝에 맞는다 (첫 카드는 보이지 않는다)
- When  다시 500px로 줄인다
- Then  둘째 카드가 띠 왼쪽 끝에 맞는다

S192 모션 줄이기
- Given `prefers-reduced-motion: reduce`
- When  "다음 할 일"을 누른다
- Then  누른 직후 띠의 스크롤 위치가 이미 한 화면(띠 폭 + 간격)만큼 옮겨져 있다

S91 없음
- Given 제출 전 참여가 없다 (`demo-data=empty`)
- Then  다음 할 일 영역이 없다

## 4. 참여 목록 (R4)
행 카드는 활자 썸네일 → 이름·요청 문구 → 상태 → 날짜 → 보상 → 동작 순서로 고정한다. 정렬은 탭마다 하나로 정하고 바꾸는 장치는 두지 않는다.

S92 참여 중 정렬
- Then  "참여 중인 테스트"의 행이 할 일 순서다: 제출 전(제출 마감 가까운 순) → 지급 대기 → 운영자 검토
- Then  첫 행이 "회의록 정리"다

S93 행 내용
- Then  각 행에 서비스 이름 활자 썸네일, 요청 문구(모집 글의 `request`, 예: "회의록 작성 후 할 일 목록이 맞는지 보기"), 상태 문구(위 표의 화면 문구, 예: "피드백 제출 전"), 날짜, 기본 보상이 있다
- Then  구독 모집 행에만 썸네일 오른쪽 위에 "추가 보상" 배지가 있다 (강조색)

S94 지급 대기
- Then  "스터디 매칭" 행에 "지급 대기"와 지급 예정 일시가 보인다
- Then  "72시간 동안 신고가 없으면 자동으로 지급돼요" 안내가 있다

S95 지원한 테스트
- Given `?tab=applied`
- Then  "북로그"(선정 대기), "레시피핏"(미선정) 2행이 있고, 선정 대기가 먼저다
- Then  각 행의 "모집 글 보기"가 `/recruitments/:slug`를 가리킨다

S96 참여했던 테스트
- Given `?tab=history`
- Then  최근 순으로 3행이 있고, 맨 위에 "받은 크레딧 합계"가 지급 완료 행의 합으로 보인다
- Then  "지급 완료" 행의 썸네일에 "지급 완료" 도장(`role="img"`)이 있다

## 5. 빈 상태 (R5)
탭마다 빈 상태 문구가 다르고, 다음 행동 하나를 보조 버튼으로 준다.

S97
- Given `demo-data=empty`
- Then  지원한: "지원한 테스트가 없어요", 참여 중: "참여 중인 테스트가 없어요", 참여했던: "아직 끝난 테스트가 없어요"
- Then  세 빈 상태 모두 "테스트 둘러보기"(`/recruitments`)가 있다
- Then  탭 개수는 모두 0이다

## 6. 로딩 (R6)
제목과 탭은 데이터를 기다리지 않고, 목록은 행 모양 스켈레톤을 먼저 보여 준다.

S98
- Given `demo-data=slow` (1.5초 지연)
- When  접속한다 (응답 시작 직후)
- Then  제목과 탭 3개가 이미 보이고 행 스켈레톤이 보인다
- Then  응답 뒤 행이 보이고 스켈레톤은 없다

## 7. 반응형 (R7)
리스트의 행 카드는 lg 이상에서 가로 한 줄(썸네일 | 내용(요청·상태·날짜·보상) | 동작), lg 미만에서 위아래로 쌓인다. 그리드의 배치는 R203을 따른다.

S99 좁은 화면
- Given 너비 375px
- Then  가로 스크롤이 없다
- Then  탭 3개가 한 줄에 보이고, 넘치면 탭 줄만 가로로 넘긴다
- Then  다음 할 일 카드는 한 장씩 꽉 차게 보이고 첫 카드가 왼쪽 여백 16px에 맞춰진다
- Then  위쪽 "다음 할 일" 버튼을 누르면 둘째 카드가, "이전 할 일"을 누르면 첫 카드가 보인다
- Then  카드의 버튼이 카드 전체 폭이다

## 9. 접근성 (R9)
키보드만으로 탭을 바꾸고 행 동작을 쓸 수 있다.

S101

## 10. 구조 (R10)
홈과 같은 규칙을 지킨다. 탭은 서버에서 URL로 처리해 새 클라이언트 컴포넌트를 만들지 않는다.

- When  `grep -rln "mock" src --include='*.tsx'`
- Then  결과가 없다

## 11. 상세 접근 (R11)
내 참여 상세 `/my/participations/:participationKey`는 그 참여의 테스터만 본다. 시나리오 S193~S202는 `frontend/e2e/participation-detail.spec.ts`에 있다.

S193 비로그인
- Given `demo-role=guest`
- When  `/my/participations/p-meeting-notes`에 접속한다
- Then  URL이 `/login?next=%2Fmy%2Fparticipations%2Fp-meeting-notes`이다

S194 없거나 내 참여가 아님
- When  테스터가 `/my/participations/nope`에, 개발자가 테스터의 참여 주소에 접속한다
- Then  맞춤 404("찾는 페이지가 없어요")가 보인다 (개발자 프로젝트 S103과 같은 방식)

## 12. 제출 전 상세와 피드백 작성 (R12)
제출 전이면 상세 안에서 피드백을 쓴다. 목록의 "피드백 쓰기"가 이 화면을 가리키므로 따로 URL을 만들지 않는다. 이 화면의 주 버튼은 "피드백 제출" 하나다.

S195 제출 전 상세

## 디자인 메모
- 강조색(One Green Rule): 다음 할 일 맨 앞 카드의 주 버튼, 추가 보상(목록은 썸네일 배지, 상세는 줄), "지급 완료" 도장, 포커스만. 상태 배지와 D-day는 강조색을 쓰지 않는다.
- 상태 배지: `Badge`(칩 회색 알약). 급한 정도는 굵기로만 나타낸다(Weight-Not-Paint). D-3 이하는 800 굵기 먹색.
- 탭: 헤더 탭과 같은 알약 탭 모양(현재 탭은 칩 회색 바탕). 개수는 `tabular-nums`, 흐린 먹.
- 행 카드: 교정지(surface-muted) 16px 면, 안쪽 24px. 리스트의 썸네일은 폭 192px로 고정한 16:10이다. 좁은 화면에서도 추가 보상 배지가 재단선과 도장을 가리지 않는 폭이다.
- 다음 할 일: 교정지 카드 띠(바탕 없는 섹션 안에 카드). 이전·다음은 보조 버튼(칩 회색 알약, 아이콘만)이고 끝에 닿으면 비활성이다. 한 번에 한 화면의 카드 수만큼 넘기고, 위치를 카드 번호로 계산해 카드가 항상 왼쪽 끝에 맞는다. 이징은 브라우저 기본 부드러운 스크롤이고, 모션 줄이기에서는 바로 이동한다. 재단선·CMYK 막대(`ProofMarks`)는 히어로 전용이라 쓰지 않는다.
- 상세: 썸네일은 제목과 이름이 겹쳐 보조 기술에서 숨기고, 상태는 배지 글자로 읽힌다. 테스트 정보는 모집 글에 대한 정보라 제목 바로 아래에 목록 행과 같은 모양(작은 항목 이름 + 굵은 값)으로 둔다(10-31: 오른쪽 카드는 따로 떨어져 보인다는 피드백으로 옮김). 진행 상황은 바탕 없이 제목·본문, 피드백 작성·제출한 피드백은 교정지 카드다. 피드백 칸은 프로젝트 폼과 같은 12px 모서리 입력 칸(`inputClass`)이고, 제출 버튼은 알약 주 버튼이다(금액 폼이 아니라 The Money Field Rule 대상이 아니다).
- 보기 방식: 채팅함 역할 탭(`ChatFilters`)과 같은 세그먼트 모양에 아이콘만 둔다. 이름은 `aria-label`과 마우스를 올렸을 때 뜨는 `title`로 알린다. 목록 맨 위 줄 오른쪽에 놓고, 참여했던 테스트에서는 왼쪽에 받은 크레딧 합계가 온다.
- 그림자 없음, 이징은 `--ease-brand` 하나.

## 데모 데이터와 가정
- 테스터 "한서윤"의 참여 11건은 시연용 샘플이다. 개발자·운영자 데모 계정은 참여 내역이 없다. 진행 중인 건은 홈 목업의 모집 글을 가리키고, 끝난 건은 새로 만든 지난 모집 글 3개("메모 정원", "주차 알리미", "카페 지도")를 쓴다.

  - 참여 중(6): 회의록 정리(제출 전, 제출 마감 D-8), 중고책 장터(제출 전, D-12), 가계부 노트(제출 전, D-14), 모아플랜(제출 전, D-16), 스터디 매칭(지급 대기, 지급까지 약 30시간), 동네 러닝 크루(운영자 검토 중)
  - 참여했던(3): 메모 정원(지급 완료), 주차 알리미(지급 완료), 카페 지도(기한 내 미제출)

- 미선정은 "지원한 테스트"에 남긴다(참여하지 않았으므로 "참여했던"이 아니다).

- 피드백 글자 수는 기획에서 미정이라 20~500자로 정했다. 최대 길이는 시연용 저장(쿠키) 한도에 맞춘 값이다.
- 샘플 중 지급 대기·운영자 검토 중·지급 완료 4건에는 시연용 피드백 원문을 넣었다. "보상 제외" 샘플은 없어서 그 상태의 상세는 E2E로 확인하지 않는다.
- D-3 이하가 아니면 D-day는 600 굵기 흐린 먹이다. 끝난 상태(미선정, 기한 내 미제출, 보상 제외) 배지는 흐린 배지(`Badge tone="muted"`)다.

## 정한 것
- 피드백 작성 위치: 상세 페이지 안에서 쓴다. 별도 URL을 만들지 않는다 (10-31)
- "보상 제외": "운영자 검토 결과 이번 참여는 보상에서 제외됐어요"와 검토 완료일만 보여 주고 사유는 보여 주지 않는다 (10-31)

## 정해야 할 것
- `page-urls.md`의 "내 참여 상세"를 후보에서 확정으로 바꿀지
- 피드백 제출 화면 담당: 개발자 프로젝트 문서는 "피드백 제출 화면은 다른 담당"이라고 적고 있다. 이 문서에서 상세 안에 만들었으니 그 문구를 맞출지
- 기본 탭: "참여 중"(이 문서의 가정) vs 첫 번째 탭 "지원한"
- 미선정 건을 "지원한"에 계속 둘지, 일정 기간 뒤 숨길지
- 지원 취소: 선정 대기 중 취소를 허용할지. 허용하면 행 동작과 확인 대화상자가 필요하다
- 채팅 진입: 구독 모집에 선정된 테스터에게 행에서 채팅방(`/my/chats/:roomKey`) 링크를 줄지
