# 테스트 계층 분리의 검증 범위

E2E를 줄이며 어떤 검사를 옮겼고 무엇을 자동 확인에서 제외했는지 기록한다. 시나리오 번호는 기존 것을 유지한다. 모든 삭제를 단위 테스트로 대체한 것은 아니다. 아래 표의 규칙 검사와 화면 연결 검사는 서로 다른 범위를 확인한다.

## 리뷰 순서

1. 위 표에서 검증이 이동한 부분과 제외한 부분을 구분한다. 필요한 전체 시나리오는 `docs/frontend/`의 각 페이지 문서에서 확인한다.
2. 단위로 옮긴 규칙이 제품에서 실제 호출되는 함수인지, 남긴 E2E가 해당 경로를 확인하는지 본다. 표만으로 충분한 검증이라고 가정하지 않는다.
3. PR에 적힌 검증 대상 커밋·CI 실행·미실행 범위를 확인한다. 재실행과 재리뷰 범위는 [검증·로그·리뷰 기준](testing.md#pr-작성과-리뷰)을 따른다.
