# 문서

계획·요구사항 문서를 어디에 두고 무엇을 쓰는지 정한 규칙이다.

## 위치
파일 이름에는 날짜를 넣지 않는다. 같은 페이지나 도메인의 문서가 이미 있으면 그 문서를 고친다.

| 문서 | 위치 | 예 |
| --- | --- | --- |
| 프론트엔드 페이지 | `docs/frontend/<도메인>/<페이지>.md` | `docs/frontend/chat/chat-room.md` |
| 여러 도메인을 모아 보여 주는 화면 | `docs/frontend/<페이지>.md` | `docs/frontend/my.md`(마이페이지), `home.md`, `header.md` |
| 백엔드 도메인 전체 | `docs/backend/<도메인>/README.md` | `docs/backend/chat/README.md` |
| 백엔드 이슈 하나 | `docs/backend/<도메인>/<기능>.md` | `docs/backend/chat/entities.md` |
| 여러 페이지·도메인 공통 | `docs/<이름>.md` | `docs/page-urls.md` |
| 여러 페이지·도메인 공통이고 한 파일로 길어 나눈 것 | `docs/<이름>/README.md`와 나눈 파일 | `docs/frontend-structure/`(프론트 폴더 구조) |

## 도메인 폴더
프론트와 백엔드는 같은 도메인 이름을 쓴다: `admin`(운영자 화면만), `auth`, `chat`, `payment`, `project`. 새 도메인이 생기면 양쪽에 같은 이름으로 만든다. 프론트 폴더에는 공통 결정이 생길 때만 `README.md`를 둔다.

- 백엔드 `README.md`는 여러 이슈에 걸친 것을 모은다: 이슈와 문서 표(이슈 링크, 내용, 문서 링크), 정한 것(항목 끝에 이슈 번호와 날짜), 데이터 구조 요약, 아직 정하지 않은 것.
- `<기능>.md`는 이슈 하나의 계획이다: 요구사항과 시나리오, 범위 밖, 작업 순서, 가정, 참고. `README.md`의 결정은 링크로 가리킨다.
- 기능 문서는 그 이슈를 시작할 때 만든다. 그 전까지 이슈의 내용은 `README.md`에 둔다.
- 프론트 페이지 문서와 같은 이름의 백엔드 도메인 폴더는 서로 링크한다. 페이지 문서 머리말에 백엔드 `README.md`를, 백엔드 `README.md`에 페이지 문서를 적는다.

## 쓰는 것
문서에는 코드와 git, GitHub로 알 수 없는 것을 쓴다: 결정과 그 이유, 시나리오, 가정, 아직 정하지 않은 것, 외부 근거.

- 진행 상태는 이슈 링크로 두고 GitHub에서 본다.
- 동작이 바뀌면 바뀐 시나리오나 결정 끝에 `(고침 #이슈: 이유)`를 붙인다. 바뀐 이유는 바뀐 자리에 둔다.
- 참고에는 병합한 뒤에도 맞는 사실을 쓴다: 라이브러리·DB 동작, 설정만 봐서는 모르는 함정, 외부 문서. 작업하던 때의 코드 상태(무엇이 아직 없는지)는 계획을 세울 때만 쓴다.
