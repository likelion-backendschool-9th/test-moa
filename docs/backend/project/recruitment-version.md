# 모집글 버전 매기기 (#177)

모집 작성 API(#92)가 모집글 버전을 프로젝트마다 1, 2, 3으로 매기게 한다. AI 버전 간 비교([#108](ai-version-comparison.md))가 직전 버전을 찾을 수 있게 하는 것이 목적이고, 도메인 전체에서 정한 것은 [README.md](README.md)에 있다.

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`는 백엔드 테스트와 1:1이다(`@DisplayName("#177-S…")`).

## 이슈 #177 확인

| 이슈 항목 | 시나리오 |
| --- | --- |
| 1 프로젝트의 첫 모집은 버전 1 | #177-S1 |
| 2 같은 프로젝트에 또 작성하면 2, 3으로 올라가고 다른 프로젝트와는 따로 센다 | #177-S1 |
| 3 취소한 모집도 번호를 차지한다 | #177-S1 |

## 1. 버전 규칙 (#177-R1)

11-08 팀 결정: 같은 프로젝트에 모집을 새로 올릴 때마다 1, 2, 3으로 번호가 올라가고, 글을 수정해도 번호는 그대로다. 분석할 콘텐츠의 순서를 버전이라는 이름으로 관리하는 것이 목적이다.

- 새 모집글의 버전은 그 프로젝트의 가장 큰 버전 + 1이다. 모집글이 없으면 1이다
- 취소한 모집글도 번호를 차지한다. 번호를 다시 쓰면 버전 비교의 순서가 꼬인다
- 번호를 세기 전에 프로젝트 행을 잠근다(`PESSIMISTIC_WRITE`, 그룹 코드 발급과 같은 잠금). 같은 프로젝트에 동시에 작성해도 차례로 번호를 받는다
- 모집 작성 요청과 응답은 그대로다. 프론트는 바꾸지 않는다
- 모집글 수정 API는 아직 없다. 만들 때 버전을 바꾸지 않는다

#177-S1 프로젝트마다 1, 2, 3 [테스트]
- When  프로젝트 "북로그"에 모집을 두 번 작성한다
- Then  버전 1, 2로 저장된다
- When  다른 프로젝트에 처음 작성한다
- Then  버전 1이다
- Given "북로그"의 버전 2를 취소했다
- When  다시 작성한다
- Then  버전 3이다

#177-S2 기존 모집 뒤로 이어진다 [테스트]
- Given 이 규칙 전에 저장돼 버전이 모두 1인 모집 2개가 있는 프로젝트
- When  모집을 두 번 작성한다
- Then  버전 2, 3이다

#177-S3 같은 프로젝트에 동시에 모집 작성 [테스트]
- When  같은 개발자가 같은 프로젝트에 동시에 5번 작성한다
- Then  모두 201이고 버전은 1, 2, 3, 4, 5다
- 참고: 잠금을 빼면 다섯 개 모두 버전 1이 되어 이 테스트가 실패하는 것을 확인했다

## 범위 밖
- 이미 저장된 모집글의 버전 고치기. 테스트 서버의 기존 모집글은 모두 1로 두고 새 모집부터 이어서 올린다(#177-S2)
- 화면에 버전 표시

## 가정
- 같은 버전이 여럿인 기존 데이터는 버전 비교가 나중에 만든 모집글을 직전 버전으로 고른다([ai-version-comparison.md](ai-version-comparison.md) 결정 1). 이 규칙 뒤로 새로 생기는 번호는 겹치지 않는다
