# 검증 실행과 로그 확인

AI가 검증하면서 읽는 코드·로그와 반복 호출을 줄이는 기준이다. 검사 종류와 필수 범위는 저장소의 기존 검증 기준을 따른다. 프론트엔드는 [README의 확인 명령](../frontend/README.md#확인-명령)을 참고한다.

## 검사 선택과 재실행

- 변경 파일과 호출 관계에서 필요한 검사를 고른다. 코드 조회는 diff와 관련 함수·설정부터 시작하고, 해결하지 못한 질문이 있을 때 범위를 넓힌다.
- 문서만 바꾸면 `git diff --check`로 끝낸다. 커밋·PR 생성이나 커밋 합치기 자체는 통과한 검사를 다시 실행하는 이유가 아니다.
- 테스트 대상, 호출되는 코드, 설정·의존성, 실행 환경이 그대로면 앞서 통과한 결과를 재사용한다. 이 중 하나가 바뀌었거나 결과가 없거나 실패 원인 확인이 필요하면 해당 검사만 다시 실행한다. rebase로 이 조건이 바뀌면 영향을 받은 검사를 확인한다.
- 테스트 목록 수집(`--list`)은 테스트 추가·삭제, 검색 조건 또는 수집 설정을 바꿨을 때 선택 범위를 확인하는 용도로 쓴다. 이미 확인한 목록과 개수는 그대로 재사용한다.

## 출력과 실패 분석

- 출력이 긴 검사는 표준 출력·오류를 저장소 밖의 임시 로그 파일에 함께 저장한다. 종료 코드를 보존하고 0일 때만 성공으로 판단한다. 파이프로 요약할 때도 원래 검사 명령의 종료 코드를 확인한다.
- 성공하면 통과 개수·실행 시간 등 마지막 요약 5줄 이내만 읽는다. 요약이 없는 검사는 종료 코드로 확인한다. 전체 성공 로그를 다시 출력하지 않는다.
- 실패하면 첫 조회는 실패한 검사 이름·오류와 관련 로그 최대 60줄로 제한한다. 원인을 설명할 증거가 부족하면 오류 위치를 검색해 필요한 구간만 추가로 읽는다. 원본 로그는 보존한다.
- 실패 재현은 실패한 테스트나 관련 파일부터 실행한다. 공통 원인이나 영향 범위가 확인되면 필요한 검사로 넓힌다. 같은 실패와 같은 로그의 반복 조회 대신 다음 실행이 확인할 가설을 정한다.
- 보고에는 실행 명령·범위·결과와 필요한 경우 원본 로그 경로를 적는다. 예전 결과를 재사용했거나 실행하지 않은 검사가 있으면 그 사실을 구분한다. 원본 CI 로그와 테스트의 검증 범위는 유지한다.
