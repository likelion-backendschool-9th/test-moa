# 프론트엔드 채팅방 (`/my/chats/:roomKey`)

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`만 e2e 테스트와 1:1이고, `[테스트: 파일 번호]`는 그 테스트가 대신 확인한다. `[명령]`은 명령 한 번, `[직접]`은 사람이 화면을 보고 확인한다. (고침 #56: `docs/test-cleanup.md`)

## 한눈에
- 끝나면: 채팅함 카드를 누르면 "준비 중" 대신 채팅방이 열린다. 위에서부터 "채팅함"으로 돌아가는 링크, 대화방 머리(프로젝트 이미지, 대화방 이름, 역할 배지와 대화 상대 닉네임, 모집 글 링크, 더보기), 날짜별로 나뉜 대화 내용, 화면 아래에 붙는 입력창이다. 내 메시지는 오른쪽 강조색(메인 색) 말풍선, 상대 메시지는 왼쪽 교정지 말풍선이다. Enter로 보내고 Shift+Enter로 줄을 바꾸며(휴대폰에서는 Enter가 줄바꿈이고 보내기 버튼으로 보낸다), 보낸 메시지는 채팅함 카드의 미리보기·일시·순서에도 반영된다. 더보기의 이름 변경·삭제도 채팅방에서 그대로 쓴다.
- 결정 필요: 없음 (채팅함 문서의 결정 필요 3 "채팅방 화면을 같이 만들지"를 이번에 만드는 것으로 정했다, 11-01 요청)
- 규모: 7단계

## 맥락
- 채팅함(`docs/frontend/chats.md`)은 목록만 만들고 채팅방은 "준비 중"으로 뒀다. 이번에 그 채팅방을 만든다.
- 채팅은 구독 개발자와 선정된 테스터의 1대1 소통이다 (README 주요 서비스 구성). 한 방에는 나와 대화 상대 두 사람만 있다.
- 백엔드에는 채팅 테이블이 아직 없고 실시간 연결(웹소켓 등)도 없다. 대화 기록은 목업으로 만들고, 보낸 메시지는 채팅함의 이름 변경·삭제처럼 시연용 세션 쿠키에 둔다. 상대의 답장은 오지 않는다.
- 디자인 토큰 문서와 채팅함의 분위기를 따른다: 작업대 바탕 위 교정지 면, 먹 글씨, 그림자·그라데이션 없음, 강조색은 정해진 자리에만.
- 채팅방도 마이페이지 메뉴가 없는 페이지다 (마이페이지 S97). 헤더의 현재 탭은 "채팅"이다.

## 1. 접근 제어 (R163)
비로그인 사용자는 로그인으로 보낸다. 내가 들어가 있지 않거나 삭제한 대화방은 열지 않는다.

S141 비로그인 [테스트: pages.spec.ts #56-S2]
- Given `demo-role=guest`
- When  `/my/chats/booklog-yunseul`에 접속한다
- Then  URL이 `/login?next=%2Fmy%2Fchats%2Fbooklog-yunseul`이다

S142 로그인 [직접]
- Given `demo-role=tester`
- When  `/my/chats/booklog-yunseul`에 접속한다
- Then  HTTP 200이고 h1 "북로그"가 있으며, 문서 제목은 "북로그 채팅방 · Test Moa"다
- Then  헤더의 "채팅" 탭에 `aria-current="page"`가 있고 "마이페이지 메뉴"는 없다

S143 들어갈 수 없는 대화방 [테스트]
- Given `demo-role=tester`
- When  다른 회원의 대화방 `/my/chats/ledger-saebyeok`과 없는 대화방 `/my/chats/nope`에 접속한다
- Then  둘 다 h1 "대화방을 찾을 수 없어요"와 "채팅함으로" 링크(`/my/chats`)가 보이고, 대화 내용과 입력창은 없다
- Then  검색엔진이 담지 않도록 `<meta name="robots" content="noindex">`가 있다

## 2. 대화방 머리 (R164)
대화방 머리는 채팅 카드와 같은 정보를 크게 보여 준다. 대화방 이름은 바꾼 이름이 있으면 그것, 없으면 프로젝트명이다. 내 닉네임은 쓰지 않는다. 역할 배지는 채팅 카드와 같은 모양이다 (채팅함 S322, 11-02).

S144 테스터 [직접]
- Given `demo-role=tester`, `/my/chats/booklog-yunseul`
- Then  "채팅함" 링크(`/my/chats`)가 맨 위에 있다
- Then  프로젝트 이미지 `/sample/projects/booklog.svg`, h1 "북로그", 배지 "개발자"와 그 오른쪽 상대 "서재지기"가 있다
- Then  "북로그 모집 글" 링크가 `/recruitments/booklog`로 간다
- Then  "북로그 채팅 더보기" 버튼이 있다

S145 개발자 [테스트]
- Given `demo-role=developer`, `/my/chats/ledger-yunseul`
- Then  h1 "가계부 노트", 배지 "테스터", 상대 "윤슬"이다
- Then  본문에 내 닉네임 "도현랩"이 없다

## 3. 대화 내용 (R165)
대화는 오래된 메시지가 위, 최근 메시지가 아래다. 날짜가 바뀌는 곳마다 날짜 구분이 들어가고, 맨 위에는 어느 모집 건의 대화방인지 한 줄로 알린다.

S146 순서와 날짜 [테스트]
- Given `demo-role=tester`, `/my/chats/booklog-yunseul`
- Then  "대화 내용" 기록(`role="log"`) 맨 위에 "북로그 모집 건으로 열린 1대1 대화방이에요."가 있다
- Then  날짜 구분은 h2이고, 첫 날짜는 "10월 29일 목요일" 꼴, 마지막 날짜는 "오늘"이다
- Then  첫 메시지는 "윤슬님, 북로그 테스트에 선정되신 걸 축하드려요. …", 마지막 메시지는 "피드백 마감이 이틀 남았어요. 막히는 부분 있으면 편하게 물어봐 주세요."다

S147 내 메시지와 상대 메시지 [직접] (고침 #60: 라이트 초록과 흰 교정지 변경)
- Then  내 메시지 "감사합니다! 오늘 저녁에 설치해서 써 볼게요."는 기록의 오른쪽 끝에 붙고, 바탕이 강조색(`rgb(15, 124, 74)`), 글씨가 흰색(`rgb(255, 255, 255)`)이다
- Then  상대 메시지 "피드백 마감이 이틀 남았어요. …"는 기록의 왼쪽 끝에 붙고, 바탕이 흰 교정지(`rgb(255, 255, 255)`)와 1px 안쪽 재단선으로 구분된다
- Then  보조 기술에는 메시지 앞에 보낸 사람이 "나:", "서재지기:"로 읽힌다

S148 묶음과 시각 [테스트]
- Then  같은 사람이 같은 분에 이어 보낸 "확인해 보니 사진을 한 번에 여러 장 올릴 때 생기는 문제였어요."와 "이번 주 업데이트에서 고칠게요." 중 뒤의 것에만 시각(`time`)이 있다
- Then  시각은 실행 환경과 관계없이 "오후 3:12" 꼴이고("AM/PM"이 아니다, 고침 11-02) `datetime`에 ISO 시각이 있다

## 4. 메시지 보내기 (R166)
입력창은 화면 아래에 붙어 있다. Enter로 보내고, Shift+Enter로 줄을 바꾼다. 휴대폰 같은 터치 기기(`pointer: coarse`)는 화상 키보드에 Shift+Enter가 없어서 Enter가 줄바꿈이고, 보내기 버튼으로만 보낸다 (11-02 요청). 한글을 조합하는 중에 누른 Enter는 글자 확정으로 보고 보내지 않는다. 보낸 메시지는 바로 내 말풍선으로 보이고, 새로고침해도 남는다.

S149 보내기 [테스트]
- Given `demo-role=tester`, `/my/chats/moaplan-yunseul`
- When  "메시지 입력"에 "주말에 일정 만들기부터 해 볼게요."를 쓰고 Enter를 누른다
- Then  기록의 마지막 메시지가 그 글이고 오른쪽 강조색 말풍선이며, 마지막 날짜 구분이 "오늘"이다
- Then  입력창은 비고 포커스가 그대로 입력창에 있다
- When  새로고침한다
- Then  마지막 메시지가 그대로 그 글이다
- When  `/my/chats`로 간다
- Then  첫 카드가 "모아플랜"이고 미리보기가 "주말에 일정 만들기부터 해 볼게요."이며 일시가 오늘(강조색)이다

S150 빈 메시지와 줄바꿈 [테스트]
- Then  입력창이 비었거나 공백뿐이면 "보내기" 버튼이 비활성이고, Enter를 눌러도 메시지 수가 그대로다
- When  "첫 줄"을 쓰고 Shift+Enter, "둘째 줄"을 쓰고 "보내기"를 누른다
- Then  마지막 메시지가 "첫 줄\n둘째 줄"이고 말풍선 안에서 두 줄로 보인다
- Then  입력창의 최대 글자 수는 500이다 (`maxlength="500"`)

S151 한글 조합 중 Enter [테스트]
- When  입력창에 "조합 중"을 쓰고, 조합 중인 Enter(`isComposing: true`)를 보낸다
- Then  메시지 수가 그대로이고 입력창에 "조합 중"이 남아 있다

S340 휴대폰의 Enter (11-02 요청) [테스트]
- Given 터치 기기(너비 375px, `isMobile`, `hasTouch`), `demo-role=tester`, `/my/chats/moaplan-yunseul`
- Then  입력창의 `enterkeyhint`가 `enter`이고, 입력창 설명이 "Enter로 줄을 바꾸고, 보내기 버튼으로 보내요."다
- When  "첫 줄"을 쓰고 Enter, "둘째 줄"을 쓴다
- Then  입력창이 "첫 줄\n둘째 줄"이고 메시지 수가 그대로다
- When  "보내기"를 누른다
- Then  마지막 메시지가 "첫 줄\n둘째 줄"이고, 포커스가 입력창에 그대로 있다 (키보드가 닫히지 않는다)
- Given 키보드 기기(너비 1280px)
- Then  `enterkeyhint`가 `send`이고, 입력창 설명이 "Enter로 보내고, Shift+Enter로 줄을 바꿔요."다
- When  "보내기"를 마우스로 누르거나, Tab으로 옮겨 Enter로 누른다
- Then  메시지가 보내지고 포커스가 입력창에 있다 (이어서 바로 쓸 수 있다)

## 5. 더보기 (R167)
채팅방 머리의 더보기는 채팅 카드와 같은 메뉴("대화방 이름 변경", 구분선, "대화방 삭제")다.

S152 이름 변경 [직접]
- Given `demo-role=tester`, `/my/chats/booklog-yunseul`
- When  "북로그 채팅 더보기" → "대화방 이름 변경"에서 "북로그 피드백 문의"로 바꾸고 "저장"을 누른다
- Then  h1이 "북로그 피드백 문의"가 되고, 더보기 버튼 이름도 "북로그 피드백 문의 채팅 더보기"가 된다
- When  "채팅함" 링크를 누른다
- Then  첫 카드 이름이 "북로그 피드백 문의"다

S153 삭제 [테스트]
- Given `demo-role=tester`, `/my/chats/moaplan-yunseul`
- When  "모아플랜 채팅 더보기" → "대화방 삭제" → "삭제"를 누른다
- Then  URL이 `/my/chats`이고 카드가 4개이며 "모아플랜"이 없다
- When  `/my/chats/moaplan-yunseul`에 다시 접속한다
- Then  "대화방을 찾을 수 없어요"가 보인다

## 6. 로딩 (R168)
"채팅함" 링크는 바로 보이고, 대화방은 `features/chat/api.ts`에서 받는 동안 머리·말풍선·입력창 모양 스켈레톤을 보여 준다.

S154 지연 [직접]
- Given `demo-data=slow`
- When  `/my/chats/booklog-yunseul`에 접속한다 (응답 시작 직후)
- Then  "채팅함" 링크와 "대화방 불러오는 중" 스켈레톤이 보인다
- Then  응답 뒤 h1 "북로그"와 대화 내용이 보이고 스켈레톤은 없다

## 7. 모바일 (R169)
좁은 화면에서도 가로 스크롤이 없고, 열자마자 가장 최근 메시지와 입력창이 함께 보인다.

S155 [테스트: pages.spec.ts #56-S1]
- Given 너비 375px, 높이 812px, `demo-role=tester`, `/my/chats/booklog-yunseul`
- Then  `document.documentElement.scrollWidth`가 375 이하다
- Then  입력창과 "보내기" 버튼이 화면 안 아래쪽에 있고, 마지막 메시지가 화면 안에서 입력창 바로 위에 있다

## 8. 접근성 (R170)
대화 기록, 날짜, 입력창, 버튼의 이름과 순서가 보조 기술에 알려진다.

S156 [직접]
- Then  대화 내용은 `role="log"`이고 이름이 "대화 내용"이다 (새 메시지가 붙으면 읽힌다)
- Then  입력창 이름은 "메시지 입력", 버튼 이름은 "보내기"다
- When  입력창에 포커스를 두고 Tab을 누른다
- Then  포커스가 "보내기"로 간다 (빈 입력창이면 버튼이 비활성이라 건너뛴다. 글을 쓴 상태에서 확인한다)

## 9. 기존 테스트와 구조 (R171)
채팅함과 홈의 테스트·문서를 채팅방에 맞게 고친다. 새 번호는 매기지 않는다.

- 채팅함 S119 고침: 첫 카드를 누르면 URL이 `/my/chats/booklog-yunseul`이고 h1 "북로그"가 보인다 ("준비 중" 대신)
- 채팅함 S134·홈 S26 고침: `/my/chats/:roomKey`는 "준비 중" 목록에서 빠진다 (`e2e/links.spec.ts`)
- 채팅함 S135·홈 S78 고침: `grep -rl '"use client"' src`가 기존 9개 + `ChatComposer`, 모두 10개다. 리뷰 반영으로 `HideFooter`, 흐름 점검으로 `ChatsBackLink`를 더했다 (11-02, 전체 수는 홈 S78). `grep -rln "mock" src --include='*.tsx'`는 결과가 없다
- 채팅함 S116~S140은 그대로 통과한다 (목업의 최근 메시지·일시는 대화 기록의 마지막 메시지에서 나오도록 바꾸되 값은 같다)

## 10. 푸터 없는 채팅방 (R172)
채팅방에는 사이트 푸터를 두지 않는다 (11-01 요청). 채팅함과 없는 대화방 안내에는 푸터가 있다 (고침 11-02 요청: 채팅방을 나와도 채팅함에는 푸터가 있어야 한다). 채팅방은 본문이 화면 아래까지 채워서, 대화가 짧아도 입력창이 화면 아래에 온다. 푸터는 지금 보이는 화면을 기준으로 숨긴다. 채팅방을 나와 다른 페이지로 가면 떠난 채팅방이 숨겨진 채 문서에 남아도, 그 페이지의 푸터는 보인다 (고침 11-02).

S157 푸터 [테스트]
- Given `demo-role=tester`
- When  `/my/chats/booklog-yunseul`에 접속한다
- Then  푸터가 보이지 않는다
- When  `/my/chats`, `/my/chats/nope`, `/my`에 접속한다
- Then  모두 푸터가 보인다 (고침 11-02: 채팅함과 없는 대화방 안내도 푸터가 보인다)

S158 짧은 대화 [직접]
- Given 너비 1440px, 높이 900px, `demo-role=developer`, `/my/chats/ledger-yunseul` (메시지 3개)
- Then  페이지가 스크롤되지 않고(`scrollHeight`가 화면 높이와 같다), 입력창 아래 끝이 화면 아래 80px 안에 있다

S321 채팅방 나오기 (11-02 리뷰·요청) [테스트]

## 가정
- 화면 배치: 채팅함과 같이 가운데 최대 폭 3xl(48rem) 한 열이다. 위에서부터 "채팅함" 링크 → 대화방 머리 → 대화 내용 → 입력창이다. 페이지 전체가 스크롤되고, 입력창 띠만 화면 아래에 붙는다(sticky). 사이트 푸터는 두지 않고, 본문이 화면 아래까지 채워서 대화가 짧아도 입력창은 화면 아래에 있다(11-01 요청). 대화 내용을 따로 높이가 정해진 상자에 넣지 않는다. 모바일에서 상자 안 스크롤과 페이지 스크롤이 겹치지 않게 하고, 가상 키보드가 올라와도 입력창이 따라 올라오게 하기 위해서다.
- 열 때와 메시지를 보낸 뒤에는 가장 최근 메시지가 입력창 바로 위에 오도록 스크롤한다. 처음 열 때는 애니메이션 없이 바로, 보낸 뒤에는 부드럽게 움직인다. 다른 화면에 갔다가 다시 들어와도 처음 열 때처럼 바로 간다 (고침 11-02).
- "채팅함" 링크: 왼쪽 화살표 아이콘 + "채팅함", 0.875rem 600 흐린 먹, hover 때 먹 글씨와 칩 회색 알약 바탕. 마지막으로 본 채팅함의 검색·역할·정렬로 돌아간다. 같은 브라우저 탭 안에서만 기억하고, 채팅방 주소로 바로 열면 조건 없는 채팅함이다 (고침 11-02).
- 대화방 머리: 왼쪽에 프로젝트 이미지(64×48px, 원본과 같은 4:3, 12px 모서리, 이미지가 없으면 활자 썸네일), 오른쪽에 대화방 이름(h1, 채팅함 제목과 같은 1.5rem 800)과 그 아래 [역할 배지 + 상대 닉네임 · "북로그 모집 글" 링크(흐린 먹, hover 때 먹 + 밑줄)], 맨 오른쪽 더보기. 머리는 페이지와 함께 스크롤되고 위에 붙지 않는다(앱 헤더 높이가 화면 폭마다 달라서).
- 말풍선: 내 메시지는 오른쪽, 강조색 바탕 + 강조 위 글씨(메인 색). 내가 보낸 말을 한눈에 가르도록 One Green Rule의 예외로 둔다. 글자 대비는 라이트 5.25:1(흰 글씨), 다크 5.34:1(검정 글씨)이다. 바탕이 강조색이라 그 안의 글을 선택하면 선택 색을 뒤집는다(강조 위 글씨 바탕 + 강조색 글자). 상대 메시지는 왼쪽, 교정지 바탕 + 먹 글씨이고 강조색을 쓰지 않는다. (고침 11-01: 먹 바탕이 검게 보인다는 피드백으로 메인 색으로) 16px 모서리이고, 묶음 마지막 말풍선만 말하는 쪽 아래 모서리가 6px다. 안쪽 10px 16px, 0.875rem, 행간 넉넉히, 최대 폭 80%. 줄바꿈은 그대로 보이고, 띄어쓰기 없는 긴 글자(주소 등)는 말풍선 안에서 끊는다.
- 묶음: 같은 사람이 이어 보낸 메시지는 4px 간격으로 붙고, 보낸 사람이 바뀌면 12px 띄운다. 시각(0.75rem 흐린 먹, tabular-nums)은 같은 사람이 같은 분에 보낸 묶음의 마지막 말풍선 옆(내 메시지는 왼쪽, 상대 메시지는 오른쪽)에만 붙인다. 상대 닉네임은 머리에 있으니 말풍선 위에 다시 쓰지 않는다.
- 날짜 구분: 가운데 0.75rem 600 흐린 먹 글자, 양옆에 1px 재단 회색 선. 날짜 묶음 사이 32px. 서울 시간 기준 "오늘", "어제", 올해 "10월 29일 목요일", 작년 이전 "2025년 12월 3일 수요일".
- 맨 위 안내: "북로그 모집 건으로 열린 1대1 대화방이에요." 0.75rem 흐린 먹 가운데 정렬. 이름을 바꿔도 프로젝트명으로 쓴다.
- 입력창: 작업대 바탕 띠(위 16px, 아래 16px·md 24px)가 화면 아래에 붙고, 그 안에 교정지 면(16px 모서리)이 있다. 여러 줄로 늘어나는 입력이라 검색창 같은 알약 대신 담는 면 모서리를 쓴다. 면 안에 테두리 없는 입력란(0.875rem, 한 줄에서 시작해 내용만큼 늘고 최대 128px까지, 그 뒤로는 안에서 스크롤)과 오른쪽 40px 원형 "보내기" 버튼(강조색 바탕 + 강조 위 글씨, 종이비행기 아이콘)이 있다. 포커스 때 면에 2px 강조색 링. md 이상에서는 면 아래에 "Enter로 보내고, Shift+Enter로 줄을 바꿔요." 안내(0.75rem 흐린 먹. 터치 기기는 "Enter로 줄을 바꾸고, 보내기 버튼으로 보내요.", 고침 11-02). 앞뒤 공백을 뺀 글이 없으면 보내기가 비활성이다. 최대 500자.
- 보내는 중: 보내기를 누르면 서버 응답 전에 내 말풍선이 60% 불투명도로 먼저 보이고 시각 대신 "보내는 중"이 붙는다. 저장된 뒤 놓일 자리에 미리 둔다: 마지막 대화가 오늘이 아니면 "오늘" 구분 아래, 상대 메시지 다음이면 12px, 내 메시지 다음이면 4px 띄운다 (고침 11-02). 저장되면 보통 말풍선으로 바뀐다. 보내지 못하면 글을 입력창에 되돌리고 "보내지 못했어요. 다시 보내 주세요."를 알린다(`role="alert"`).
- 강조색을 쓰는 자리: "보내기" 버튼(이 화면의 주 버튼 하나), 내 말풍선, 입력창 포커스 링, 열린 더보기 버튼, 원래 있던 포커스 링. 상대 말풍선·날짜·닉네임·배지에는 쓰지 않는다.
- 저장 위치(시연용): 보낸 메시지는 보낸 회원(닉네임)과 함께 `demo-chat-sent` 세션 쿠키에 쌓는다. 같은 방의 두 회원이 함께 보는 기록이라 쿠키 하나에 두고, 보는 회원 기준으로 나·상대를 나눈다. 한글이 많아도 쿠키 크기 제한(약 4KB)을 넘지 않도록 base64url로 담고, 3,600자를 넘으면 오래된 보낸 메시지부터 지운다. 대화방 이름 변경·삭제는 회원마다 `demo-chat-tester`, `demo-chat-developer` 쿠키에 따로 둔다 (고침 11-02).
- 시각 맞추기: 목업 대화 기록은 접속 시각 기준으로 거꾸로 계산한다. 그런데 보낸 메시지는 실제 보낸 시각에 머문다. 시간이 지나도 목업 메시지가 내 메시지 뒤로 넘어가지 않도록, 보낸 메시지가 있는 방은 그 방에서 처음 보낸 시각을 기준으로 목업 기록을 계산한다.
- 채팅함 반영: 보낸 메시지가 있는 방은 마지막 보낸 메시지가 카드의 미리보기와 최근 일시가 되고, 최신순 정렬에도 그 시각을 쓴다.
- 없는 방: 비로그인 확인과 쿠키 읽기가 Suspense 안에서 일어나 응답이 이미 시작된 뒤라 HTTP 상태는 200이다(Next 16 스트리밍 규칙). 대신 Next가 `noindex`를 넣고, 화면은 대화방 전용 안내(`not-found.tsx`)를 보여 준다.

## 변경 이력
- 11-01 1차: 채팅방 계획. 채팅함 문서의 결정 필요 3을 "이번에 만든다"로 닫았다.
- 11-01 2차: 채팅함·채팅방에서 사이트 푸터를 뺐다(R172, S157·S158 추가). `globals.css`에 `no-footer` 변형을 두고, 페이지 맨 바깥 요소에 `data-no-footer`를 두면 CSS `:has()`로 푸터를 숨기고 본문(main)이 세로 flex가 된다. 채팅방은 그 안을 채우고 입력창 띠에 `mt-auto`를 줘서 대화가 짧아도 입력창이 화면 아래에 온다. 경로를 읽는 `usePathname`은 채팅방 같은 동적 주소에서 Suspense가 필요해 푸터가 늦게 그려지거나 깜빡여서 쓰지 않았다. 개발 서버의 "시연용" 선택 상자도 푸터 안에 있어 채팅 화면에서는 보이지 않는다.
- 11-01 3차: 내 말풍선을 먹 바탕에서 강조색(메인 색) 바탕 + 강조 위 글씨로 바꿨다(S147·S149 고침). One Green Rule의 예외로 DESIGN.md에 적었다.
- 11-02 4차: PR #20 리뷰를 반영했다(위 리뷰 피드백). R173(S317·S318)과 S321을 더하고, 푸터 숨김을 `no-footer` 변형에서 `HideFooter`로 바꿨다.
