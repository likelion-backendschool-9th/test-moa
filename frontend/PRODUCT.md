## Platform

web

## Users
- **테스터 (주 사용자):** 개발 경험이 없어도 되는 일반 사용자. 모집 글을 보고 지원해서, 참여가 확정되면 안내된 항목대로 서비스를 써 보고, 사용 경험과 버그를 피드백으로 제출한다. 보상으로 크레딧을 받는다.
- **개발자 (두 번째 사용자):** 테스트받고 싶은 소프트웨어를 프로젝트로 등록하고, 테스트 모집 건을 올려 피드백을 받는다. 무료로 쓸 수 있고, 구독하면 테스터 직접 선정, 상단 순환 노출, 채팅, 분석 기능을 쓴다.
- **운영자:** 신고·제재, 출금 요청, 모집 취소 요청을 검토한다.

## Product Purpose
개발자와 테스터를 연결하는 소프트웨어 테스터 모집 플랫폼. 개발자는 실제 사용자에게 버그와 사용성 피드백을 받고, 테스터는 새 서비스를 써 보고 크레딧을 받는다. 우선 목표는 5명 팀이 포트폴리오와 발표에서 시연할 수 있는 첫 버전이다.

## Positioning
- 개발 지식이 없어도 테스터가 될 수 있다.
- 버그를 못 찾아도 요청한 테스트를 하고 피드백을 내면 보상 대상이다.
- 테스트로 받은 크레딧은 1크레딧당 1원으로 현금화할 수 있다.
- 제출 후 72시간 동안 신고가 없으면 개발자 승인 없이 자동 지급된다.

## Operating Context
- 흐름: 모집 글 등록 → 지원 → 참여 확정 → 테스터가 자기 시간에 테스트 → 피드백 제출 → 72시간 신고 대기 또는 운영자 검토 → 크레딧 지급
- 하나의 프로젝트에서 여러 테스트 모집 건을 진행한다. 참여자·피드백·보상은 모집 건별로 관리한다.
- 무료 모집은 모집 인원까지 선착순 확정, 구독 모집은 개발자가 지원자를 직접 선정한다.
- 모집 마감일과 피드백 제출 마감일은 따로 정하고, 테스터는 지원 전에 둘 다 확인한다.

## Capabilities and Constraints
- 첫 지원 대상은 접속 링크로 이용하는 웹서비스. 모바일 앱, 게임, API·라이브러리는 이후 확장 대상이다.
- 스택: Next.js 16 (App Router, Cache Components), Tailwind CSS v4, TypeScript. 로그인과 API는 아직 목업이다.
- 라이트·다크 모드를 모두 지원하고 시스템 설정을 따른다.
- 5명 팀이 페이지를 나눠 개발한다. 디자인 토큰과 공통 컴포넌트(`components/ui`)를 다른 페이지에서 그대로 재사용할 수 있어야 한다.
- 페이지 URL은 `test-moa/docs/page-urls.md`를 따른다.
- 용어는 `project-lion/GLOSSARY.md`를 따른다 (프로젝트, 테스트 모집 건, 크레딧, 기본 보상, 추가 보상).
- 미정: 구독 가격, 크레딧 지급량, 모집 인원 한도, 최소 출금액, 상단 노출 슬롯 수와 순환 기준, 실제 결제·현금화 연동 범위.

## Brand Commitments
- 서비스 이름: Test Moa
- 한국어 서비스. 문구는 존댓말 해요체로 쓴다.

## Evidence on Hand
- 실제 사용자, 후기, 고객사, 이용 수치는 아직 없다. 지어내지 않는다.
- 화면의 모집 글과 보상 숫자는 시연용 샘플이다 (`src/features/recruitment/mock.ts`).
- 로고나 브랜드 자산은 없다. 임시 파비콘(`src/app/icon.svg`)만 있다.

## Product Principles
1. 테스터의 진입 장벽을 낮춘다. 개발 용어 없이 무엇을 하고 무엇을 받는지 바로 알 수 있어야 한다.
2. 보상과 일정은 숨기지 않는다. 마감일, 인원, 보상을 지원 전에 보여 준다.
3. 확정된 사실만 말한다. 미정인 가격·수치·실적을 약속하지 않는다.
4. 시연에서 바로 이해되는 흐름을 우선한다.
