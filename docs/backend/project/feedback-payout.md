# 피드백 보상 72시간 자동 지급 (#288)

테스터가 피드백을 낸 뒤 72시간 동안 신고가 없으면 시스템이 참가 단위로 보상 크레딧을 적립한다. 지금까지는 화면이 "제출 + 72시간에 자동 지급"을 안내했지만 지급하는 코드가 없어서, 피드백은 제출(`SUBMITTED`)로 남고 크레딧이 쌓이지 않았다. 도메인 전체에서 정한 것은 [README.md](README.md)에 있다. 크레딧 지갑과 장부 규칙은 [결제·구독·크레딧](../payment/README.md)에 있다.

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`는 백엔드 테스트와 1:1이다(`@DisplayName("#288-S…")`).

## 이슈 #288 확인

| 이슈 항목 | 시나리오 |
| --- | --- |
| 1·2 72시간 동안 신고가 없으면 참가 단위로 지급하고 크레딧을 적립 | #288-S1, #288-S2 |
| 3 한 칸이라도 신고됐으면 참가 전체 지급 보류(#66) | #288-S3 |

| 5 내 참여와 크레딧 내역에 지급 완료와 적립이 보임 | #288-S1 |
| 정해야 할 것: 담당·주기·두 번 지급 막기 | 정한 것 1~3 |

## 정한 것
1. 담당은 프로젝트 도메인이다(`FeedbackPayoutService`). 지급 조건이 참가·피드백 상태에 있고, 크레딧은 결제 도메인의 지갑·장부 규칙(`grantEarned` + 장부 `EARNED`)대로 남긴다. 결제 계획 문서도 프로젝트 도메인으로 적었다
2. 10분마다 돈다(`feedback.payout-cron`, 기본 `0 */10 * * * *`). 그래서 실제 지급은 안내한 시각(제출 + 72시간)보다 최대 10분 늦을 수 있다
3. 참가 행을 잠근 뒤(`findLockedById`) 조건을 다시 보고 피드백을 `REWARDED`로 바꾼다. 서버가 여러 대이거나 실행이 겹쳐도 두 번째는 이미 지급된 피드백을 보고 건너뛴다

## 1. 지급 (#288-R1)

- 지급할 참가: 확정(`CONFIRMED`)이고 보상 스냅샷이 있으며, 제출(`SUBMITTED`) 피드백이 있고 신고됨(`REPORTED`)·보상 제외(`EXCLUDED`) 피드백이 없고, 가장 이른 제출 시각 + 72시간이 지났다. 승인 대기 보상 합(`sumPendingRewardByUserId`)과 같은 조건이다
- 모집이 취소돼도 피드백을 낸 참가는 확정으로 남아([recruitment-cancel.md](recruitment-cancel.md)) 같은 규칙으로 지급한다
- 지급하면 그 참가의 제출 피드백을 모두 `REWARDED`로 바꾸고, 지갑 적립 잔액에 기본 + 추가 보상 스냅샷을 더하고, 장부에 `EARNED` 한 줄("피드백 보상 · {모집글 제목}")을 남긴다. 피드백이 여러 칸이어도 보상은 참가당 한 번이다(정한 것 2)
- 지갑이 없으면 만든다(`insertIfAbsent`). 탈퇴 유예·파기된 회원도 회원 행은 남아 그대로 지급한다
- 한 번에 200건까지 읽고 참가마다 따로 트랜잭션을 쓴다. 한 건이 실패해도 로그를 남기고 다음 참가로 넘어가며, 남은 참가는 다음 실행이 지급한다
- 지급된 뒤 내 참여 상태는 "지급 완료"(`paid`)이고 받은 크레딧이 보인다. 화면의 안내 문구는 바꾸지 않는다

## 2. 신고와 겹칠 때 (#288-R2)

- 신고는 제출 후 72시간 안에만 할 수 있고, 지급은 72시간이 지난 뒤에만 한다. 두 요청이 경계에서 겹칠 수 있어, 신고(`FeedbackServiceImpl.report`)도 같은 참가 행을 잠근 뒤 피드백 상태를 DB에서 다시 읽는다(고침 #288: 전에는 읽어 둔 엔티티의 상태만 봤다)
- 지급된 피드백은 상태가 `REWARDED`라 신고하면 409 `FEEDBACK_NOT_REPORTABLE`이다
- 운영자가 신고를 기각하면 피드백이 제출로 돌아가(`dismissReport`), 72시간이 지났으면 다음 실행에 지급된다. 인정하면 그 칸이 보상 제외가 되어 참가 전체를 지급하지 않는다(#66, 고침 #85)

#288-S1 제출한 지 72시간이 지나고 신고가 없으면 참가 단위로 한 번 지급한다 [테스트]
- Given 확정 참가(기본 보상 1000)와 73시간 전에 낸 피드백 두 칸
- When  지급이 돈다
- Then  1건 지급, 피드백 두 칸이 `REWARDED`, 적립 잔액 1000, 장부 `EARNED` +1000 "피드백 보상 · 북로그 1차 테스트" 한 줄이다
- Then  내 참여 상세가 `paid`이고 받은 크레딧이 1000이다
- When  다시 돈다
- Then  지급하지 않고 잔액이 그대로다

#288-S2 72시간이 지나지 않았으면 지급하지 않는다 [테스트]
- Given 71시간 전에 낸 피드백
- Then  지급하지 않고 제출 상태로 남는다

#288-S3 한 건이라도 신고됐거나 보상 제외면 참가 전체 지급을 보류한다 [테스트]
- Given 두 칸 중 한 칸이 신고됨
- Then  지급하지 않는다
- When  운영자가 기각해 제출로 돌아간다
- Then  다음 실행에 지급된다
- Given 두 칸 중 한 칸이 보상 제외
- Then  지급하지 않고 남은 칸도 제출로 남는다

#288-S4 모집이 취소돼도 피드백을 낸 참가는 지급한다 [테스트]
- Given 피드백을 낸 뒤 모집이 취소됐다
- Then  72시간이 지나면 지급된다

#288-S5 지급된 피드백은 신고할 수 없다 [테스트]
- Given 지급된 피드백
- When  개발자가 신고한다
- Then  409 `FEEDBACK_NOT_REPORTABLE`이다

#288-S6 자동 지급이 동시에 두 번 돌면 [테스트]
- Given 지급할 참가 하나(10번 되풀이)
- When  지급을 동시에 두 번 돌린다
- Then  두 실행이 지급한 수의 합이 1이고, 적립 잔액과 장부 줄 수가 참가 수만큼만 늘어난다
- 참고: 참가 행 잠금을 빼면 같은 테스트가 첫 번째 반복에서 2건 지급으로 실패한다
