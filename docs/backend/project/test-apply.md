# 테스트 지원 API (#114)

로그인한 테스터가 모집글에 지원해 참가(`registers`)를 만드는 API. 선착순 모집은 지원과 동시에 확정하고 기본 보상을 고정하며, 선발형(구독) 모집은 개발자 선정(#115)을 기다린다. 도메인 전체에서 정한 것은 [README.md](README.md), 참가 엔티티 규칙은 [entities.md 3](entities.md#3-지원과-참가-89-r3)에 있다.

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`는 백엔드 테스트와 1:1이다(`@DisplayName("#114-S…")`).

## 이슈 #114 확인

| 이슈 항목 | 시나리오 |
| --- | --- |
| 1 로그인한 테스터가 모집 중인 모집글에 지원 | #114-S1, #114-S2 |
| 2 선착순은 지원하자마자 확정되고 보상액이 고정 | #114-S2 |
| 3 선발형은 선정 대기로 저장 | #114-S1 |
| 4 다시 지원, 마감·취소된 모집, 자기 프로젝트는 저장되지 않음 | #114-S3, #114-S4, #114-S5, #114-S7 |
| 5 비로그인은 401 | #114-S6 |
| 확인 필요: 선착순 확정과 취소 규칙 | 11-07 팀 채팅에서 선착순은 취소 규칙의 예외로 정했고 #116에 반영됨([README 정한 것 13](README.md#정한-것)) |

## 1. 테스트 지원 (#114-R1)

| 동작 | API | 로그인 | 성공 |
| --- | --- | --- | --- |
| 테스트 지원 | `POST /api/v1/recruitments/{recruitmentId}/applications` | 필요 | 201 |

본문은 없다.

- 지원할 수 있는 모집: 취소되지 않았고 모집 마감 전이다(모집 중, [README 정한 것 11](README.md#정한-것)). 저장 상태가 `RECRUITING`이 아니면 마감으로 본다
- 선착순(`FIRST_COME`): 참가를 저장하고 바로 `confirm`을 불러 `CONFIRMED`가 된다. 기본 보상 1,000 크레딧, 추가 보상 0을 고정한다([README 정한 것 14](README.md#정한-것))
- 선발형(`MANUAL`): `APPLIED`로 저장하고 보상은 정하지 않는다. 확정할 때(#115) 고정한다
- 다시 지원: 같은 모집에 대기(`APPLIED`)·확정(`CONFIRMED`)·거절(`REJECTED`) 참가가 있으면 막는다. 참여 취소(`CANCELLED`)만 남은 회원은 다시 지원할 수 있다(가정 1)
- 동시 요청: 모집 취소(#116)와 같은 모집글 행 잠금(`PESSIMISTIC_WRITE`)으로 읽어, 지원과 취소가 겹치지 않고 같은 회원이 여러 번 눌러도 하나만 저장된다
- 응답: `registerId`, `recruitmentId`, `status`(`applied`·`confirmed`, 프론트 `ApplicationStatus` 이름), `appliedAt`, `confirmedAt`(선발형은 null), `baseReward`(선발형은 null)

| 상황 | 상태 | `error.code` |
| --- | --- | --- |
| 로그인하지 않음 | 401 | `UNAUTHORIZED` |
| 없는 모집, 취소된 모집 | 404 | `NOT_FOUND` |
| 모집 마감이 지남 | 409 | `RECRUITMENT_CLOSED` ("모집이 마감됐어요") |
| 자기 프로젝트의 모집 | 409 | `OWN_RECRUITMENT` ("내 모집에는 지원할 수 없어요") |
| 이미 지원함(대기·확정·거절) | 409 | `ALREADY_APPLIED` ("이미 지원한 테스트예요") |

#114-S1 선발형 모집 지원 [테스트]
- Given 선발형 모집 중인 모집
- When  테스터가 지원한다
- Then  201이고 `status` `applied`, `appliedAt` 있음, `confirmedAt`·`baseReward` 없음이다
- Then  참가 하나가 `APPLIED`로 저장되고 보상 스냅샷은 없다

#114-S2 선착순 모집 지원 [테스트]
- Given 선착순 모집 중인 모집
- Then  201이고 `status` `confirmed`, `confirmedAt` 있음, `baseReward` 1000이다
- Then  참가가 `CONFIRMED`이고 기본 1000, 추가 0, 확정 시각이 저장된다

#114-S3 다시 지원 [테스트]
- Given 이미 지원한 테스터
- When  다시 지원한다
- Then  409 `ALREADY_APPLIED`이고 참가는 하나다
- Given 그 지원이 거절됐다
- Then  다시 지원해도 409다
- Given 참여 취소(`CANCELLED`)만 남은 다른 회원
- Then  다시 지원할 수 있고 참가가 둘(취소, 새 지원)이 된다

#114-S4 마감·취소·없는 모집 [테스트]
- Then  모집 마감이 지난 모집은 409 `RECRUITMENT_CLOSED`, 취소된 모집과 없는 모집은 404이고 참가는 저장되지 않는다

#114-S5 자기 모집 [테스트]
- When  개발자가 자기 프로젝트의 모집에 지원한다
- Then  409 `OWN_RECRUITMENT`이고 저장되지 않는다

#114-S6 비로그인 [테스트]
- Then  토큰이 없으면 401이고 저장되지 않는다

#114-S7 같은 회원이 동시에 여러 번 지원 [테스트]
- Given 선착순 모집 중인 모집
- When  같은 테스터가 동시에 5번 지원한다
- Then  하나만 201이고 나머지는 409이며, 참가는 하나만 저장된다
- 참고: 잠금을 빼면 이 테스트가 실패하는 것을 확인했다

## 범위 밖
- 프론트 연결(지원 페이지 `/recruitments/:slug/apply`는 아직 준비 중 화면이다)
- 테스터가 스스로 참여를 취소하는 API
- 이용 정지된 회원의 지원 막기(운영자 제재 #86과 함께 정한다)
- 추가 보상(11-07 팀 채팅에서 뺐다)

## 가정
1. 참여 취소만 남은 회원은 다시 지원할 수 있다. 지금 참여 취소는 모집 취소(#116)로만 생기는데, 그때는 모집도 취소돼 다시 지원할 수 없다. 테스터 스스로 취소하는 기능이 생기면 다시 지원을 허용할지 그때 정한다
2. 같은 회원·모집의 참가를 DB 유일 제약으로 막지 않는다. 참여 취소 뒤 다시 지원하면 참가가 여러 개가 되기 때문이고, 대신 모집글 행 잠금으로 동시 요청을 막는다
