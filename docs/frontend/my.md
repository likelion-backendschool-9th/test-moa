# 프론트엔드 마이페이지 (`/my`)

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`만 e2e 테스트와 1:1이고, `[테스트: 파일 번호]`는 그 테스트가 대신 확인한다. `[명령]`은 명령 한 번, `[직접]`은 사람이 화면을 보고 확인한다. (고침 #56)

## 한눈에
- 끝나면: 마이페이지 하위 페이지 5개에 왼쪽 메뉴(모바일은 위쪽 가로 탭)가 생긴다. `/my`는 대시보드가 된다: 프로필(이름·닉네임·이메일), 지금 할 일, 활동 요약, 크레딧과 구독, 최근 크레딧 내역. 하위 페이지 내용은 지금처럼 "준비 중".
- 결정 필요: 없음 (레이아웃은 사이드바 + 대시보드, 섹션 4개 추가로 확정 10-30)
- 규모: 7단계, 약 4~5시간 (1차 카드 3개는 이미 있음)

## 맥락
- 1차(커밋 `53233cf`)로 카드 3개(내 정보, 크레딧, 구독)를 만들었다. 구조가 단순하다는 피드백을 받아 레퍼런스를 보고 다시 짠다.
- 레퍼런스에서 가져온 패턴:
  1. 첫 화면에 지금 할 일을 둔다 (계정 홈은 다음 행동부터)
  2. 사용 가능 잔액을 크게, 행동 버튼을 바로 옆에 (지갑형 대시보드)
  3. 요약 숫자에서 상세로 이동한다 (요약 → 상세)
  4. 최근 내역은 최신순 목록 + 전체 보기
  5. 프로필 완성도 막대 (Testbirds 대시보드) — 3차에서 뺐다
- 개발자와 테스터는 한 계정이다. 테스트 참여와 내 프로젝트 활동을 한 화면에 함께 보여 주고, 역할로 나누지 않는다.
- 금액·가격·한도는 미정이다. 화면에 가격이나 한도를 약속하지 않는다 (PRODUCT.md 원칙 3).

## 13. 내 신고와 받은 제재 (#85·#86)
`AUTH_MODE=backend`일 때만 마이페이지 홈의 최근 크레딧 아래에 두 카드를 더한다. 목업에는 없다.

- #85-R1 "내 신고"는 내가 한 신고를 최신순으로 보여 준다(`GET /api/v1/reports/me`). 대상 종류, 사유, 처리 상태(검토 대기·기각·인정), 신고 일시. 신고당한 회원과 판정한 운영자는 보이지 않는다
- #86-R7 "받은 제재"는 내가 받은 경고·정지를 보여 준다(`GET /api/v1/sanctions/me`). 종류와 막힌 기능, 사유, 기간, 상태(제한 중·해제됨·끝남·경고). 없으면 "받은 제재가 없어요"
- #86-R8 두 카드는 조회에 실패하면 그 카드만 "…를 불러오지 못했어요. 잠시 뒤 다시 열어 주세요"를 보이고, 크레딧·구독·계정 같은 나머지 마이페이지는 그대로 보인다(#85 내 신고도 같다)

#85-S20 내 신고 카드 [직접]
- Given 신고 3건(검토 대기·기각·인정)이 있는 회원
- Then  최신순으로 세 줄과 각 상태가 보인다. 신고가 없으면 "아직 한 신고가 없어요"

- #85-R11 "내 신고" 카드에는 최근 3건만 두고, 제목 옆 "전체 보기 N건"을 누르면 주소를 바꾸지 않고 마이페이지 위에 "내 신고" 창이 열린다
  - 위에 처리 상태 필터(전체·검토 대기·기각·인정, 건수 포함), 아래 목록은 창 안에서만 스크롤한다
  - 줄마다 대상 종류, 처리 상태, 사유 전체, 신고·처리 일자, 내가 올린 증거 파일(이름·크기, 누르면 새 탭)

#85-S29 내 신고 전체 보기 창 [직접]
- Given 증거 파일을 붙인 신고와 처리된 신고가 있는 회원
- When  "전체 보기"를 누른다
- Then  주소는 그대로이고 "내 신고" 창이 열리며, 상태 필터에 건수가 보이고 증거 파일 이름을 누르면 열린다
- When  "검토 대기"를 누른다
- Then  검토 대기 신고만 남는다. 닫기·Esc로 닫으면 "전체 보기"로 포커스가 돌아온다

#86-S11 받은 제재 카드 [직접]
- Given 지금 걸린 채팅 정지, 해제된 정지, 지난 경고가 있는 회원
- Then  "기간 정지 · 채팅 제한 / 제한 중", "해제됨", "경고"가 보인다. 제재가 없으면 "받은 제재가 없어요"

## 가정
- 화면 배치(1024px 이상): 왼쪽 메뉴 12rem, 오른쪽은 위에서부터 프로필 머리말 → 지금 할 일 → 활동 요약 → [크레딧 | 구독] → 최근 크레딧 내역 순서다. (고침 10-30: 활동 요약을 지금 할 일 아래로) 1024px 미만에서는 메뉴가 본문 위 가로 탭이 된다.
- 지금 할 일 종류: 테스트 참여(참여 확정 뒤 테스트 시작, 피드백 제출 마감), 내 프로젝트(지원자 선정 마감, 새 피드백 확인). 마감이 있는 항목이 먼저, 그다음 생긴 순서다. 최대 5개. (고침 10-30: 승인 대기 보상·출금 처리 중은 크레딧 카드에만 둔다)
- 승인 대기 보상은 아직 지급 전이라 총 잔액에 넣지 않는다 (GLOSSARY: 승인 대기 보상).
- 시연용 샘플 수치:
  - tester(한서윤): 지원 2, 참여 중 1, 완료 5, 프로젝트 0, 승인 대기 1,350
  - developer(박도현): 지원 1, 참여 중 0, 완료 3, 프로젝트 2, 모집 중 1, 새 피드백 3
  - 크레딧 총합은 `session.ts`와 맞추고, 최근 내역 5건의 합은 총합과 맞추지 않는다 (5건만 보여 주므로)
- 운영자는 서비스 이용 회원이 아니라고 본다. 그래서 할 일은 빈 상태로 두고, 구독·활동 요약·출금 링크는 숨긴다.
- `demo-role`의 tester·developer는 계정 종류가 아니라 시연용 회원 두 명이다. 화면 분기는 데이터로만 한다.
- 비로그인 직접 접속은 `/login?next=%2Fmy`로 보낸다.
- 구독 만료일은 접속 시각 +30일이다. 구독 주기는 미정이라 "다음 결제일"이라는 말은 쓰지 않는다.
- 디자인은 `DESIGN.md` 토큰과 `components/ui`만 쓴다. 새 hex·px 값을 넣지 않는다. 메뉴의 현재 항목은 모바일 메뉴와 같은 강조 규칙(연한 에메랄드 바탕 + 강조색 글씨)을 따른다.
