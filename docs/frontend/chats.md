# 프론트엔드 채팅함 (`/my/chats`)

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`만 e2e 테스트와 1:1이고, `[테스트: 파일 번호]`는 그 테스트가 대신 확인한다. `[명령]`은 명령 한 번, `[직접]`은 사람이 화면을 보고 확인한다. (고침 #56)

## 한눈에
- 끝나면: `/my/chats`에 내가 들어가 있는 채팅방이 카드 목록으로 보인다. 카드는 왼쪽에 카드 높이를 다 채우는 프로젝트 이미지, 선이나 그라데이션 없이 바로 옆에 대화방 이름, 역할 배지(개발자·테스터)와 대화 상대 닉네임, 최근 메시지 미리보기가 있고, 오른쪽 위에 최근 일시와 더보기 버튼이 있다. 내 닉네임은 쓰지 않는다. 더보기에서 대화방 이름 변경과 대화방 삭제(맨 아래)를 한다. 목록 위 첫 줄은 채팅방 검색, 둘째 줄은 왼쪽 "전체 / 테스터 / 개발자" 역할 탭과 오른쪽 최신순·오래된순 정렬이고, 상태는 URL(`q`, `role`, `sort`)에 남는다. 오늘 온 대화와 고른 탭의 수는 강조색으로 표시한다. 카드를 누르면 채팅방(`/my/chats/:roomKey`)으로 간다. 채팅방 화면은 `docs/frontend/chat-room.md`에서 따로 계획해 만들었다.
- 결정 필요:

  2. ~~프로젝트 사진~~ → 시연용 웹·앱 화면 이미지 5장을 만들어 넣었다 (10-30 요청, S117). 실제 사진은 API를 붙일 때 `project_images`에서 받는다
  3. ~~채팅방 화면을 이번에 같이 만들지~~ → 따로 계획해 만들었다 (11-01 요청, `docs/frontend/chat-room.md`)
- 규모: 7단계

## 맥락
- 채팅은 구독 개발자와 해당 모집 건에 선정된 테스터의 1대1 소통이다 (README 주요 서비스 구성). 그래서 채팅 요청자는 프로젝트 주인(개발자), 채팅 응답자는 테스터다.
- 개발자와 테스터는 한 계정이다 (마이페이지 문서 맥락). 같은 사람이 어떤 방에서는 개발자(내 프로젝트의 채팅), 다른 방에서는 테스터(테스터로 참여한 채팅)일 수 있다. 기본은 모두 보여 주고, 역할 탭으로 나눠 본다 (10-30 요청).
- 요청에서 "모달"이라고 한 목록 한 칸은 카드(박스)다 (10-30 확인). 이 문서에서는 "채팅 카드"라고 부른다.
- 채팅방에는 따로 정한 이름이 없다. "채팅방 이름 검색"은 카드에 보이는 프로젝트명과 대화 상대 닉네임을 찾는 것으로 본다.
- 프로젝트별 보기(칩, 드롭다운)는 넣었다가 뺐다 (10-30 요청). 프로젝트로 찾을 때는 검색창에 프로젝트명을 쓴다.
- 홈의 모집 카드는 이미지 파일 없이 서비스 이름 활자를 썸네일로 쓴다 (홈 S74). 채팅 카드는 요청에 따라 프로젝트 화면 이미지를 쓰고, 이미지가 없을 때만 같은 활자 썸네일(이름 첫 글자)로 돌아간다. 모집 카드 규칙은 바꾸지 않는다.
- 백엔드에는 채팅 테이블이 아직 없다. 프론트 목업으로 먼저 만든다.
- 채팅함은 마이페이지 메뉴가 없는 페이지다 (마이페이지 S97).

## 2. 채팅 카드 (R114)
카드는 왼쪽 프로젝트 이미지(카드 높이를 다 채움) 바로 옆에 오른쪽 내용이 오는 구조다. 둘 사이에 선이나 그라데이션은 없다. 글자는 모두 최근 메시지와 같은 크기(0.875rem)이고, 대화방 이름만 역할 탭(전체·테스터·개발자)과 같은 굵기(700)로 둔다. 나머지는 보통 굵기이고 색으로 나눈다(대화방 이름·닉네임은 먹, 메시지·일시는 흐린 먹). 내용은 위에서부터 [대화방 이름 … 최근 일시·더보기], [역할 배지 + 대화 상대 닉네임], [최근 메시지 미리보기]다. 대화방 이름은 바꾼 이름이 있으면 그것, 없으면 프로젝트명이다. 내 닉네임은 쓰지 않는다. 배지는 상대가 개발자(프로젝트 주인)인지 테스터인지 알리고, 강조색 없이 테스터는 칩 회색 바탕, 개발자는 바탕 없이 재단 회색 테두리로 나눈다. 카드를 누르면 채팅방으로 간다. (고침 10-30: 이미지 구조 스케치 반영. 고침 11-01: 배지를 닉네임 앞으로, 선 대신 그라데이션 → 그라데이션도 빼고 글자 크기·굵기 통일. 고침 11-02: 배지를 역할마다 바탕·테두리로 나눔, 리뷰 제안)

S116 카드 요소 [직접]
- Given `demo-role=tester`
- Then  첫 카드에 "북로그", 배지 "개발자"와 그 오른쪽 상대 "서재지기", "피드백 마감이 이틀 남았어요. 막히는 부분 있으면 편하게 물어봐 주세요."가 있다
- Then  내 닉네임 "윤슬"은 카드에 없다
- Then  대화방 이름·닉네임·메시지는 글자 크기가 같고, 대화방 이름만 역할 탭 "전체"와 같은 굵기(700)이며 닉네임·메시지는 보통 굵기(400)다. 이름·닉네임은 먹, 메시지는 흐린 먹이다
- Then  최근 일시는 `time` 요소이고 `datetime`에 ISO 시각이 있다
- Then  "북로그 채팅 더보기" 버튼이 있다

S117 프로젝트 이미지 [직접]
- Then  첫 카드의 이미지는 `/sample/projects/booklog.svg`이고 실제로 불러와진다 (대체 텍스트는 비어 있다. 이름이 바로 옆 제목에 있다)
- Then  이미지 칸은 카드 왼쪽 끝에 붙어 카드 높이를 다 채우고, 프로젝트명은 그 오른쪽에 있다
- Then  이미지 칸에 오른쪽 선이 없고(`border-right-width: 0px`), 그라데이션도 없다

S118 미리보기 한 줄 [직접]
- Given 너비 375px
- Then  미리보기는 한 줄이고, 넘치는 글자는 "…"로 줄인다 (`-webkit-line-clamp: 1`)

S119 채팅방으로 이동 [직접]
- When  첫 카드를 누른다
- Then  URL이 `/my/chats/booklog-yunseul`이고 h1 "북로그"가 보인다 (고침 11-01: 채팅방을 만들어 "준비 중" 대신)

S322 역할 배지 (11-02 리뷰 제안) [직접]
- Given `demo-role=developer`
- Then  상대가 테스터인 배지는 칩 회색 바탕(`rgb(228, 228, 224)`)이고 테두리가 없다
- Then  상대가 개발자인 배지("북로그"의 서재지기)는 바탕이 없고 1px 재단 회색(`rgb(214, 214, 209)`) 안쪽 테두리다
- Then  두 배지는 글자색이 같은 먹이고(강조색 아님) 높이도 같다
- Then  채팅방 머리의 배지도 같다 (`/my/chats/ledger-yunseul`은 테스터, `/my/chats/booklog-dohyeon`은 개발자)

## 3. 순서와 일시 (R115)
기본은 최근 메시지가 최신인 방이 위에 온다. 일시는 오늘이면 시각, 어제면 "어제", 그 전이면 날짜로 쓴다.

S120 테스터 [테스트]
- Given `demo-role=tester`
- Then  카드 5개가 "북로그" → "모아플랜" → "레시피핏" → "가계부 노트" → "회의록 정리" 순서다
- Then  앞의 세 카드 일시는 "오후 3:12" 같은 시각, "어제", "10월 28일" 같은 날짜다

S121 개발자 [테스트]
- Given `demo-role=developer`
- Then  카드 4개가 "가계부 노트"(새벽코더 테스터) → "가계부 노트"(윤슬 테스터) → "북로그"(서재지기 개발자) → "회의록 정리"(윤슬 테스터) 순서다 (같은 계정이 테스터로 참여한 방도 함께 보인다)
- Then  내 닉네임 "도현랩"은 목록에 없다
- Then  두 번째 카드는 테스터의 "가계부 노트" 카드와 같은 채팅방(`/my/chats/ledger-yunseul`)이고 미리보기도 같다. 테스터 쪽 카드에는 상대 "도현랩"과 배지 "개발자"가 보인다

S136 오늘 온 대화 [테스트] (고침 #60: 라이트 초록 변경)
- Given `demo-role=tester`
- Then  첫 카드의 일시는 강조색(`rgb(15, 124, 74)`)이고 앞에 강조색 점이 있다 (`data-today`)
- Then  둘째 카드("어제")의 일시는 강조색이 아니다

## 4. 검색·정렬·역할 탭 (R116)
목록 위 첫 줄은 채팅방 검색, 둘째 줄은 왼쪽 "전체 / 테스터 / 개발자" 역할 탭, 같은 줄 오른쪽 최신순·오래된순이다 (고침 10-30: 좌우를 바꿈). 내 프로젝트의 채팅은 개발자 탭, 테스터로 참여한 채팅은 테스터 탭에 모인다. 상태는 URL(`q`, `role`, `sort`)에 남는다. 채팅방이 하나도 없으면 이 영역을 보여 주지 않는다.

S122 검색 [테스트]
- Given `demo-role=tester`
- When  "채팅방 검색"에 "도현랩"을 입력한다 (300ms 뒤 반영)
- Then  URL에 `q=%EB%8F%84%ED%98%84%EB%9E%A9`가 붙고 카드 2개("가계부 노트", "회의록 정리")가 보인다
- Then  "채팅방 2개"가 `aria-live="polite"`로 읽힌다
- Then  역할 탭의 수가 검색 결과 기준 "전체 2", "테스터 2", "개발자 0"으로 바뀐다

S123 역할 탭 [테스트]
- Given `demo-role=developer`
- Then  "역할별 보기"에 "전체 4", "테스터 1", "개발자 3"이 순서대로 있고 "전체"가 눌린 상태다
- When  "개발자"를 누른다
- Then  URL에 `role=developer`가 붙고 내 프로젝트의 카드 3개("가계부 노트", "가계부 노트", "회의록 정리")가 보이며, 탭의 수 "3"이 강조색이다
- When  "테스터"를 누른다
- Then  URL에 `role=tester`가 붙고 "북로그" 카드 하나(상대 "서재지기", 배지 "개발자")가 보인다
- When  "전체"를 누른다
- Then  URL이 `/my/chats`이다

S124 정렬 [테스트]
- Given `demo-role=tester`
- When  "오래된순"을 누른다
- Then  URL에 `sort=oldest`가 붙고 첫 카드가 "회의록 정리", 마지막 카드가 "북로그"다

S125 결과 없음과 초기화 [직접]
- When  "채팅방 검색"에 "없는채팅방"을 입력한다
- Then  "조건에 맞는 채팅방이 없어요"가 보인다
- When  "조건 초기화"를 누른다
- Then  URL이 `/my/chats`이고 카드 5개가 다시 보이며 검색창이 비어 있다

S126 URL로 열기 [테스트]
- Given `demo-role=developer`, `/my/chats?role=developer&sort=oldest`로 연다
- Then  "개발자" 탭과 "오래된순"이 눌린 상태이고 첫 카드가 "회의록 정리"다

S137 빈 역할 탭 [직접]
- Given `demo-role=tester`
- When  "개발자" 탭을 누른다
- Then  "개발자로 나눈 채팅이 없어요"와 "내 프로젝트에서 선정한 테스터와 나눈 채팅이 여기에 모여요."가 보인다
- When  "전체 보기"를 누른다
- Then  URL이 `/my/chats`이고 카드 5개가 보인다

S319 검색 대기 중 역할 탭·정렬 (11-02 리뷰) [테스트]
- Given `demo-role=developer`
- When  "채팅방 검색"에 "윤슬"을 쓰고 300ms가 지나기 전에 "개발자" 탭을 누른다
- Then  URL에 `q=윤슬`과 `role=developer`가 함께 남고, 시간이 지나도 탭이 "전체"로 돌아가지 않는다
- When  검색어를 "가계부"로 바꾸고 바로 "오래된순"을 누른다
- Then  URL에 `q=가계부`, `role=developer`, `sort=oldest`가 모두 남고, 카드는 상대 "윤슬" → "새벽코더" 순서다

S320 검색 대기 중 화면 떠나기 (11-02 리뷰) [테스트]
- Given `demo-role=tester`
- When  "채팅방 검색"에 "북로그"를 쓰고 바로 헤더 로고(홈으로 가는 링크)를 누른다
- Then  URL이 `/`이고, 기다리던 검색이 늦게 실행되어 채팅함으로 되돌아오지 않는다
- When  헤더의 "채팅"을 눌러 돌아온다
- Then  검색창이 비어 있고 카드 5개가 보인다. 입력창과 목록이 주소의 검색 조건과 같다 (고침 11-02 재리뷰)
- When  "모아"를 쓰고 바로 헤더 로고를 누른 뒤 브라우저에서 뒤로 간다
- Then  검색창이 비어 있고 카드 5개가 보인다

S138 배치 [직접]
- Given 너비 1440px과 375px
- Then  검색창이 위에 있고, 역할 탭은 왼쪽, 정렬은 같은 줄 오른쪽에 있다

## 5. 더보기 (R117)
더보기 버튼은 카드마다 메뉴를 연다. 메뉴는 "대화방 이름 변경", 구분선, "대화방 삭제" 순서로, 삭제가 맨 아래다. 항목을 고르면 대화상자가 열린다. (고침 11-01: "채팅방 열기", "모집 글 보기"에서 바꿈)

S127 열기 [직접]
- When  "북로그 채팅 더보기"를 누른다
- Then  버튼에 `aria-expanded="true"`가 있고 포커스가 첫 항목으로 간다
- Then  메뉴 항목은 "대화방 이름 변경", "대화방 삭제" 순서이고 사이에 구분선이 하나 있다

## 가정
- 화면 배치: 본문은 가운데 최대 너비 3xl(48rem)의 한 열이다. 위에서부터 제목·한 줄 설명 → 검색창(한 줄 전체) → [전체 / 테스터 / 개발자 … 최신순·오래된순] → 결과 수 → 카드 목록이다. 375px에서도 역할 탭과 정렬이 한 줄에 들어가도록 탭 안쪽 여백을 줄인다(12px, sm 이상 16px). (고침 10-30: 프로젝트별을 빼고 역할 탭, 그다음 탭을 왼쪽·정렬을 오른쪽으로)
- 카드: 왼쪽 이미지 칸은 카드 높이를 다 채우고 폭은 96px(sm 128px, md 160px)이다. 선이나 그라데이션 없이 이미지 바로 옆에 내용이 온다. 넓은 화면에서 이미지 칸은 약 160×115px로 이미지 원본 4:3에 가깝다. 내용은 안쪽 여백 위아래 16px·좌우 20px(md 24px), 줄 사이 6px이고, [대화방 이름 … 최근 일시·더보기], [역할 배지 + 상대 닉네임], [미리보기 한 줄] 순서다. 카드 사이 16px. 글자는 모두 최근 메시지와 같은 크기(0.875rem)이고, 대화방 이름만 역할 탭(전체·테스터·개발자)과 같은 굵기(700)로 둔다. 나머지는 보통 굵기이고 색으로 나눈다(대화방 이름·닉네임은 먹, 메시지·일시는 흐린 먹). (고침 10-30: 여백이 없어 답답하다 → 늘림, 이미지 구조 스케치 반영, 세로 여백이 넓다 → 위아래 24px에서 16px로, 이미지 폭도 줄임. 고침 11-01: 세로선을 빼고 그라데이션 → 그라데이션도 빼고, 글자 크기·굵기를 최근 메시지에 맞춤 → 대화방 이름만 역할 탭처럼 굵게)
- 카드 hover는 프로젝트명이 강조색이 되고 이미지가 살짝(105%) 커진다. 이미지가 없을 때의 활자 썸네일은 글자가 4px 올라간다. 그림자는 쓰지 않는다.
- 프로젝트 이미지: `public/sample/projects/`의 시연용 SVG 5장. 웹 서비스(북로그, 모아플랜, 회의록 정리)는 브라우저 창, 앱(레시피핏, 가계부 노트)은 휴대폰 화면 모양이다. 실제 서비스 화면이 아니라 샘플 서비스의 시연용 그림이다. 이미지는 프로젝트명 바로 옆이라 장식으로 보고 대체 텍스트를 비운다. 이미지 칸이 이미지 비율과 다르면 가운데를 기준으로 잘라 채운다. 이미지가 없으면 이름 첫 글자 활자 썸네일을 보여 준다. 첫 카드 이미지는 화면을 열 때 가장 큰 요소(LCP)라 바로 불러온다 (`loading="eager"`, 고침 11-02).
- 대화 상대 표기: 내 닉네임은 쓰지 않고, 작은 배지로 상대의 역할("개발자" 또는 "테스터")을 먼저 쓴 뒤 상대 닉네임(보통 굵기)을 쓴다. 배지(`ChatRoleBadge`)는 6px 모서리, 0.75rem이고, 강조색 없이 테스터는 `Badge` 기본 모양(칩 회색 바탕), 개발자는 `outline`(바탕 없이 1px 재단 회색 안쪽 테두리, 크기는 같다)이다. 보조 기술에는 "대화 상대 개발자 서재지기"로 읽힌다. (고침 10-30: "요청자 | 응답자"에서 바꿈. 고침 11-01: 배지를 앞으로. 고침 11-02: 역할마다 바탕·테두리로 나눔, 리뷰 제안)
- 대화방 이름 변경: 대화상자에 지금 이름이 든 입력창(최대 30자)과 "취소"(ghost)·"저장"(primary)이 있다. 앞뒤 공백을 빼고 빈 이름은 저장하지 않는다. 바꾼 이름은 카드 제목, 더보기 버튼 이름, 검색 대상에 쓰인다. 이미지와 프로젝트는 그대로다.
- 대화방 삭제: 확인 대화상자에 "취소"(ghost, 처음 포커스)와 "삭제"(먹 바탕 `strong`)가 있다. 디자인에 위험 색(빨강)이 없어서 강조색 대신 먹 버튼을 쓴다. 삭제하면 목록·결과 수·탭 수에서 바로 빠진다.
- 저장 위치(시연용): 이름 변경과 삭제는 내 채팅함에만 적용되므로 회원마다 `demo-chat-tester`, `demo-chat-developer` 세션 쿠키에 따로 저장한다 (고침 11-02: 쿠키 하나를 같이 써서 시연 회원을 바꾸면 상대 채팅함에도 반영됐다). 같은 브라우저에서는 새로고침해도 남고, 브라우저를 닫으면 처음 상태로 돌아간다. 서버 액션에서 쿠키를 바꾸면 Next가 페이지를 다시 그려 목록에 반영된다. 채팅방에서 보낸 메시지는 `demo-chat-sent` 쿠키에 보낸 회원과 함께 따로 두고, 그 방 카드의 미리보기·일시·순서에 반영한다.
- 역할 탭: "전체", "테스터"(내가 테스터로 참여한 채팅), "개발자"(내 프로젝트의 채팅) 순서다. 칩 회색 알약 홈 안에서 고른 탭만 교정지 면으로 올라오는 모양이고, 탭마다 채팅방 수를 붙인다. 수는 검색어를 적용한 결과 기준이다. 고른 탭에 채팅방이 없으면 "개발자로 나눈 채팅이 없어요"처럼 안내하고 "전체 보기"를 둔다.
- 강조색을 쓰는 자리 (고침 10-30: 강조색이 안 보인다는 피드백): 오늘 온 대화의 일시와 앞의 점, hover 때 프로젝트명, 고른 역할 탭의 수, 열린 더보기 버튼(연한 강조 바탕 + 강조 아이콘), 그리고 원래 있던 포커스 링·검색창 포커스. 카드마다 반복되는 정보(닉네임, 배지, 썸네일)에는 쓰지 않는다.
- 검색 대상은 바꾼 대화방 이름, 프로젝트명, 대화 상대 닉네임이다. 대소문자를 구분하지 않는다. 입력은 300ms 뒤 반영한다. 그 전에 역할 탭·정렬을 누르면 기다리던 검색어를 함께 반영하고, 링크로 화면을 떠나거나 뒤로·앞으로 가면 버리고, 입력창도 주소에 반영된 검색어로 되돌린다 (고침 11-02). 떠난 채팅함은 입력값째 숨겨진 채 남아서, 되돌리지 않으면 돌아왔을 때 입력창과 목록이 어긋난다.
- 정렬은 최신순(기본, URL에 남기지 않음)과 오래된순 두 가지다. 기준은 최근 메시지 일시다.
- 일시 규칙(서울 시간): 오늘 "오후 3:12", 어제 "어제", 올해 "10월 28일", 작년 이전 "2025. 12. 3.". 오전·오후는 실행 환경의 ICU 버전에 따라 "AM/PM"으로 나올 수 있어서 24시간 값을 받아 직접 붙인다 (고침 11-02). 작년 이전 샘플은 없어서 e2e로 확인하지 않는다. 오늘 샘플은 접속 1분 전이라, 자정 직후 1분 동안은 "어제"로 보일 수 있다.

  - tester(윤슬)는 위 5개 방에 모두 테스터로 들어가 있다. developer(도현랩)는 `ledger-saebyeok`, `ledger-yunseul`, `meeting-yunseul` 3개 방에 개발자로, `booklog-dohyeon` 1개 방에 테스터로 들어가 있다.
  - 요청자가 나면 나의 역할은 개발자, 응답자가 나면 테스터다. 카드에는 반대편 사람이 대화 상대로 나온다.
  - 메시지 내용은 마이페이지 목업과 맞췄다: 북로그 피드백 제출 D-2, 모아플랜 참여 확정, 윤슬의 레시피핏·가계부 노트·회의록 정리 보상, 도현랩의 북로그 보상 6일 전.
  - 서재지기, 모아메이커, 냉장고셰프, 새벽코더는 기존 목업에 없어서 새로 정한 시연용 닉네임이다. 윤슬, 도현랩은 마이페이지 목업의 닉네임이다.
- 가계부 노트와 회의록 정리는 모집 목업에서 일반 모집(`isSubscription: false`)이지만, 마이페이지 목업에는 구독 기능인 "지원자 선정"과 피드백 확인이 있다. 채팅 목업은 마이페이지 쪽을 따라 두 프로젝트를 도현랩의 구독 모집으로 본다. 모집 목업을 고칠지는 따로 정한다.
- 운영자는 서비스 이용 회원이 아니라고 보고(마이페이지 문서와 같다) 채팅방이 없다.
- 채팅방 키(`roomKey`)는 시연용으로 "프로젝트-응답자"로 만든다. 실제 키 형식은 API를 붙일 때 정한다.
- 디자인은 `DESIGN.md` 토큰과 `components/ui`만 쓴다. 새 hex·px 값을 넣지 않는다. 새 토큰은 겹침 `--z-popover` 하나이고, 새 공용 요소는 먹 바탕 버튼(`strong`) 하나다.
