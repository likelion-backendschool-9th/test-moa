# AI 리뷰 묶기 기준 넓히기 (#283)

AI 리뷰 분석(#107)이 리뷰를 기능 × 성격(버그·불편·요청) × 심각도마다 나눠, 1~2건짜리 그룹이 많았다. 성격·심각도로 나누는 규칙은 PR #260에서 "그룹 하나가 카테고리·심각도를 하나만 받는다"는 이유로 넣었는데, 이번에는 그 제약을 가장 심각한 리뷰를 따르는 것으로 푼다(결정 2). 묶는 기준을 기능·화면 하나로 넓히고, 처음 묶은 뒤 남은 1건 그룹을 비슷한 그룹에 합친다. 바뀌는 곳은 분석 서버(`analysis-server`)뿐이고 응답 형식, 메인 백엔드, DB, 화면은 그대로다. 분석 실행·저장은 [ai-review-analysis.md](ai-review-analysis.md)를 따른다. 시나리오는 `#283-S1`부터 센다.

## 한눈에
- 끝나면: 같은 기능·화면의 리뷰가 성격·심각도와 상관없이 한 그룹이 되고, 1건 그룹은 맞는 그룹이 없을 때만 남는다
- 결정 필요: 없음
- 규모: 3단계

## 정한 것 (11-22)

| # | 결정 | 이유 |
| --- | --- | --- |
| 1 | 그룹은 기능·화면 단위로 묶는다. 같은 기능이면 버그·불편·요청이 섞여도, 심각도가 달라도 한 그룹이다. 칭찬은 칭찬끼리 묶는다 | 개발자가 리뷰를 그룹으로 관리하기 쉽다. 칭찬은 칭찬 요약과 칭찬 리뷰 목록이 카테고리(`PRAISE`)로 고르므로 문제 리뷰와 섞지 않는다 |
| 2 | 성격이 섞인 그룹의 카테고리·심각도는 가장 심각한 리뷰를 따르고, 이슈 초안 하나에 증상을 모두 정리한다. 묶기 단계가 그 리뷰를 대표 리뷰로 고른다 | 심각한 버그가 다른 리뷰에 묻혀 낮은 우선순위로 보이지 않게 한다. 라벨 단계는 대표 리뷰를 맨 앞에 두고 최대 5건만 보므로, 대표가 가장 심각해야 심각도가 맞는다 |
| 3 | 테스트 항목은 기본값으로 쓴다. 같은 항목이면 같은 그룹에 넣되, 내용이 다른 기능이면 내용을 따르고, 항목이 없어도 같은 기능이면 합친다 | 항목만으로 묶으면 항목이 넓은 모집글("앱 전체 써 보기")에서 모든 리뷰가 한 그룹이 된다 |
| 4 | 처음 묶은 뒤 1건 그룹이 있으면 가벼운 모델(`label_model`)에 그룹 목록을 보내 옮길 그룹을 묻는다. 맞는 그룹이 없으면 그대로 둔다 | 한 번에 완벽히 묶기보다 묶은 뒤 합치는 쪽이 조절하기 쉽다. 그룹 이름 대신 리뷰 일부만 보내 호출이 가볍다 |
| 5 | 합치기 응답은 그대로 믿지 않는다. 1건 그룹이 아닌 그룹을 옮기거나, 없는 그룹·미분류·자기 자신으로 옮기거나, 이미 옮긴 그룹·이미 다른 그룹을 받은 그룹이 다시 옮겨지는 제안은 버린다. 응답이 이상하면(`LLMOutputError`) 합치지 않고 계속하고, API 장애는 분석 전체를 실패시킨다 | 묶기 검증(#107 결정 7)과 같은 원칙이다. 옮기기가 꼬리를 물지 않아 결과가 제안 순서에만 달려 있다 |
| 6 | 옮긴 리뷰는 받은 그룹의 라벨 예시에서 대표 리뷰 다음에 둔다 | 따로 남았던 리뷰라 그룹의 다른 증상일 가능성이 높아, 이슈 초안에 빠지지 않게 한다 |
| 7 | 1건짜리 칭찬이 여러 개면 기능이 달라도 하나로 모은다. 칭찬과 문제가 함께 있는 리뷰("A는 좋은데 B가 안 돼요")는 문제 쪽 그룹에만 넣는다 | 합쳐도 된다고만 하면 합치기 단계가 칭찬을 하나도 옮기지 않았다. 섞인 리뷰가 칭찬 그룹에 들어가면 라벨 단계가 문제 부분을 보고 칭찬 그룹을 `BUG`로 붙였다(바꾸기 전에도 있던 문제) |
| 8 | 라벨과 합치기 호출의 `max_tokens`는 4000이다 | 라벨용 모델(Haiku 5.5)은 답하기 전에 생각 블록을 쓰고 그 토큰도 `max_tokens`에 들어간다. 증상을 모두 적는 이슈 초안이 1500에서 잘려 그룹이 "분석 실패"가 됐고, 합치기는 1000에서 잘렸다. 상한일 뿐이라 쓴 만큼만 과금된다 |

## 1. 묶는 기준 (#283-R1)

#283-S1 기능·화면 단위로 묶기 [직접]
- Given 평가 리뷰 세트(`analysis-server/evals/grouping_reviews.json`)에 로그인 리뷰로 앱 종료, 자동 로그인 풀림, 애플 로그인 요청, 키보드에 가려지는 버튼이 있다
- When  분석을 실행한다
- Then  네 리뷰가 한 그룹에 들어가고, 칭찬("로그인이 빠르고 간편해요")은 칭찬 그룹에 들어간다

#283-S2 테스트 항목은 기본값, 내용이 우선 [직접]
- Given 항목이 "로그인"인 "로그인은 잘 되는데 통계 화면이 느리게 떠요"와, 항목이 없는 "갤러리에 있는 영수증 사진도 불러올 수 있으면 좋겠어요"가 있다
- Then  앞 리뷰는 통계 그룹에, 뒤 리뷰는 영수증 촬영 그룹에 들어간다

#283-S3 섞인 그룹의 심각도 [직접]
- Given 영수증 촬영 그룹에 "저장하는 중에 앱이 종료됐어요"(치명)와 "긴 영수증은 한 번에 안 찍혀요"(불편)가 함께 있다
- Then  그룹의 대표 리뷰는 앱 종료 리뷰이고, 카테고리는 `BUG`, 심각도는 1이다. 이슈 초안의 현상에 두 증상이 모두 있다

## 2. 1건 그룹 합치기 (#283-R2)

#283-S4 1건 그룹을 같은 기능 그룹에 옮기기 [테스트]
- Given 처음 묶은 결과에 로그인 그룹(3건)과 로그인 리뷰 1건 그룹, 결제 리뷰 1건 그룹이 있다
- When  합치기 단계가 로그인 1건 그룹을 로그인 그룹으로 옮기라고 답한다
- Then  로그인 그룹이 4건이 되고 옮긴 리뷰가 라벨 예시에서 대표 리뷰 다음에 온다. 결제 1건 그룹은 그대로다

#283-S5 잘못된 합치기 제안 [테스트]
- When  합치기 응답에 2건 그룹을 옮기는 제안, 없는 그룹·미분류·자기 자신으로 옮기는 제안, 이미 다른 그룹을 받은 그룹을 옮기는 제안이 섞여 있다
- Then  그 제안은 버리고 나머지만 적용한다. 어떤 리뷰도 사라지지 않는다

#283-S6 합치기 실패 [테스트]
- When  합치기 응답이 스키마에 맞지 않는다
- Then  합치지 않은 결과로 분석을 마친다
- When  합치기 중 Claude API 장애가 난다
- Then  분석 전체가 502로 실패한다(메인 백엔드는 `FAILED`로 바꾼다, #107-S4)

#283-S7 합칠 것이 없음 [테스트]
- Given 1건 그룹이 없거나, 미분류 말고 그룹이 하나뿐이다
- Then  합치기 단계를 부르지 않는다

## 3. 바꾸기 전후 비교 (#283-R3)

#283-S8 평가 리뷰 세트 [직접]
- Given 평가 리뷰 세트 40건(가상의 가계부 앱, 테스트 항목 4개, 의미 없는 리뷰 3건)
- When  `uv run python evals/run_grouping.py 2`를 바꾸기 전후로 실행한다
- Then  그룹 수와 1건 그룹 수가 줄고, 의미 없는 리뷰 3건은 계속 미분류다
- 결과(11-22): 바꾸기 전 2회 평균 그룹 20.5개·1건 그룹 6.5개 → 바꾼 뒤 3회 모두 그룹 9개·1건 그룹 2개(앱 전체 글씨 크기, 가족 공유 요청). 미분류는 3건 그대로

## 범위 밖
- 상위 주제 > 세부 문제 두 단계 그룹(DB·화면 변경)
- 성격별로 이슈 초안을 여러 개 쓰는 것
- 버전 비교(#108)의 짝짓기 기준 완화, 이전 버전 그룹 이름 재사용
- 임베딩·군집화 알고리즘으로 바꾸는 것

## 작업 순서
1. 평가 리뷰 세트와 실행 스크립트(`analysis-server/evals/`), 바꾸기 전 결과
2. 묶기·라벨 프롬프트(`adapters/llm/prompts.py`)
3. 합치기 — 도메인 검증(`domain/clustering.py`), 포트·어댑터·서비스, 테스트

## 가정
- 평가 리뷰 세트는 실제 데이터가 아니라 묶기가 잘게 쪼개지는 경우를 일부러 넣어 만든 것이다. 실제 모집글 리뷰로 다시 확인한다

## 참고
- 버전 비교(#108)는 현재 그룹 하나를 이전 그룹 하나에만 잇는다. 이번 변경 전에 잘게 분석한 버전과 비교하면, 하나로 합쳐진 이전 그룹 가운데 하나만 이어지고 나머지는 "이번 버전에서는 보고되지 않음"으로 나올 수 있다. 두 버전을 다시 분석하면 맞는다
- 라벨 단계는 그룹마다 리뷰 최대 5건(`ANALYSIS_PROMPT_SAMPLES_PER_GROUP`)만 본다. 그룹이 넓어지면 나머지 리뷰의 증상은 이슈 초안에 빠질 수 있어, 대표 리뷰(가장 심각)와 옮긴 리뷰를 앞에 둔다(결정 2, 6)
- 같은 입력이라도 Claude의 묶기 결과는 실행마다 조금씩 달라서, 평가 스크립트는 여러 번 돌려 평균을 본다
- 합치기 결과는 `singletons_merged` 로그(제안 수, 적용 수, 제안 목록)로 본다
- 칭찬 요약·전체 요약(`max_tokens` 400), 후속 질문(600)도 라벨용 모델이라 생각 블록이 길어지면 잘릴 수 있다. 이번 평가에서는 잘리지 않아 그대로 뒀다
- Windows의 한글 경로에서는 `uv run pytest`가 "uv trampoline failed to canonicalize script path"로 실패한다. `uv run python -m pytest`로 돌린다
