# 채팅방 메시지 검색 화면 (#105)

채팅방(`/my/chats/:roomKey`)에서 검색어를 넣으면 찾은 메시지로 대화가 이동해 강조되고, 위·아래 화살표로 다른 결과로 옮겨 간다. 채팅방 화면은 [chat-room.md](chat-room.md), 검색 API는 [search.md](../../backend/chat/search.md)(#105-R1~R3), 채팅 백엔드 결정은 [README.md](../../backend/chat/README.md)에 있다.

## 한눈에
- 끝나면: 대화방 머리의 돋보기 버튼을 누르면 화면 아래 입력창 자리에 검색 띠(검색창, "1/3", 위·아래 화살표, 닫기)가 뜬다. 검색어를 넣고 Enter를 누르면 가장 최근 결과로 대화가 이동하고 그 말풍선이 강조된다. 위 화살표는 더 오래된 결과로, 아래 화살표는 더 최근 결과로 간다. 결과가 이미 불러온 대화보다 오래되었으면 이전 메시지를 이어 불러온 뒤 이동한다. 결과가 없으면 "검색 결과가 없어요"를 알린다. 닫으면 입력창이 쓰던 글 그대로 돌아온다. 목업 모드에서도 같은 동작을 한다
- 결정 필요: 없음
- 규모: 5단계

## 정한 것
- 결과 사이는 위·아래 화살표와 "2/5" 표시로 오간다. 결과 목록 화면은 두지 않는다 (11-21 사용자 결정, 이슈의 "정할 것" 1)
- 대화보다 오래된 결과로 갈 때는 결과가 나올 때까지 `before=`로 30개씩 이어 불러 붙인다. 결과 주변만 받는 새 조회(`around=`)는 만들지 않는다. 화면이 "최근 메시지부터 끊김 없이 이어진 목록"이라는 전제(실시간 채우기, 읽음 처리, 맨 아래 스크롤)를 그대로 지키기 위해서다 (11-21 사용자 결정, 이슈 참고의 "이 순번 주변")

## 1. 검색 열기와 결과로 이동 (#105-R4)
참여자가 검색어를 넣으면 가장 최근 결과로 대화가 이동하고, 그 말풍선이 강조된다. 그 자리에서 위·아래로 스크롤해 앞뒤 대화를 이어서 볼 수 있다.

#105-S7 정상 [테스트]
- Given 목업 모드에서 윤슬로 `/my/chats/booklog-yunseul`을 열었다 (사진이 들어간 메시지는 "독서 기록에 사진을 여러 장…", "확인해 보니 사진을 한 번에…", "업데이트하고 나니 사진 순서가…" 셋)
- When  "대화 내용 검색" 버튼을 누른다
- Then  입력창 자리에 검색창("대화 내용 검색")이 뜨고 검색창에 포커스가 있다
- When  "사진"을 입력하고 Enter를 누른다
- Then  결과 수가 "1/3"이다
- Then  "업데이트하고 나니 사진 순서가 그대로 잘 나와요." 말풍선이 강조되고(`aria-current="true"`) 화면 안에 있다

#105-S8 정상: 오래된 결과 이어 불러오기 [테스트]
- Given 불러온 대화가 순번 36~65이고, 찾은 결과가 순번 5다
- When  결과 순번 5로 이동한다
- Then  `before=36`, `before=6`을 차례로 부르고, 대화는 순번 1~65로 끊김 없이 이어진다
- When  결과 순번 40으로 이동한다
- Then  이미 불러온 대화 안이라 아무것도 부르지 않는다

#105-S9 직접: 실제 API에서 오래된 결과로 이동 [직접]
- Given `AUTH_MODE=backend`에서 메시지가 70개 넘는 방에, 순번 5에만 "접속 주소"가 있다
- When  "접속 주소"를 검색한다
- Then  이전 메시지를 이어 불러온 뒤 순번 5 말풍선이 강조된 채 화면 가운데쯤에 있고, 위·아래로 스크롤하면 앞뒤 대화가 끊김 없이 보인다
- Then  검색 띠를 닫고 아래로 스크롤해 맨 아래까지 내려가면 상대가 새로 보낸 메시지도 실시간으로 붙는다
- When  결과가 이어 불러온 대화의 첫 메시지가 되는 검색어를 넣는다(예: 순번 6에만 있는 말. 이어 불러오면 대화가 6~65가 된다)
- Then  가운데로 옮기며 맨 위 감시 요소가 보여 이전 메시지를 더 불러와도, 강조된 말풍선이 화면 밖으로 밀려나지 않는다
- When  맨 아래에서 먼 오래된 결과를 보는 채로 상대가 메시지를 보낸다
- Then  강조된 결과 자리에 머물고 맨 아래로 끌려가지 않는다 (맨 아래 근처에서만 따라 내려가는 지금 규칙 그대로)

## 2. 다른 결과로 옮기기 (#105-R5)
위 화살표("이전 결과")는 더 오래된 결과로, 아래 화살표("다음 결과")는 더 최근 결과로 옮긴다. 결과 수 표시는 가장 최근 결과가 1이다.

#105-S10 정상 [테스트]
- Given #105-S7에서 "1/3"이다
- When  "이전 결과"를 누른다
- Then  "2/3"이고 "확인해 보니 사진을 한 번에 여러 장 올릴 때 생기는 문제였어요." 말풍선이 강조된다. 앞 결과의 강조는 사라진다
- When  "이전 결과"를 한 번 더 누른다
- Then  "3/3"이고 "독서 기록에 사진을 여러 장 올리면 순서가 바뀌는 것 같아요."가 강조되며, "이전 결과"는 비활성이다
- When  검색창에서 Enter를 누른다
- Then  "3/3" 그대로다 (처음 결과로 돌아가지 않는다)
- When  "다음 결과"를 두 번 누른다
- Then  "1/3"이고 "다음 결과"는 비활성이다

## 3. 결과가 없을 때 (#105-R6)
찾은 메시지가 없으면 없다고 알리고 대화 위치는 그대로 둔다.

#105-S11 실패: 결과 없음 [테스트]
- Given #105-S7의 방에서 검색 띠를 열었다
- When  "환불"을 입력하고 Enter를 누른다
- Then  "검색 결과가 없어요"가 보이고 "이전 결과"·"다음 결과"는 비활성이다
- Then  강조된 말풍선이 없다

## 4. 검색 닫기 (#105-R7)
닫기를 누르거나 Esc를 누르면 검색 띠가 닫히고 강조가 사라지며, 입력창이 쓰던 글 그대로 돌아온다. 대화 위치는 바꾸지 않는다.

#105-S12 정상: 쓰던 글이 남는다 [테스트]
- Given #105-S7의 방에서 입력창에 "내일 다시 볼게요"를 써 두었다
- When  검색 띠를 열고 "사진"을 검색한 뒤 Esc를 누른다
- Then  입력창이 다시 보이고 내용은 "내일 다시 볼게요"다
- Then  강조된 말풍선이 없고, "대화 내용 검색" 버튼에 포커스가 있다

## 5. 모양과 접근성 (#105-R8)
검색 띠는 입력창 띠와 같은 자리·모양이고, 강조는 디자인 토큰 안에서 한다. 좁은 화면에서도 가로 스크롤이 없다.

#105-S13 화면 [직접]
- Given 1440px·375px, 라이트·다크
- When  #105-S7~#105-S11을 차례로 해 본다
- Then  검색 띠가 입력창 띠와 같은 높이·바탕이고, 375px에서 검색창·결과 수·화살표·닫기가 한 줄에 들어가며 가로 스크롤이 없다
- Then  강조된 말풍선이 내 말풍선(강조색 바탕)이어도 상대 말풍선이어도 강조가 보인다
- Then  결과 수의 바뀜을 스크린 리더가 읽는다(`aria-live="polite"`)

## 가정
- 검색 버튼은 대화방 머리의 더보기 왼쪽에 둔 돋보기 아이콘 버튼("대화 내용 검색")이다. 머리는 위에 붙지 않아서, 결과로 이동해도 계속 보이도록 검색 띠는 화면 아래에 붙은 입력창 자리에 띄운다
- 검색은 Enter로 시작한다. 입력할 때마다 찾지 않는다. 검색 띠가 열린 채 검색어를 바꾸고 Enter를 누르면 새로 찾아 다시 "1/N"부터 간다. 같은 검색어로 Enter를 다시 누르면 "이전 결과"와 같고, 가장 오래된 결과("N/N")에서는 그 자리에 머문다. 처음 결과로 돌아가지 않는다
- 검색어는 앞뒤 공백을 뺀 1자 이상, 100자 이하다(입력창 `maxLength` 100). 비었으면 Enter를 눌러도 부르지 않는다
- 결과는 검색한 순간의 목록이다. 검색 띠가 열린 동안 새로 온 메시지는 다시 검색해야 결과에 들어간다
- 이동은 말풍선을 화면 가운데로 부드럽게 스크롤한다(`scrollIntoView({ block: "center" })`). 강조는 검색 띠를 닫거나 다른 결과로 옮길 때까지 남는다
- 결과까지 이어 불러오는 동안 결과 수 자리에 "찾는 중…"을 쓰고 화살표를 비활성으로 둔다. 이어 불러오기가 실패하면 "메시지를 불러오지 못했어요"를 쓰고, 그때까지 불러온 대화는 그대로 둔다. 401·404는 이전 메시지 불러오기처럼 `router.refresh()`한다
- 목업 모드는 방의 대화를 모두 한 번에 받으므로 이어 불러오기 없이 바로 이동한다
- 검색해도 읽음 처리는 바뀌지 않는다. 읽음은 지금처럼 불러온 대화의 마지막 순번으로 보낸다

## 참고 (2026-11-21 확인)
- 대화 상태는 `ChatConversation/hook.ts`의 `useChatConversation`이 가진다. 이전 메시지는 맨 위 감시 요소(`IntersectionObserver`)가 보이면 `before=`로 30개씩 붙이고, 붙인 뒤 첫 말풍선 위치를 기준으로 스크롤을 되돌린다(`anchor`)
- 새 메시지는 SSE 알림을 받을 때마다 `after={마지막 순번}`으로 채우고, `shouldReplaceChatMessages`는 새 서버 목록 바로 앞 순번이 없으면 목록을 통째로 바꾼다. 이어 불러오기도 순번이 끊기지 않게 붙여야 이 판단이 틀어지지 않는다
- e2e는 목업 모드로 돈다. 목업 대화는 방마다 10개 미만이라 이어 불러오기는 단위 테스트(#105-S8)와 직접 확인(#105-S9)으로 본다
