# 프론트엔드 참여 테스트 (`/my/participations`)

테스터가 지원하고 참여한 테스트를 한곳에서 관리하는 화면이 지켜야 하는 요구사항(R)과 시나리오(S)를 모았다. S번호는 홈(S2~S82)과 겹치지 않게 S448부터 매기고(S468·S469는 나중에 더했다. 리뷰 반영으로 더한 S470·S471는 다른 문서와 겹치지 않게 비어 있는 다음 번호를 썼다), `frontend/e2e/participations.spec.ts`(상세는 `participation-detail.spec.ts`)의 테스트 이름과 1:1로 맞는다(S467는 grep으로 확인). 상세 시나리오 S472~S481와 리뷰 반영 S482도 비어 있는 다음 번호를 썼다. 테스트를 추가하거나 바꾸면 이 문서도 함께 고친다.

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`만 e2e 테스트와 1:1이고, `[테스트: 파일 번호]`는 그 테스트가 대신 확인한다. `[명령]`은 명령 한 번, `[직접]`은 사람이 화면을 보고 확인한다. (고침 #56: `docs/test-cleanup.md`)

## 한눈에
- 누가: 로그인한 테스터. 비로그인은 로그인으로 보낸다.
- 무엇을: "다음에 뭘 해야 하지?"에 바로 답한다. 피드백 제출 마감, 크레딧 지급 시점, 선정 결과를 지원 순서가 아니라 급한 순서로 보여 준다.
- 화면 구성(위에서부터):
  1. 공통 헤더(홈과 같음). "참여 테스트" 탭이 현재 탭이다
  2. 페이지 제목 "참여 테스트"와 한 줄 요약(제출할 피드백 n개, 지급 대기 n크레딧)
  3. 마감 캘린더와 마감 임박 테스트: 왼쪽은 내 피드백 제출 마감을 표시한 달력, 오른쪽은 제출 전 테스트를 마감 순으로 모은 목록이다. 좁은 화면에서는 위아래로 쌓인다. 주 버튼은 목록 맨 위에만
  4. 탭 3개: 지원한 테스트 / 참여 중인 테스트 / 참여했던 테스트 (개수 표시)
  5. 선택한 탭의 참여 목록(행 카드)
  6. 상세(`/my/participations/:participationKey`): 진행 상황, 피드백 작성 또는 제출한 피드백, 테스트 정보
- URL: `docs/page-urls.md`의 참여 테스트 섹션을 따른다. 탭은 `?tab=applied|ongoing|history`, 상세는 `/my/participations/:participationKey`(`docs/page-urls.md`에서는 아직 후보).
- 디자인: `frontend/DESIGN.md`와 `docs/design-tokens.html`의 토큰·컴포넌트를 그대로 쓴다. 새 색이나 새 버튼 스타일을 만들지 않는다.
- 데이터: 목업이다. `demo-role`, `demo-data` 쿠키로 상태를 바꾼다(홈과 같은 장치).

## 참여 상태와 탭
README의 흐름(지원 → 참여 확정 → 테스트 → 피드백 제출 → 72시간 신고 대기 또는 운영자 검토 → 지급)을 아래 상태로 나눈다. 탭은 상태를 묶은 것이다.

| 탭 | 상태 | 화면 문구 | 행에서 보여 줄 날짜 | 행 동작 |
| --- | --- | --- | --- | --- |
| 지원한 테스트 `applied` | 선정 대기 | "선정 대기" | 모집 마감일 | 모집 글 보기 |
| | 미선정 | "미선정" | 모집 마감일 | 모집 글 보기 |
| 참여 중인 테스트 `ongoing` | 제출 전 | "피드백 제출 전" + D-day | 피드백 제출 마감일 | 피드백 쓰기 |
| | 지급 대기 | "지급 대기" | 지급 예정 일시(제출 + 72시간) | 제출 내용 보기 |
| | 운영자 검토 | "운영자 검토 중" | 제출일 | 제출 내용 보기 |
| 참여했던 테스트 `history` | 지급 완료 | "지급 완료" + 받은 크레딧 | 지급일 | 상세 보기 |
| | 미완료 | "기한 내 미제출" | 피드백 제출 마감일 | 상세 보기 |
| | 보상 제외 | "보상 제외" | 검토 완료일 | 상세 보기 |

- 무료 모집은 선착순 확정이라 지원과 동시에 "참여 중"으로 간다. "지원한 테스트"에는 구독 모집(개발자가 직접 선정)만 남는다.
- 상태 문구는 존댓말 해요체로 쓰고, 운영 용어(신고, 제재)는 행에서 직접 쓰지 않는다.

## 2. 탭 (R183)

## 3. 마감 캘린더와 마감 임박 테스트 (R184)
로그인한 테스터 본인의 피드백 제출 전 참여만 다룬다. lg 이상은 왼쪽에 마감 캘린더, 오른쪽에 마감 임박 테스트를 나란히 두고, 그보다 좁으면 위아래로 쌓는다. "임박"은 기간으로 자르지 않고 제출 전 참여 전체를 마감이 가까운 순서로 보여 준다. 캘린더는 오늘이 있는 달에서 시작하고 이전·다음 버튼으로 넘긴다. 마감일 칸은 md 이상에서 서비스 이름을(같은 날이 여러 건이면 첫 이름과 "외 n건"), 그보다 좁으면 점을 보여 주고, 스크린 리더는 어느 폭에서나 이름을 읽는다. 날짜 계산은 서울 시간 기준이다. 이 화면의 주 버튼(강조색)은 목록 맨 위 항목의 버튼 하나뿐이고, 나머지는 보조 버튼이다.

S455 목록 맨 위 [테스트] (고침 #46: 다음 할 일 카드를 마감 임박 목록으로 바꿈)
- Then  첫 항목에 "회의록 정리"와 "D-8"이 보이고, 주 버튼 "피드백 쓰기"가 그 참여의 상세(`/my/participations/:participationKey`)를 가리킨다
- Then  화면의 강조색 바탕 버튼은 이것 하나다

#46-S9 마감 임박 목록 [테스트]
- Then  제목이 "마감 임박 테스트 4"이고 회의록 정리(D-8) → 중고책 장터(D-12) → 가계부 노트(D-14) → 모아플랜(D-16) 순서다
- Then  "중고책 장터 피드백 쓰기"는 보조 버튼이고 그 참여의 상세를 가리킨다

#46-S10 마감 캘린더 [테스트]
- Then  이번 달 제목과 일~토 머리글이 있고, 오늘 칸이 `aria-current="date"`다
- Then  이번 달과 다음 달을 합쳐 마감일 칸에 위 4개 테스트가 "<이름> 제출 마감"으로 표시된다

#46-S11 달 넘기기 [테스트]
- When  "다음 달"을 12번 누른다
- Then  매번 제목이 한 달씩 바뀌고 해가 바뀌어도 맞는다
- When  "이전 달"을 누르고 탭을 바꾼다
- Then  오늘이 없는 달에는 오늘 표시가 없고, 탭을 바꿔도 보던 달이 남는다

#46-S14 같은 날 마감 여러 건 [직접]

- Then  칸에 첫 이름과 "외 1건"이 보이고 그 주의 줄 높이가 다른 주와 같다
- Then  스크린 리더는 두 이름을 모두 읽는다

#46-S12 배치 [직접]

## 4. 참여 목록 (R185)
행 카드는 활자 썸네일 → 이름·요청 문구 → 상태 → 날짜 → 보상 → 동작 순서로 고정한다. 정렬은 탭마다 하나로 정하고 바꾸는 장치는 두지 않는다.

S457 참여 중 정렬 [테스트]
- Then  "참여 중인 테스트"의 행이 할 일 순서다: 제출 전(제출 마감 가까운 순) → 지급 대기 → 운영자 검토
- Then  첫 행이 "회의록 정리"다

S458 행 내용 [직접] (고침 #46: 추가 보상을 썸네일 배지로 옮김)
- Then  각 행에 서비스 이름 활자 썸네일, 요청 문구(모집 글의 `request`, 예: "회의록 작성 후 할 일 목록이 맞는지 보기"), 상태 문구(위 표의 화면 문구, 예: "피드백 제출 전"), 날짜, 기본 보상이 있다
- Then  구독 모집 행에만 썸네일 오른쪽 위에 "추가 보상 +320 크레딧" 같은 금액 배지가 있다 (강조색)

S459 지급 대기 [직접]
- Then  "스터디 매칭" 행에 "지급 대기"와 지급 예정 일시가 보인다
- Then  "72시간 동안 신고가 없으면 자동으로 지급돼요" 안내가 있다

S460 지원한 테스트 [테스트]

- Then  "북로그"(선정 대기), "레시피핏"(미선정) 2행이 있고, 선정 대기가 먼저다
- Then  각 행의 "모집 글 보기"가 `/recruitments/:slug`를 가리킨다

- Then  최근 순으로 3행이 있고, 맨 위에 "받은 크레딧 합계"가 지급 완료 행의 합으로 보인다
- Then  "지급 완료" 행의 썸네일에 "지급 완료" 도장(`role="img"`)이 있다

제목과 탭은 데이터를 기다리지 않고, 목록은 행 모양 스켈레톤을 먼저 보여 준다.

- Then  응답 뒤 캘린더, 마감 임박 목록, 행이 보이고 스켈레톤은 없다

## 12-1. 피드백 이미지 (#57-R1)
피드백을 쓰면서 이미지를 PNG·JPG·WEBP로 한 장에 5MB까지, 5장까지 고를 수 있다. 고르면 바로 미리 보고 뺄 수 있다. 한도를 넘는 파일이 섞이면 이번에 고른 파일은 넣지 않고 이유를 알린다. 시연용이라 파일은 서버로 보내지 않고 이름·크기·형식만 보내며, 제출한 피드백에는 내용 아래에 미리 보기와 같은 크기의 칸으로 아이콘과 파일 이름이 남는다. 실제 업로드와 이미지 다시 보기는 백엔드 저장소가 정해지면 붙인다.

#57-S1 미리 보기와 빼기 [테스트]
- When  이미지 2장을 고른다
- Then  미리 보기 2개와 "2 / 5"가 보인다
- When  한 장을 뺀다
- Then  미리 보기가 1개가 되고 포커스가 "이미지 추가"로 간다

#57-S2 장수 한도 [테스트]
- Given 4장을 골랐다
- When  2장을 더 고른다
- Then  "이미지는 5장까지 올릴 수 있어요"가 보이고 4장 그대로다
- When  1장을 더 고른다
- Then  5장이 되고 "이미지 추가"가 없다. 한 장을 빼면 다시 나타나 포커스를 받는다

#57-S3 형식과 용량 [테스트]
- When  GIF나 5MB가 넘는 파일을 고른다
- Then  이유가 보이고 들어가지 않는다
- When  맞는 파일을 고른다
- Then  안내가 사라지고 들어간다

#57-S4 제출 [테스트]
- When  이미지 2장과 함께 제출한다
- Then  요청에 파일 내용이 없다
- Then  제출한 피드백에 "첨부 이미지 2"와 파일 이름이 있고, 새로고침해도 남는다

#57-S5 서버 확인 [테스트]
- Given 숨은 칸의 값을 6장으로 바꿨다
- When  제출한다
- Then  "이미지는 5장까지 올릴 수 있어요"가 보이고 입력과 미리 보기가 남는다

#57-S6 이미지 없이 제출 [직접]
- When  이미지를 모두 빼고 제출한다
- Then  제출한 피드백에 첨부 이미지가 없다

#57-S7 화면 배치 [직접]
- Then  "이미지 0 / 5" 옆에 형식·용량·장수 안내가 있고, 좁은 화면에서는 안내가 다음 줄로 내려간다
- Then  제출한 이미지는 내용 아래에 같은 크기의 정사각형 칸으로 넓은 화면 5칸, 좁은 화면 3칸씩 놓인다
- Then  너비 375px에서 긴 파일 이름은 말줄임되고 가로 스크롤이 없으며, 마우스를 올리면 전체 이름이 보인다

## 13. 상태별 상세 (R194)
상태마다 지금 단계와 다음에 일어날 일을 진행 상황에 한 줄로 알리고, 제목 바로 아래 "테스트 정보"에 마감일·보상·진행 날짜를 둔다. 운영 용어(신고 사유, 제재)는 쓰지 않는다.

## 디자인 메모
- 강조색(One Green Rule): 마감 임박 목록 맨 위의 주 버튼, 추가 보상(목록은 썸네일 배지, 상세는 줄), "지급 완료" 도장, 포커스만. 상태 배지와 D-day는 강조색을 쓰지 않는다.
- 상태 배지: `Badge`(칩 회색 알약). 급한 정도는 굵기로만 나타낸다(Weight-Not-Paint). D-3 이하는 800 굵기 먹색.
- 탭: 헤더 탭과 같은 알약 탭 모양(현재 탭은 칩 회색 바탕). 개수는 `tabular-nums`, 흐린 먹.
- 행 카드: 교정지(surface-muted) 16px 면, 안쪽 24px. 리스트의 썸네일은 폭 192px로 고정한 16:10이다. 좁은 화면에서도 추가 보상 배지가 재단선과 도장을 가리지 않는 폭이다.
- 마감 일정: 교정지 면 두 칸. 마감일 칸은 강조색 없이 칩 회색 바탕에 800 굵기로, 오늘은 먹색 2px 안쪽 테두리로 나타낸다(Weight-Not-Paint). 이전·다음 달은 보조 버튼(칩 회색 알약, 아이콘만)이다.
- 상세: 썸네일은 제목과 이름이 겹쳐 보조 기술에서 숨기고, 상태는 배지 글자로 읽힌다. 테스트 정보는 모집 글에 대한 정보라 제목 바로 아래에 목록 행과 같은 모양(작은 항목 이름 + 굵은 값)으로 둔다(10-31: 오른쪽 카드는 따로 떨어져 보인다는 피드백으로 옮김). 진행 상황은 바탕 없이 제목·본문, 피드백 작성·제출한 피드백은 교정지 카드다. 피드백 칸은 프로젝트 폼과 같은 12px 모서리 입력 칸(`inputClass`)이고, 제출 버튼은 알약 주 버튼이다(금액 폼이 아니라 The Money Field Rule 대상이 아니다).
- 보기 방식: 채팅함 역할 탭(`ChatFilters`)과 같은 세그먼트 모양에 아이콘만 둔다. 이름은 `aria-label`과 마우스를 올렸을 때 뜨는 `title`로 알린다. 목록 맨 위 줄 오른쪽에 놓고, 참여했던 테스트에서는 왼쪽에 받은 크레딧 합계가 온다.
- 그림자 없음, 이징은 `--ease-brand` 하나.

## 데모 데이터와 가정
- 테스터 "한서윤"의 참여 11건은 시연용 샘플이다. 개발자·운영자 데모 계정은 참여 내역이 없다. 진행 중인 건은 홈 목업의 모집 글을 가리키고, 끝난 건은 새로 만든 지난 모집 글 3개("메모 정원", "주차 알리미", "카페 지도")를 쓴다.
  - 지원한(2): 북로그(선정 대기), 레시피핏(미선정)
  - 참여 중(6): 회의록 정리(제출 전, 제출 마감 D-8), 중고책 장터(제출 전, D-12), 가계부 노트(제출 전, D-14), 모아플랜(제출 전, D-16), 스터디 매칭(지급 대기, 지급까지 약 30시간), 동네 러닝 크루(운영자 검토 중)
  - 참여했던(3): 메모 정원(지급 완료), 주차 알리미(지급 완료), 카페 지도(기한 내 미제출)
- `demo-data=empty`는 참여 0건, `slow`는 1.5초 지연이다. `single`은 홈 전용이라 여기서는 normal로 본다.
- 모집 마감일·피드백 제출 마감일은 참여 목업에 따로 두지 않고, 가리키는 모집 글의 값을 그대로 쓴다.
- 보상 크레딧은 기획에서 미정이라 홈 목업 값을 그대로 쓴다. 미선정·미제출·보상 제외는 받은 크레딧 0이다.
- 미선정은 "지원한 테스트"에 남긴다(참여하지 않았으므로 "참여했던"이 아니다).
- 기본 탭은 할 일이 있는 "참여 중"으로 정했다.
- 스터디 매칭은 지급까지 약 30시간(제출 42시간 전)이라, 제출이 모집 글 등록보다 앞서지 않게 홈 목업의 등록일을 1일 전에서 4일 전으로 옮겼다. 홈 시나리오 결과는 바뀌지 않는다.
- 피드백 글자 수는 기획에서 미정이라 20~500자로 정했다. 최대 길이는 시연용 저장(쿠키) 한도에 맞춘 값이다.
- 샘플 중 지급 대기·운영자 검토 중·지급 완료 4건에는 시연용 피드백 원문을 넣었다. "보상 제외" 샘플은 없어서 그 상태의 상세는 E2E로 확인하지 않는다.
- D-3 이하가 아니면 D-day는 600 굵기 흐린 먹이다. 끝난 상태(미선정, 기한 내 미제출, 보상 제외) 배지는 흐린 배지(`Badge tone="muted"`)다.
