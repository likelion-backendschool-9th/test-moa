# 프론트엔드 운영자 플랜 관리 (`/admin/plans`)

운영자가 무료 플랜과 구독 플랜의 혜택을 고치는 페이지의 요구사항과 시나리오다. 이슈: [#257](https://github.com/likelion-backendschool-9th/test-moa/issues/257). 요구·시나리오는 `#257-R…`, `#257-S…`로 센다.

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`만 테스트와 1:1이고, `[테스트: 파일 번호]`는 그 테스트가 대신 확인한다. `[직접]`은 사람이 화면을 보고 확인한다.

## 한눈에
- 화면 안에 하위 탭이 둘이다. "혜택"(`/admin/plans`)은 아래 플랜 혜택 편집이고, "회원 구독"(`/admin/plans?tab=subscriptions`)은 회원에게 구독을 주고 빼는 화면이다([subscriptions.md](subscriptions.md)의 #204-S11~S16을 그대로 옮겼다). 선택한 탭은 주소의 `tab`에 남고, 회원 검색은 `email`이 붙는다. 운영자 상단 탭에서는 "구독"을 없애고 "플랜" 하나로 합쳤다.
- 예전 주소 `/admin/subscriptions`(검색 `?email=` 포함)는 "회원 구독" 탭으로 넘어간다.
- 목적: 운영자가 API를 직접 부르지 않고 화면에서 무료 플랜의 이름·혜택과 구독 플랜의 혜택을 바꾼다.
- 화면 구성: 운영자 하위 탭에 "플랜"을 더한다. 무료 플랜 패널 하나, 지금 파는 구독 플랜마다 패널 하나. 패널마다 혜택 입력칸(한 줄에 하나)과 저장 버튼이 있다.
- 데이터: **백엔드 모드(`AUTH_MODE=backend`)에서만 동작한다.** 목업 모드에서는 "백엔드와 연결했을 때 쓸 수 있어요" 안내만 보인다(두 탭 모두).
- 백엔드: 무료 `GET /api/v1/plans/free`·`PUT /api/v1/admin/plans/free`([free-plan.md](../../backend/payment/free-plan.md)), 구독 `GET /api/v1/plans`·`POST /api/v1/admin/plans`([subscription.md](../../backend/payment/subscription.md)). 백엔드 변경은 없다.
- 구독 플랜은 혜택만 고치는 API가 없어 **새 버전 등록**(`POST`)으로 저장한다. 서버가 `version`을 올린 새 행을 만들고, 이미 구독한 회원은 산 당시의 플랜 행을 그대로 가리킨다. 가격·크레딧 가격·이용 기간은 저장 시점의 서버 값을 그대로 보낸다(편집 화면이 오래돼도 다른 값으로 덮어쓰지 않는다).
- 범위 밖: 구독 플랜의 가격·기간 변경, 플랜 삭제·판매 중지, 이전 버전 목록, 혜택만 고치는 백엔드 API.
- 페이지 URL: `docs/page-urls.md`

이 아래 시나리오는 따로 적지 않으면 `demo-role=admin`이고 백엔드 모드다.

## 1. 접근 권한 (#257-R1)

#257-S1 일반 회원·비로그인 [테스트: pages.spec.ts #56-S2, #56-S3]
- When  비로그인이나 일반 회원이 `/admin/plans`에 접속한다
- Then  비로그인은 로그인으로 가고, 일반 회원은 접근할 수 없다는 화면이 보인다

## 2. 목업 모드 안내 (#257-R2)

#257-S5 목업 모드에서는 안내만 보인다 [테스트]
- Given `demo-role=admin`이고 백엔드 모드가 아니다
- When  `/admin/plans`에 접속한다
- Then  "백엔드와 연결했을 때 쓸 수 있어요"가 보이고 혜택 입력칸은 없다. "플랜" 탭이 현재 탭이다

## 3. 현재 값 보기 (#257-R3)

#257-S2 현재 값이 채워져 보인다 [직접]
- Given 서버에 무료 플랜 혜택과 구독 플랜이 있다
- When  `/admin/plans`에 접속한다
- Then  무료 패널에 이름과 혜택(한 줄에 하나)이, 구독 패널마다 플랜 이름과 혜택이 채워져 있다. 혜택이 없으면 입력칸이 비어 있다
- Given 지금 파는 구독 플랜이 없다
- Then  "지금 파는 구독 플랜이 없어요" 안내가 보인다

## 4. 혜택 저장 (#257-R4)

#257-S3 무료 플랜을 저장한다 [직접]
- When  이름이나 혜택을 고치고 "저장"을 누른다
- Then  "무료 플랜을 저장했어요"가 보이고, `/subscription`의 무료 카드에 새 값이 보인다

#257-S4 구독 플랜 혜택을 새 버전으로 저장한다 [직접]
- When  구독 패널의 혜택을 고치고 "새 버전으로 저장"을 누른다
- Then  "새 버전으로 등록했어요"가 보이고, `/subscription`과 결제 화면의 플랜에 새 혜택이 보인다. 가격·기간은 그대로다
- Then  이미 구독한 회원의 `/my/subscription`은 계속 구독 중이다

## 5. 입력 검사 (#257-R5)

#257-S6 혜택 입력은 한 줄에 하나로 자르고 서버 상한을 넘으면 거절한다 [테스트: tests/unit/subscription.test.ts]
- Given 앞뒤 공백·빈 줄이 섞인 입력
- Then  공백을 지우고 빈 줄은 뺀 목록이 된다
- Given 혜택이 11개 이상이거나, 한 줄이 100자를 넘거나, 쉼표를 담았다
- Then  저장하지 않고 이유를 알린다(10개까지·100자까지·쉼표 불가)

#257-S7 서버가 거절하면 이유가 화면에 보인다 [직접]
- Given 저장하는 사이 운영자 세션이 만료되었거나 서버가 오류를 돌려준다
- When  저장을 누른다
- Then  서버의 이유가 패널 안에 보이고, 입력한 내용은 그대로 남는다
- Given 저장하는 사이 운영자 세션이 끝났다(로그아웃·갱신 실패)
- Then  오류 화면 대신 패널에 "운영자 로그인을 확인하지 못했어요. 다시 로그인한 뒤 저장해 주세요"가 보이고 입력한 내용은 남는다
- Given 구독 플랜을 저장하기 전 지금 플랜을 다시 읽는 조회(`GET /api/v1/plans`)가 실패한다
- Then  오류 화면 대신 그 이유가 패널에 보이고 저장하지 않는다

## 6. 회원 구독 탭 (#257-R6)

#257-S8 예전 `/admin/subscriptions` 주소는 회원 구독 탭으로 넘어간다 [테스트]
- When  `/admin/subscriptions?email=a@example.com`에 접속한다
- Then  `/admin/plans?tab=subscriptions&email=a%40example.com`으로 가고 "회원 구독" 탭이 현재 탭이다

#257-S9 회원 구독 탭의 접근 권한과 목업 안내 [테스트: pages.spec.ts #56-S2, #56-S3 · admin-plans-subscriptions.spec.ts #204-S12]
- 접근 권한([subscriptions.md](subscriptions.md) #204-S11): `PAGES`에 `/admin/plans?tab=subscriptions`가 있어서, 비로그인은 이 주소로 돌아오게 로그인으로 가고 일반 회원은 운영자 안내만 보는지를 `pages.spec.ts`가 확인한다
- 목업 안내(#204-S12): 안내 문구가 보이고 검색창·"구독 주기" 버튼이 없으며 "회원 구독"·"플랜" 탭이 현재 탭인지만 확인한다

#257-S10 회원 구독 탭의 이메일 검색과 구독 주기·빼기 [직접]
- 이메일 검색·없는 이메일·운영자 계정·구독 주기/빼기는 #204-S13~S16과 같다. 자동 테스트는 없어 백엔드 모드에서 사람이 확인한다
- 비로그인으로 `/admin/plans?tab=subscriptions&email=…`에 들어가 로그인하면 검색 주소까지 그대로 돌아온다(검색어가 붙은 주소는 #257-S9가 확인하지 않는다)
