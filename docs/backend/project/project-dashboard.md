# 내 프로젝트 전체 현황 API (#122)

내 프로젝트 목록 위의 "전체 현황"이 쓰는 API. 화면 규칙은 [프로젝트 화면 S523](../../frontend/project/projects.md)이고, 도메인 전체에서 정한 것은 [README.md](README.md)에 있다. (고침 #251: "지금 확인할 일"을 화면에서 없애 `todos`와 그 쿼리도 지웠다)

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`는 백엔드 테스트와 1:1이다(`@DisplayName("#122-S…")`).

## 이슈 #122 확인

| 이슈 항목 | 시나리오 |
| --- | --- |
| 1 확정을 기다리는 지원자 수를 모집 건별로. 구독 모집이고 모집 마감 전인 것만 | #122-S1 (고침 #251: 없앰) |
| 2 72시간이 지나지 않은 신고 대기 피드백 수와 자동 지급까지 남은 시간을 모집 건별로 | #122-S2 (고침 #251: 없앰) |
| 3 지원자 항목이 먼저, 피드백 항목은 자동 지급이 가까운 순서 | #122-S3 (고침 #251: 없앰) |
| 4 모든 프로젝트의 모집 중, 테스트 중 모집 건 수와 신고 대기 피드백 수 | #122-S4 (고침 #251: 신고 대기 피드백 수를 테스트까지 완료한 모집 수로 바꿈) |

## 1. 전체 현황 (#122-R1)

| 동작 | API | 로그인 | 성공 |
| --- | --- | --- | --- |
| 전체 현황 | `GET /api/v1/developer/projects/dashboard` | 필요 | 200 |

```json
{
  "overview": { "recruiting": 3, "testing": 1, "closed": 2 }
}
```

- 자기 프로젝트의 모집만 센다. 프로젝트나 모집이 없으면 모두 0이다
- 취소한 모집은 현황에 세지 않는다
- `overview.recruiting`·`testing`·`closed`는 `Recruitment.phaseAt`으로 센 모집 건 수다. `closed`는 피드백 제출 마감이 지난 모집이다. 모집을 일찍 종료로 바꾸는 코드가 없어서 마감이 지난 모집만 센다 (고침 #251: `waitingReports`를 `closed`로 바꿈)
- 예전 응답의 `todos`(지원자 확정 대기, 신고 대기 피드백)는 #251에서 없앴다

#122-S1 지원자 할 일 (고침 #251: `todos`를 없애 삭제. 테스트도 지움)

#122-S2 신고 대기 피드백 (고침 #251: `todos`를 없애 삭제. 테스트도 지움)

#122-S3 순서 (고침 #251: `todos`를 없애 삭제. 테스트도 지움)

#122-S4 전체 현황 [테스트] (고침 #251: 세 번째 숫자를 신고 대기 피드백 수에서 `closed`로 바꿈)
- Then  모든 프로젝트의 모집 중, 테스트 중, 테스트까지 완료한 모집 건 수가 나온다
- Then  취소한 모집은 세지 않는다

#122-S5 내 것만 [테스트]
- Given 다른 회원의 모집과 지원자
- Then  세지 않는다
- Given 프로젝트가 없는 회원
- Then  모두 0이다
- Given 로그인하지 않았다
- Then  401이다
