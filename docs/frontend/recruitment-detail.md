# 프론트엔드 모집글 상세 (`/recruitments/:slug`)

테스터가 지원 전에 일정, 인원, 보상, 조건을 확인하는 공개 페이지다 (이슈 #63).

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`만 e2e 테스트(`frontend/e2e/recruitment-detail.spec.ts`)와 1:1이고, `[직접]`은 사람이 화면을 보고 확인한다.

## 한눈에
- 누가: 누구나. 로그인하지 않아도 볼 수 있다.
- 무엇을: 상태·구독 모집·유형 배지, 모집글 제목과 설명, 프로젝트 이미지와 소개, 모집 조건, 테스트 항목, 일정·인원·선정 방식·보상 요약, 지원 버튼
- 이번에 하지 않는 것: 지원 페이지와 제출(`/recruitments/:slug/apply`는 준비 중), 실제 API

## 모집글 상세 (#63-R1)
넓은 화면(lg 이상)은 왼쪽에 소개·조건·항목, 오른쪽에 스크롤을 따라오는 요약이 있고, 좁으면 제목 바로 아래에 요약이 온다. 접속 링크는 참여가 확정된 테스터에게만 안내하므로 보여 주지 않는다. 소개는 프로젝트 상세 설명이 있으면 그것을, 없으면 모집 건의 한 줄 소개를 쓰고, 이미지 높이까지 보이다가 "더 보기"로 펼친다. 프로젝트 이미지가 없으면 기본 이미지가 나온다.

#63-S1 모집 중 [테스트]
- Given 비로그인, `/recruitments/booklog`
- Then  제목, "모집 중", "구독 모집", 모집 마감, 피드백 제출 마감, 인원, 선정 방식, 기본 보상, 추가 보상이 보인다
- Then  모집 조건과 테스트 항목(필수·선택)이 보이고 접속 링크는 없다
- When  "지원하기"를 누른다
- Then  `/recruitments/booklog/apply`의 준비 중 화면으로 간다

#63-S2 지원할 수 없음 [테스트]
- Given 정원이 찬 모집 건(`folio-builder`), 모집이 끝난 모집 건(`memo-garden`)
- Then  "정원이 모두 찼어요" 또는 "모집이 마감됐어요"가 보이고 "지원하기"가 없다

#63-S3 상세 샘플이 없는 모집 건 [테스트]
- Given `/recruitments/moaplan`
- Then  요청 문구가 제목이 되고, 기본 이미지와 "따로 정한 조건이 없어요"가 보이며 테스트 항목은 없다
- Then  추가 보상과 "지원하기"가 있다

#63-S4 없는 모집 건 [테스트]
- Given 없는 주소, 취소가 승인된 모집 건(`folio-builder-old`)
- Then  "찾는 페이지가 없어요"가 보인다

#63-S5 배치와 로딩 [직접]
- Then  넓은 화면은 요약이 오른쪽에서 스크롤을 따라오고, 좁은 화면은 제목 아래에 있으며 가로 스크롤이 없다
- Given `demo-data=slow`
- Then  스켈레톤이 먼저 보인다

## 데이터
- `project/api.ts`의 `findPublicRecruitment(slug)`가 역할과 상관없이 모집 건, 상세, 프로젝트를 찾는다. 실제 API를 붙이면 이 함수 본문을 바꾼다.
- 모집글 제목, 조건, 테스트 항목 샘플은 북로그와 포트폴리오 빌더의 모집 건에만 있다. 나머지는 #63-S3처럼 기본 내용으로 보인다.
- PR #31의 데이터에 기대므로 #31이 먼저 머지되어야 한다.
