# 프론트엔드 참여 테스트 (`/testers/recruitments`)

백엔드: [프로젝트·테스터·피드백 백엔드](../../backend/project/README.md)

테스터가 지원하고 참여한 테스트를 한곳에서 관리하는 화면이 지켜야 하는 요구사항(R)과 시나리오(S)를 모았다. S번호는 홈(S2~S82)과 겹치지 않게 S448부터 매기고(S468·S469는 나중에 더했다. 리뷰 반영으로 더한 S470·S471는 다른 문서와 겹치지 않게 비어 있는 다음 번호를 썼다), `frontend/e2e/participations.spec.ts`(상세는 `participation-detail.spec.ts`)의 테스트 이름과 1:1로 맞는다(S467는 grep으로 확인). 상세 시나리오 S472~S481와 리뷰 반영 S482도 비어 있는 다음 번호를 썼다. 테스트를 추가하거나 바꾸면 이 문서도 함께 고친다.

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`만 e2e 테스트와 1:1이고, `[테스트: 파일 번호]`는 그 테스트가 대신 확인한다. `[명령]`은 명령 한 번, `[직접]`은 사람이 화면을 보고 확인한다. (고침 #56)

## 한눈에
- 누가: 로그인한 테스터. 비로그인은 로그인으로 보낸다.
- 무엇을: "다음에 뭘 해야 하지?"에 바로 답한다. 피드백 제출 마감, 크레딧 지급 시점, 선정 결과를 지원 순서가 아니라 급한 순서로 보여 준다.
- 화면 구성(위에서부터):
  1. 공통 헤더(홈과 같음). "참여 테스트" 탭이 현재 탭이다
  2. 페이지 제목 "참여 테스트"와 한 줄 요약(제출할 피드백 n개, 지급 대기 n크레딧)
  3. 마감 캘린더와 마감 임박 테스트: 왼쪽은 내 피드백 제출 마감을 표시한 달력, 오른쪽은 제출 전 테스트를 마감 순으로 모은 목록이다. 좁은 화면에서는 위아래로 쌓인다. 주 버튼은 목록 맨 위에만
  4. 탭 3개: 지원한 테스트 / 참여 중인 테스트 / 참여했던 테스트 (개수 표시)
  5. 선택한 탭의 참여 목록(행 카드)
  6. 상세(`/testers/recruitments/:participationKey`): 진행 상황, 피드백 작성 또는 제출한 피드백, 테스트 정보
- URL: `docs/page-urls.md`의 참여 테스트 섹션을 따른다. 탭은 `?tab=applied|ongoing|history`, 상세는 `/testers/recruitments/:participationKey`(`docs/page-urls.md`에서는 아직 후보).
- 디자인: `frontend/DESIGN.md`와 `docs/design-tokens.html`의 토큰·컴포넌트를 그대로 쓴다. 새 색이나 새 버튼 스타일을 만들지 않는다.
- 데이터: 목업이다. `demo-role`, `demo-data` 쿠키로 상태를 바꾼다(홈과 같은 장치).

## 참여 상태와 탭
README의 흐름(지원 → 참여 확정 → 테스트 → 피드백 제출 → 72시간 신고 대기 또는 운영자 검토 → 지급)을 아래 상태로 나눈다. 탭은 상태를 묶은 것이다.

| 탭 | 상태 | 화면 문구 | 행에서 보여 줄 날짜 | 행 동작 |
| --- | --- | --- | --- | --- |
| 지원한 테스트 `applied` | 선정 대기 | "선정 대기" | 모집 마감일 | 모집 글 보기 |
| | 미선정 | "미선정" | 모집 마감일 | 모집 글 보기 |
| 참여 중인 테스트 `ongoing` | 제출 전 | "피드백 제출 전" + D-day | 피드백 제출 마감일 | 피드백 쓰기 |
| | 지급 대기 | "지급 대기" | 지급 예정 일시(제출 + 72시간) | 제출 내용 보기 |
| | 운영자 검토 | "운영자 검토 중" | 제출일 | 제출 내용 보기 |
| 참여했던 테스트 `history` | 지급 완료 | "지급 완료" + 받은 크레딧 | 지급일 | 상세 보기 |
| | 미완료 | "기한 내 미제출" | 피드백 제출 마감일 | 상세 보기 |
| | 보상 제외 | "보상 제외" | 검토 완료일 | 상세 보기 |

- 무료 모집은 선착순 확정이라 지원과 동시에 "참여 중"으로 간다. "지원한 테스트"에는 구독 모집(개발자가 직접 선정)만 남는다.
- 상태 문구는 존댓말 해요체로 쓰고, 운영 용어(신고, 제재)는 행에서 직접 쓰지 않는다.

## 3. 마감 캘린더와 마감 임박 테스트 (R184)
로그인한 테스터 본인의 피드백 제출 전 참여만 다룬다. lg 이상은 왼쪽에 마감 캘린더, 오른쪽에 마감 임박 테스트를 나란히 두고, 그보다 좁으면 위아래로 쌓는다. "임박"은 기간으로 자르지 않고 제출 전 참여 전체를 마감이 가까운 순서로 보여 준다. 캘린더는 오늘이 있는 달에서 시작하고 이전·다음 버튼으로 넘긴다. 마감일 칸은 md 이상에서 서비스 이름을(같은 날이 여러 건이면 첫 이름과 "외 n건"), 그보다 좁으면 점을 보여 주고, 스크린 리더는 어느 폭에서나 이름을 읽는다. 날짜 계산은 서울 시간 기준이다. 이 화면의 주 버튼(강조색)은 목록 맨 위 항목의 버튼 하나뿐이고, 나머지는 보조 버튼이다.

S455 목록 맨 위 [직접] (고침 #46: 다음 할 일 카드를 마감 임박 목록으로 바꿈)
- Then  첫 항목에 "회의록 정리"와 "D-8"이 보이고, 주 버튼 "피드백 쓰기"가 그 참여의 상세(`/testers/recruitments/:participationKey`)를 가리킨다 (고침 #101: 역할 경로로 이동)
- Then  화면의 강조색 바탕 버튼은 이것 하나다

#46-S9 마감 임박 목록 [직접]
- Then  제목이 "마감 임박 테스트 4"이고 회의록 정리(D-8) → 중고책 장터(D-12) → 가계부 노트(D-14) → 모아플랜(D-16) 순서다
- Then  "중고책 장터 피드백 쓰기"는 보조 버튼이고 그 참여의 상세를 가리킨다

#46-S10 마감 캘린더 [직접]
- Then  이번 달 제목과 일~토 머리글이 있고, 오늘 칸이 `aria-current="date"`다
- Then  이번 달과 다음 달을 합쳐 마감일 칸에 위 4개 테스트가 "<이름> 제출 마감"으로 표시된다

#46-S11 달 넘기기 [직접]
- When  "다음 달"을 12번 누른다
- Then  매번 제목이 한 달씩 바뀌고 해가 바뀌어도 맞는다
- When  "이전 달"을 누르고 탭을 바꾼다
- Then  오늘이 없는 달에는 오늘 표시가 없고, 탭을 바꿔도 보던 달이 남는다

#46-S14 같은 날 마감 여러 건 [직접]
- Given 같은 날 마감이 2건이다
- Then  칸에 첫 이름과 "외 1건"이 보이고 그 주의 줄 높이가 다른 주와 같다
- Then  스크린 리더는 두 이름을 모두 읽는다

#46-S12 배치 [직접]
- Then  너비 1440px에서 캘린더와 목록이 같은 높이에서 시작해 나란하다
- Then  너비 375px에서는 캘린더 아래에 목록이 온다

S468~S471 없앰 (고침 #46: 카드 띠와 버튼 넘기기를 없앰)

## 4. 참여 목록 (R185)
행 카드는 활자 썸네일 → 이름·요청 문구 → 상태 → 날짜 → 보상 → 동작 순서로 고정한다. 정렬은 탭마다 하나로 정하고 바꾸는 장치는 두지 않는다.

S457 참여 중 정렬 [직접]
- Then  "참여 중인 테스트"의 행이 할 일 순서다: 제출 전(제출 마감 가까운 순) → 지급 대기 → 운영자 검토
- Then  첫 행이 "회의록 정리"다

S458 행 내용 [직접] (고침 #46: 추가 보상을 썸네일 배지로 옮김) (고침 #138: 배지를 홈 모집 카드와 같게 하고 금액은 보상 줄로 옮김)
- Then  각 행에 서비스 이름 활자 썸네일, 요청 문구(모집 글의 `request`, 예: "회의록 작성 후 할 일 목록이 맞는지 보기"), 상태 문구(위 표의 화면 문구, 예: "피드백 제출 전"), 날짜, 기본 보상이 있다
- Then  구독 모집 행에만 썸네일 왼쪽 위에 홈 모집 카드와 같은 "추가 보상" 배지가 있고, 기본 보상 옆에 "추가 보상 +320 크레딧" 같은 금액이 있다 (강조색)

S459 지급 대기 [직접]
- Then  "스터디 매칭" 행에 "지급 대기"와 지급 예정 일시가 보인다
- Then  "72시간 동안 신고가 없으면 자동으로 지급돼요" 안내가 있다

S460 지원한 테스트 [직접]
- Given `?tab=applied`
- Then  "북로그"(선정 대기), "레시피핏"(미선정) 2행이 있고, 선정 대기가 먼저다
- Then  각 행의 "모집 글 보기"가 `/recruitments/:slug`를 가리킨다

S461 참여했던 테스트 [직접]
- Given `?tab=history`
- Then  최근 순으로 3행이 있고, 맨 위에 "받은 크레딧 합계"가 지급 완료 행의 합으로 보인다
- Then  "지급 완료" 행의 썸네일에 "지급 완료" 도장(`role="img"`)이 있다

### 추가 보상 배지는 홈 모집 카드와 같다 (#138-R1)
추가 보상 배지를 홈 모집 카드와 같은 모양·자리(썸네일 왼쪽 위, 강조색 작은 배지 "추가 보상")로 맞춘다. 이전에는 "추가 보상 +n 크레딧" 큰 배지가 오른쪽 위에 있어서, 배지가 있는 행은 "지급 완료" 도장이 썸네일 가운데로 커지며 옮겨 가 행마다 도장 크기와 자리가 달랐다. 썸네일은 활자 썸네일 그대로 두고, 홈 카드의 유형 배지는 붙이지 않는다.

#138-S1 추가 보상 배지와 도장 [직접]
- Given 참여 목록(`?tab=history`), 리스트·그리드 보기
- Then  구독 모집인 "주차 알리미"에만 썸네일 왼쪽 위에 "추가 보상" 배지가 있고, 보상 줄에 "추가 보상 +300 크레딧"이 있다
- Then  "웹서비스" 같은 유형 배지는 없다
- Then  "지급 완료" 도장은 배지가 있는 행도 오른쪽 위에 다른 행과 같은 크기로 찍히고 배지와 겹치지 않는다

#138-S2 홈 모집 카드와 같은 배지 [직접]
- Then  참여 목록의 "추가 보상" 배지가 홈 "전체 테스트" 카드의 배지와 글자·색·크기가 같다
- Then  좁은 화면(390px) 리스트 보기의 썸네일(폭 192px)에서 배지와 도장이 겹치지 않고 가로로 넘치지 않는다

## 5. 빈 상태 (R186)
탭마다 빈 상태 문구가 다르고, 다음 행동 하나를 보조 버튼으로 준다.

S462 [직접]
- Given `demo-data=empty`
- Then  지원한: "지원한 테스트가 없어요", 참여 중: "참여 중인 테스트가 없어요", 참여했던: "아직 끝난 테스트가 없어요"
- Then  세 빈 상태 모두 "테스트 둘러보기"(`/recruitments`)가 있다
- Then  탭 개수는 모두 0이다

## 6. 로딩 (R187)
제목과 탭은 데이터를 기다리지 않고, 목록은 행 모양 스켈레톤을 먼저 보여 준다.

S463 [직접] (고침 #46: 마감 일정 스켈레톤을 더함)
- Given `demo-data=slow` (1.5초 지연)
- When  접속한다 (응답 시작 직후)
- Then  제목과 탭 3개가 이미 보이고 마감 일정 스켈레톤과 행 스켈레톤이 보인다

## 12-1. 피드백 이미지 (#57-R1)

## 17. 참여 상세 다시 디자인 (#230)
API는 그대로이고 상세의 구성만 바꾼다. "테스트 접속"이 작은 글씨 줄의 밑줄 링크라 눈에 띄지 않았다. 확정된 테스터가 가장 먼저 하는 일이 접속이라 제목 줄의 버튼으로 올리고, 프로젝트 정보는 표로 정리한다. 위에서 아래로 이렇게 놓는다.

1. 맨 위 "‹ 참여 중인 테스트" 돌아가기 링크
2. 제목 줄: 프로젝트 이름(h1) 옆에 상태 배지·구독 모집 배지·"마감 D-n", 오른쪽에 "모집 글"(보조)과 "테스트 열기" 버튼
3. 프로젝트 소개 한 줄(흐리게). 모집 설명은 아래 "모집 설명" 칸에만 둔다
4. 활자 썸네일 | 정보 카드: 맨 위에 접속 링크(굵은 글씨, 밑줄), 아래에 항목 표 두 줄
5. 진행 상황(제출 전에는 뺀다), 모집 설명, 테스트 항목(제출 전에는 피드백을 쓰는 칸), 제출한 피드백

페이지 좌우 여백과 폭은 다른 화면과 같은 `Container`(최대 1536px, 좌우 16px, md 이상 40px)를 따른다. 가운데 좁은 열로 모으지 않는다. 썸네일과 정보 카드는 나란히 놓일 때(md 이상) 같은 높이이고, 좁은 화면에서는 썸네일이 한 줄 폭으로 위에 온다.

- #230-R1 "테스트 열기"는 제출 전에 강조색 주 버튼이고, 제출한 뒤에는 보조 버튼이다. 새 탭으로 열고(`target="_blank"`, `rel="noopener noreferrer"`) 읽는 프로그램에는 "(새 탭)"을 덧붙인다. 접속 링크가 http(s) 주소가 아니거나 없으면(선정 대기·미선정·취소) 버튼과 링크 줄이 없다. "모집 글"은 취소된 모집에는 없다.
- #230-R2 제목 옆 "마감 D-n"은 제출 전에만 보인다. 사흘 이하는 색이 아니라 굵기(800)로 알린다.
- #230-R3 정보 표 왼쪽은 유형, 모집 방식, 테스트 항목(개수·필수 수), 지원일이고 오른쪽은 모집 마감, 제출 마감(제출 전이면 D-day), 크레딧(기본 보상), 추가 크레딧(있을 때만 강조색 글씨)이다. 진행에 따라 오른쪽에 제출일·지급 예정·지급일·검토 완료가 붙는다. 모집 방식은 선정 방식(선착순·선발형)이고, 읽지 못하면 구독 모집 여부로 보인다. 640px(40rem) 미만에서는 한 줄로 쌓는다.
- #230-R4 프로젝트 소개(제목 줄 아래)와 모집 설명("모집 설명" 칸)은 공개 모집글 API(`findPublicRecruitment`)에서 읽는다. 참여 API의 모집 정보는 모드마다 소개와 설명이 뒤바뀌어 있어(백엔드는 설명이 `summary`) 쓰지 않는다. 취소돼서 읽지 못하면 프로젝트 소개는 없고 모집 설명은 참여 API의 값을 쓴다. 비어 있으면 줄·칸을 그리지 않는다. 선정 방식도 같은 응답에서 가져온다.
- #230-R6 모집 설명은 처음에 3줄까지만 보이고, 넘치면 "더 보기"로 펼치고 "접기"로 다시 접는다. 3줄에 다 들어가면 버튼이 없다.
- #230-R7 제출 전에는 "진행 상황"을 그리지 않는다. 제목 줄의 "마감 D-n"과 정보 표의 제출 마감, 테스트 항목 안내가 같은 말이기 때문이다. 다른 단계(선정 대기, 지급 대기 등)는 다음 일을 알려 주므로 그대로 둔다.
- #230-R5 시연 데이터의 확정된 참여에도 시연용 접속 주소(`https://{모집 slug}.example.com`)를 둔다.

## 18. 피드백 이미지 실제 연결 (#57)
[#57](https://github.com/likelion-backendschool-9th/test-moa/issues/57). API, 주소, 권한은 [피드백 이미지 업로드 API](../../backend/project/feedback-images.md)를 따른다. 12-1장의 화면을 `AUTH_MODE=backend`에서 실제 저장소에 잇는다.

`[직접]`은 `AUTH_MODE=backend`로 실제 백엔드에 붙여 확인한다. `[테스트: 파일 번호]`는 그 단위 테스트가 확인한다.

### 한눈에
- 끝나면: 테스터가 칸마다 고른 이미지가 제출할 때 실제로 저장되고, 테스터는 참여 상세에서, 개발자는 피드백 탭에서 이미지를 다시 본다.
- 결정 필요: 없음
- 규모: 5단계, 약 4시간

### 정한 것
- 파일은 제출할 때 올린다. #191과 같은 이유로, 고를 때 올리면 작성을 그만둘 때마다 안 쓰는 파일이 남는다.
- 브라우저는 Next Route Handler에 파일을 보내고, 제출 서버 액션에는 주소만 넘긴다. 파일은 서버 액션을 거치지 않는다.
- 올리기 전에 브라우저에서 `parseFeedbackForm`으로 글 입력을 먼저 검사한다. 입력 오류로 돌아올 제출이 파일을 남기지 않게 한다.
- 제출한 이미지는 `<img>`로 그린다. 개발자 `FeedbackList`와 같고, 로그인 쿠키가 Route Handler에 그대로 간다.
- 목업 모드는 지금처럼 파일을 보내지 않는다. 폼은 `uploadEnabled`(`isBackendAuth`)가 참일 때만 올린다.

### 참고 (2026-11-10 확인)
- `uploadImages`는 `isUploadedImageUrl`로 응답을 검사하는데 이 함수는 공개 이미지 주소만 받는다. 피드백 주소를 그대로 넘기면 실패한다.

- 도장: `RecruitmentThumb`이 `stamp` prop을 받게 바꿨다(#78에서 모집 완료가 없어져 지금은 "지급 완료"만 쓴다). 참여 기능은 썸네일만 가져다 쓰고 `ProofStamp`를 직접 쓰지 않아서 `features/recruitment`에 그대로 두었다.

## 디자인 메모
- 강조색(One Green Rule): 마감 임박 목록 맨 위의 주 버튼, 추가 보상(목록은 썸네일 배지와 보상 줄의 금액, 상세는 줄), "지급 완료" 도장, 포커스만. 상태 배지와 D-day는 강조색을 쓰지 않는다.
- 상태 배지: `Badge`(칩 회색 알약). 급한 정도는 굵기로만 나타낸다(Weight-Not-Paint). D-3 이하는 800 굵기 먹색.
- 탭: 헤더 탭과 같은 알약 탭 모양(현재 탭은 칩 회색 바탕). 개수는 `tabular-nums`, 흐린 먹.
- 행 카드: 교정지(surface-muted) 16px 면, 안쪽 24px. 리스트의 썸네일은 폭 192px로 고정한 16:10이다. 추가 보상 배지는 왼쪽 위, 도장은 오른쪽 위라 좁은 썸네일에서도 겹치지 않는다(#138).
- 마감 일정: 교정지 면 두 칸. 마감일 칸은 강조색 없이 칩 회색 바탕에 800 굵기로, 오늘은 먹색 2px 안쪽 테두리로 나타낸다(Weight-Not-Paint). 이전·다음 달은 보조 버튼(칩 회색 알약, 아이콘만)이다.
- 접속(#230): 제목 줄의 "테스트 열기" 버튼이 제출 전에는 강조색 주 버튼이다. 제출 전에는 접속 → 제출이 이어지는 한 흐름이라 "피드백 제출"과 함께 두 개이고, 제출한 뒤에는 보조 버튼으로 내린다. 정보 카드는 교정지 면(그림자 없음, 16px 모서리)에 접속 링크를 굵게, 아래에 항목 표를 둔다.
- 상세: 썸네일은 제목과 이름이 겹쳐 보조 기술에서 숨기고, 상태는 배지 글자로 읽힌다. 테스트 정보는 모집 글에 대한 정보라 제목 바로 아래에 목록 행과 같은 모양(작은 항목 이름 + 굵은 값)으로 둔다(10-31: 오른쪽 카드는 따로 떨어져 보인다는 피드백으로 옮김). 진행 상황은 바탕 없이 제목·본문, 피드백 작성·제출한 피드백은 교정지 카드다. 피드백 칸은 프로젝트 폼과 같은 12px 모서리 입력 칸(`inputClass`)이고, 제출 버튼은 알약 주 버튼이다(금액 폼이 아니라 The Money Field Rule 대상이 아니다).
- 보기 방식: 채팅함 역할 탭(`ChatFilters`)과 같은 세그먼트 모양에 아이콘만 둔다. 이름은 `aria-label`과 마우스를 올렸을 때 뜨는 `title`로 알린다. 목록 맨 위 줄 오른쪽에 놓고, 참여했던 테스트에서는 왼쪽에 받은 크레딧 합계가 온다.
- 그림자 없음, 이징은 `--ease-brand` 하나.

## 데모 데이터와 가정
- 테스터 "한서윤"의 참여 11건은 시연용 샘플이다. 개발자·운영자 데모 계정은 참여 내역이 없다. 진행 중인 건은 홈 목업의 모집 글을 가리키고, 끝난 건은 새로 만든 지난 모집 글 3개("메모 정원", "주차 알리미", "카페 지도")를 쓴다.
  - 지원한(2): 북로그(선정 대기), 레시피핏(미선정)
  - 참여 중(6): 회의록 정리(제출 전, 제출 마감 D-8), 중고책 장터(제출 전, D-12), 가계부 노트(제출 전, D-14), 모아플랜(제출 전, D-16), 스터디 매칭(지급 대기, 지급까지 약 30시간), 동네 러닝 크루(운영자 검토 중)
  - 참여했던(3): 메모 정원(지급 완료), 주차 알리미(지급 완료), 카페 지도(기한 내 미제출)
- `demo-data=empty`는 참여 0건, `slow`는 1.5초 지연이다. `single`은 홈 전용이라 여기서는 normal로 본다.
- 모집 마감일·피드백 제출 마감일은 참여 목업에 따로 두지 않고, 가리키는 모집 글의 값을 그대로 쓴다.
- 보상 크레딧은 기획에서 미정이라 홈 목업 값을 그대로 쓴다. 미선정·미제출·보상 제외는 받은 크레딧 0이다.
- 미선정은 "지원한 테스트"에 남긴다(참여하지 않았으므로 "참여했던"이 아니다).
- 기본 탭은 할 일이 있는 "참여 중"으로 정했다.
- 스터디 매칭은 지급까지 약 30시간(제출 42시간 전)이라, 제출이 모집 글 등록보다 앞서지 않게 홈 목업의 등록일을 1일 전에서 4일 전으로 옮겼다. 홈 시나리오 결과는 바뀌지 않는다.
- 피드백 글자 수는 기획에서 미정이라 칸마다 500자까지로 정했다. 최소 글자 수는 없다. 시연용 저장은 쿠키 하나(4,000바이트)라, 모든 칸을 합쳐 한글 약 900자가 넘으면 저장하지 못하고 안내한다.
- 참여 샘플의 테스트 항목은 `participation/mock.ts`에 따로 둔다. 모집 글 상세의 항목 샘플과는 연결되어 있지 않다.
- 샘플 중 지급 대기·운영자 검토 중·지급 완료 4건에는 시연용 피드백 원문을 넣었다. "보상 제외" 샘플은 없어서 그 상태의 상세는 E2E로 확인하지 않는다.
- D-3 이하가 아니면 D-day는 600 굵기 흐린 먹이다. 끝난 상태(미선정, 기한 내 미제출, 보상 제외) 배지는 흐린 배지(`Badge tone="muted"`)다.
