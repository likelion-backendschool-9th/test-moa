# 프론트엔드 운영자 구독 관리 (`/admin/subscriptions`)

운영자가 시연·확인용으로 회원에게 구독을 주고 빼는 페이지의 요구사항과 시나리오다. 이슈: [#204](https://github.com/likelion-backendschool-9th/test-moa/issues/204). 요구·시나리오는 `#204-R…`, `#204-S…`로 센다(`#204-S1`~`S10`은 백엔드 [admin-subscription.md](../../backend/payment/admin-subscription.md), 이 문서는 `#204-S11`부터, 구독 결제 연결은 [subscription.md](../payment/subscription.md)의 `#204-S17`부터다).

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`만 e2e 테스트와 1:1이고, `[테스트: 파일 번호]`는 그 테스트가 대신 확인한다. `[직접]`은 사람이 화면을 보고 확인한다.

## 한눈에
- 목적: 운영자가 회원의 **이메일**로 그 회원의 구독 상태를 보고, **결제 없이** 구독을 주거나 뺀다. 데모와 확인용 계정을 만드는 도구다. 결제 이력·크레딧에는 남지 않는다.
- 스택: 홈과 같다. 실행 방법은 `frontend/README.md`를 본다.
- 화면 구성: 운영자 하위 탭에 "구독"을 더한다(홈·회원·신고·제재·출금 요청·**구독**). 이메일 검색창 → 찾은 회원의 닉네임·이메일·구독 상태 → "구독 주기"·"구독 빼기" 버튼.
- 데이터: **백엔드 모드(`AUTH_MODE=backend`)에서만 동작한다.** 구독을 주고 빼는 일은 서버에 있는 회원의 상태를 바꾸는 것이라 목업으로 흉내 낼 대상이 없다. 목업 모드에서는 "백엔드와 연결했을 때 쓸 수 있어요"라는 안내만 보인다.
- 백엔드: [admin-subscription.md](../../backend/payment/admin-subscription.md) — `GET`·`POST`·`DELETE /api/v1/admin/subscriptions`
- 디자인: 신고·제재 관리와 같은 토큰과 `components/ui`만 쓴다. 되돌리기 어려운 동작은 아니지만 회원의 구독이 바뀌므로, 두 버튼 모두 결과를 화면에 알린다. 주 버튼은 "구독 주기" 하나다(강조색 바탕).
- 페이지 URL: `docs/page-urls.md`

이 아래 시나리오는 따로 적지 않으면 `demo-role=admin`이고 백엔드 모드다.

## 1. 접근 권한 (#204-R1)
운영자에게만 보인다. 규칙은 운영자 홈 R15와 같다.

#204-S11 일반 회원·비로그인 [테스트: pages.spec.ts #56-S2, #56-S3]
- Given 비로그인, 또는 일반 회원
- When  `/admin/subscriptions`에 접속한다
- Then  비로그인은 로그인으로 가고, 일반 회원은 접근할 수 없다는 화면이 보인다(다른 운영자 페이지와 같다)

## 2. 목업 모드 안내 (#204-R2)

#204-S12 목업 모드에서는 안내만 보인다 [테스트]
- Given `demo-role=admin`이고 백엔드 모드가 아니다
- When  `/admin/subscriptions`에 접속한다
- Then  "백엔드와 연결했을 때 쓸 수 있어요"가 보이고 이메일 검색창과 구독 버튼은 없다

## 3. 회원 찾기 (#204-R3)
검색창에 이메일을 넣으면 `?email=` 주소로 이동해 서버가 회원과 구독 상태를 읽는다. 주소를 그대로 열어도 같은 결과가 보인다.

#204-S13 이메일로 회원의 구독 상태를 본다 [직접]
- Given 구독 중인 회원과 구독하지 않은 회원
- When  각 이메일로 검색한다
- Then  닉네임·이메일과 구독 상태가 보인다. 구독 중이면 "구독 중", 이용 중인 상품(플랜 이름), 만료일, 남은 날이 보이고 "구독 주기"·"구독 빼기"가 있다. 구독하지 않았으면 "구독하지 않았어요"와 "구독 주기"가 있고 "구독 빼기"는 없다

#204-S14 없는 이메일 [직접]
- When  가입하지 않은 이메일로 검색한다
- Then  "찾을 수 없어요"가 보이고 버튼은 없다

#204-S15 운영자 계정 [직접]
- When  운영자 회원의 이메일로 검색한다
- Then  "운영자 계정은 구독 대상이 아니에요"가 보이고 "구독 주기"·"구독 빼기"는 없다

## 4. 구독 주기·빼기 (#204-R4)

#204-S16 구독을 주고 뺀다 [직접]
- Given 구독하지 않은 회원을 찾았다
- When  "구독 주기"를 누른다(플랜은 지금 파는 플랜 하나)
- Then  "구독했어요"라는 결과 안내가 보이고 구독 상태가 구독 중(만료일 오늘 + 플랜 기간)으로 바뀐다. 그 회원으로 로그인하면 `/my/subscription`에 구독 중으로 나온다
- When  "구독 빼기"를 누른다
- Then  "구독을 뺐어요" 안내가 보이고 상태가 "구독하지 않았어요"로 바뀐다
- 서버가 거절하면(운영자 계정, 지금 파는 플랜 없음 등) 서버의 이유가 화면에 보인다

## 범위 밖
- 회원 목록·검색(이메일로만 찾는다), 부여 이력, 플랜 가격·기간 바꾸기
- 결제·환불 처리. 구독 부여는 결제 이력과 크레딧 내역에 나오지 않는다
- 목업 모드에서의 부여·해제 흉내

## 작업 순서
1. 문서(이 문서와 백엔드 문서)
2. 백엔드 API(S1~S10)
3. 구독 결제 연결(subscription.md `#204-S17`~)
4. 운영자 화면: `features/subscription/admin.ts`(읽기·쓰기), `/admin/subscriptions` 페이지, `ADMIN_NAV`에 "구독", `e2e/pages.ts`에 `["/admin/subscriptions", "admin"]`, `page-urls.md`

## 가정
- 이메일 검색은 `?email=`이라 브라우저 기록에 이메일이 남는다. 운영자 전용 시연 도구라 감수한다.
- 구독 주기 버튼은 지금 파는 플랜을 한 개로 본다. 플랜이 여러 개가 되면 선택 칸을 더한다.
