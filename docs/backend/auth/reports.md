# 회원 신고·증거 첨부 (#85)

회원이 모집 글·회원·채팅방을 사유와 증거 파일로 신고하는 API(1차)와, 운영자 판정·피드백 신고 연결·내 신고 목록(2차). 여러 이슈에 걸친 결정은 [README.md](README.md).

## 정한 것

- 신고는 `reports` 한 테이블로 피드백·모집 글·회원·채팅을 함께 쓴다. `target_type`(`FEEDBACK`·`RECRUITMENT`·`USER`·`CHAT`)과 `target_id`로 대상을 구분한다(팀 ERD 11-09)
- ERD 칸과 코드: `reports.user_id` = 신고한 회원, `reported_user_id` = 신고당한 회원(서버가 대상에서 찾는다), `reviewer_id` = 판정한 운영자(2차). 상태는 `PENDING`·`REJECTED`·`ACCEPTED`
- 채팅은 밖으로 방 id 대신 `roomKey`를 쓰므로, 신고 요청은 `roomKey`를 받고 `target_id`에는 방 id를 저장한다
- 신고당한 회원: 모집 글은 그 모집의 프로젝트 주인, 회원은 그 회원, 채팅은 그 방의 상대 참여자
- 피드백 신고는 이미 있는 피드백 신고 API(`POST /api/v1/developer/feedbacks/{id}/report`, #175)가 받는다. 2차에서 그 API가 `reports` 행도 만들게 연결하고, 이 API에서는 `FEEDBACK`을 받지 않는다
- 증거 파일은 서버 디스크(`UPLOAD_DIR`, 컨테이너 `/app/uploads`, 볼륨 `upload-data`)에 무작위 이름으로 저장하고, `report_evidences`에는 경로·원래 이름·종류·크기만 둔다. 공개 주소가 없고 API로만 연다
- 파일 종류는 확장자가 아니라 파일 앞부분(시그니처)으로 PNG·JPG·WEBP·PDF인지 본다
- 파일 저장 코드(`global/file/FileStorage`)는 공용이다. 프로필 이미지(#84) 등도 같은 코드를 쓴다
- 개발 모드(root로 실행)와 운영 이미지는 DB(`db-data`)와 업로드 볼륨(`upload-data`)을 함께 쓴다. 운영 이미지는 켜질 때만 root로 업로드 폴더의 주인을 app으로 맞추고, 앱은 `setpriv`로 권한을 내려 app 사용자로 실행한다. 그래서 어느 모드에서 만든 신고든 다른 모드에서 증거를 열 수 있다
- 업로드 한도: 한 장 5MB, 한 번에 최대 5장(요청 30MB). Spring `max-file-size 5MB`·`max-request-size 30MB`, nginx `client_max_body_size 30m`. 프론트(Next) 연결 때 `serverActions.bodySizeLimit`도 맞춘다

## API

- `POST /api/v1/reports` (multipart): `targetType`, `targetId`(채팅이 아니면), `roomKey`(채팅이면), `reason`, `files`(0~5개). 201과 신고 한 건
- `GET /api/v1/reports/{reportId}/evidences/{evidenceId}`: 증거 파일. 신고한 본인과 운영자만

## 시나리오

#85-S1 회원이 모집 글·회원·채팅방을 사유와 증거 파일로 신고한다 [테스트]
- Given 로그인한 회원
- When  `POST /api/v1/reports`로 대상과 사유, PNG·PDF 증거를 보낸다
- Then  201이고 상태는 `PENDING`, 증거 목록(원래 이름·종류·크기)이 온다
- Then  신고당한 회원은 모집 글이면 프로젝트 주인, 회원이면 그 회원, 채팅이면 방의 상대다
- 증거 없이 사유만 보내도 된다

#85-S2 자기 자신, 자기 모집 글은 신고할 수 없다 [테스트]
- 400 `REPORT_SELF`("자기 자신은 신고할 수 없어요")

#85-S3 같은 회원이 검토 대기 중인 같은 대상을 또 신고하면 409 `REPORT_DUPLICATED` [테스트]
- 판정이 끝난 뒤에는 다시 신고할 수 있다(2차에서 확인)

#85-S4 없는 대상, 참여하지 않은 채팅방은 404 [테스트]

#85-S5 증거 파일 규칙에 맞지 않으면 400이고 신고를 만들지 않는다 [테스트]
- 5MB를 넘는 파일의 413은 테스트 도구(MockMvc)가 업로드 한도를 거치지 않아 실제 서버(`bootRun`)에서 확인한다
- PNG·JPG·WEBP·PDF가 아니면(확장자를 바꾼 파일 포함) "PNG·JPG·WEBP·PDF 파일만 올릴 수 있어요", 6장 이상이면 "증거 파일은 5장까지 올릴 수 있어요", 한 장이 5MB를 넘으면 "파일은 한 장 5MB까지 올릴 수 있어요"(실제 서버는 업로드 단계에서 413, 그 뒤 서비스 검사는 400)
- 사유가 비면 400(칸 `reason`), 대상 종류가 `FEEDBACK`이면 400("피드백 신고는 피드백 화면에서 해 주세요")

#85-S6 증거 파일은 신고한 본인과 운영자만 열 수 있다 [테스트]
- 다른 회원은 404(있는지도 알리지 않는다), 로그인하지 않으면 401
- 응답의 종류는 저장한 `content_type`이다

#85-S7 같은 회원이 같은 대상을 동시에 두 번 신고해도 하나만 저장되고 나머지는 409 [테스트]
- 신고자 회원 행을 잠가(`select ... for update`) 중복 확인과 저장을 한 번에 하나씩 처리한다

#85-S8 신고가 최종 롤백되면 저장한 증거 파일도 남지 않는다 [테스트]
- 저장한 파일은 트랜잭션 완료 콜백에 묶여, 커밋되지 않으면(메서드 안의 예외, 커밋 실패, 바깥 트랜잭션 롤백) 지운다. 복사 도중 실패한 파일은 저장 함수가 바로 지운다

## 2차: 운영자 판정, 피드백 신고 연결, 내 신고 목록

- API
  - `GET /api/v1/admin/reports?status=PENDING|DONE&targetType=`: 운영자 신고 목록. 검토 대기는 오래된 순, 처리 완료는 최근 처리 순
  - `GET /api/v1/admin/reports/{id}`: 운영자 신고 상세(대상 내용, 증거, 처리 결과)
  - `POST /api/v1/admin/reports/{id}/review` `{result: REJECTED|ACCEPTED}`: 판정. 한 번만
  - `GET /api/v1/reports/me`: 내 신고 목록, 최신순
- 운영자 화면의 이름은 가운데를 가린다(`Masking.name`, 이재용 → 이*용, #86 시나리오 1). 닉네임과 회원 id는 그대로 준다
- 피드백 신고: 피드백 신고 API(`POST /api/v1/developer/feedbacks/{id}/report`)가 `feedback.report()`와 함께 `reports` 행(FEEDBACK)을 만든다. 신고당한 회원은 그 피드백을 쓴 테스터다
- 피드백 신고 판정: 기각하면 `feedback.dismissReport()`로 제출(`SUBMITTED`)로 되돌리고, 인정하면 `feedback.exclude()`를 부른다
  - 처음에는 기각하면 `reward()`(`REWARDED`)로 했다. 지급 기록을 남기는 코드가 아직 없어서, 승인 대기에서도 잔액에서도 보상이 사라졌다(#208 리뷰)
  - 제출로 되돌리면 승인 대기에 다시 잡히고, 실제 지급은 지급 담당의 72시간 자동 지급이 한다
  - 기각된 피드백은 같은 개발자가 다시 신고할 수 없다(409 `FEEDBACK_REPORT_DISMISSED`). 다시 신고해 지급을 또 멈추지 못하게 한다
  - 인정해서 보상 제외(`EXCLUDED`)된 칸이 있으면, 함께 낸 다른 칸이 제출 상태여도 그 참가는 승인 대기에서 빠진다(신고된 칸과 같은 규칙)
- 판정은 신고 행을 잠그고(`select ... for update`) 처리해서 두 운영자가 동시에 판정해도 하나만 된다

#85-S9 운영자가 검토 대기·처리 완료 신고 목록을 대상 종류로 걸러 본다 [테스트]
- 검토 대기는 신고가 오래된 순, 처리 완료는 처리가 최근인 순이다
- 각 행에 대상 종류, 모집 건 이름(피드백·모집 글·채팅), 사유, 신고 일시, 처리 결과·일시, 신고자·신고당한 회원(닉네임과 가린 이름)이 있다

#85-S10 운영자가 신고 상세에서 대상 내용과 증거를 본다 [테스트]
- 피드백은 원문, 모집 글은 제목, 채팅은 방(`roomKey`)과 모집 건 이름, 회원은 닉네임. 없는 신고는 404

#85-S11 운영자가 신고를 기각하거나 인정하고, 판정은 한 번만 할 수 있다 [테스트]
- 200이고 상태·처리 일시·판정한 운영자가 남는다. 이미 판정한 신고는 409 `REPORT_ALREADY_REVIEWED`

#85-S12 피드백 신고 API로 신고하면 FEEDBACK 신고가 생기고, 기각하면 피드백은 `SUBMITTED`, 인정하면 `EXCLUDED`가 된다 [테스트]

#85-S13 판정이 끝난 대상은 같은 회원이 다시 신고할 수 있다 [테스트]

#85-S14 회원이 내 신고 목록에서 내가 한 신고와 처리 상태를 본다 [테스트]
- 최신순. 신고당한 회원·판정한 운영자·제재는 보이지 않고, 다른 회원의 신고는 없다

#85-S15 운영자 신고 API는 운영자만 쓸 수 있다 [테스트]
- 일반 회원 403, 로그인하지 않으면 401

#85-S16 두 운영자가 같은 신고를 동시에 판정해도 하나만 된다 [테스트]

#85-S17 피드백 신고를 기각하면 그 참가의 보상이 승인 대기에 다시 잡힌다 [테스트]
- 신고 중에는 승인 대기 0, 기각 뒤 크레딧 잔액 API(`GET /api/v1/my/credits`)의 `pendingReward`가 보상액(1,000)이다

#85-S18 기각된 피드백은 다시 신고할 수 없다 [테스트]
- 같은 피드백을 다시 신고하면 409 `FEEDBACK_REPORT_DISMISSED`

#85-S19 한 번에 낸 칸 중 하나를 인정하면 그 참가는 승인 대기에서 빠진다 [테스트]
- 칸 2개를 내고 1개가 인정되면(`EXCLUDED`), 남은 칸이 `SUBMITTED`여도 승인 대기 0
