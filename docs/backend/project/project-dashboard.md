# 내 프로젝트 할 일·전체 현황 API (#122)

내 프로젝트 목록 위의 "지금 확인할 일"과 "전체 현황"이 쓰는 API. 화면 규칙은 [프로젝트 화면 S522·S523](../../frontend/project/projects.md)이고, 도메인 전체에서 정한 것은 [README.md](README.md)에 있다.

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`는 백엔드 테스트와 1:1이다(`@DisplayName("#122-S…")`).

## 이슈 #122 확인

| 이슈 항목 | 시나리오 |
| --- | --- |
| 1 확정을 기다리는 지원자 수를 모집 건별로. 구독 모집이고 모집 마감 전인 것만 | #122-S1 |
| 2 72시간이 지나지 않은 신고 대기 피드백 수와 자동 지급까지 남은 시간을 모집 건별로 | #122-S2 |
| 3 지원자 항목이 먼저, 피드백 항목은 자동 지급이 가까운 순서 | #122-S3 |
| 4 모든 프로젝트의 모집 중, 테스트 중 모집 건 수와 신고 대기 피드백 수 | #122-S4 |

## 1. 할 일과 전체 현황 (#122-R1)

| 동작 | API | 로그인 | 성공 |
| --- | --- | --- | --- |
| 할 일·전체 현황 | `GET /api/v1/developer/projects/dashboard` | 필요 | 200 |

```json
{
  "todos": [
    { "kind": "applicants", "recruitmentId": 3, "projectName": "북로그", "count": 8, "payoutAt": null },
    { "kind": "feedback", "recruitmentId": 5, "projectName": "메모", "count": 2, "payoutAt": "2026-11-12T03:00:00Z" }
  ],
  "overview": { "recruiting": 3, "testing": 1, "waitingReports": 2 }
}
```

- 자기 프로젝트의 모집만 센다. 프로젝트나 모집이 없으면 빈 목록과 0이다
- 취소한 모집은 할 일에도 현황에도 세지 않는다
- `applicants`: 구독 모집이고 모집 중(모집 마감 전)이며 대기(`APPLIED`) 지원자가 있는 모집 건. `count`는 대기 지원자 수다
- `feedback`: 제출 상태(`SUBMITTED`)이고 제출 후 72시간이 지나지 않은 피드백이 있는 모집 건. `count`는 그 피드백 수이고 `payoutAt`은 가장 먼저 낸 피드백의 제출 시각 + 72시간이다
- 순서: 지원자 항목이 먼저 모집 최신순으로 오고, 피드백 항목은 `payoutAt`이 가까운 순서다
- `overview.recruiting`·`testing`은 `Recruitment.phaseAt`으로 센 모집 건 수이고, `waitingReports`는 `feedback` 항목의 `count` 합이다
- 피드백은 항목별 행이라 항목을 3개 낸 참가는 3건으로 센다. 프로젝트 상세의 피드백 수와 같은 기준이다
- 문구와 남은 시간 계산은 프론트가 한다. 이동할 탭 주소는 `recruitmentId`로 만든다
- 자동 지급이 아직 없어서 72시간이 지난 피드백은 제출 상태로 남지만 여기서는 세지 않는다

#122-S1 지원자 할 일 [테스트]
- Given 구독 모집에 대기 지원자 2명, 확정 1명이 있다
- Then  `applicants` 항목의 `count`가 2다
- Given 무료 모집의 대기 지원자, 모집 마감이 지난 구독 모집의 대기 지원자, 대기 지원자가 없는 구독 모집, 취소한 구독 모집
- Then  항목에 없다

#122-S2 신고 대기 피드백 [테스트]
- Given 72시간이 지나지 않은 제출 상태 피드백 2건이 있다
- Then  `feedback` 항목의 `count`가 2이고 `payoutAt`은 먼저 낸 피드백의 제출 시각 + 72시간이다
- Given 신고된 피드백, 72시간이 지난 피드백, 취소한 모집의 피드백
- Then  세지 않는다

#122-S3 순서 [테스트]
- Then  지원자 항목이 먼저 오고, 피드백 항목은 `payoutAt`이 가까운 순서다

#122-S4 전체 현황 [테스트]
- Then  모든 프로젝트의 모집 중, 테스트 중 모집 건 수와 신고 대기 피드백 수가 나온다
- Then  종료·취소한 모집은 모집 건 수에 없다

#122-S5 내 것만 [테스트]
- Given 다른 회원의 모집과 지원자
- Then  세지 않는다
- Given 프로젝트가 없는 회원
- Then  빈 목록과 0이다
- Given 로그인하지 않았다
- Then  401이다
