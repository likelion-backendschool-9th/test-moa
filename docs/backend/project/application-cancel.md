# 지원 취소 API (#286)

테스터가 자기 참가(`registers`)를 직접 취소하는 API. 지금은 잘못 지원하면 되돌릴 방법이 없고, 선착순은 지원과 동시에 확정되어 실수로 누르면 바로 참가자가 된다. 도메인 전체에서 정한 것은 [README.md](README.md), 참가 엔티티 규칙은 [entities.md 3](entities.md#3-지원과-참가-89-r3)에 있다. 화면은 [참여 테스트 19](../../frontend/project/participations.md#19-지원-취소-286)에 있다.

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`는 백엔드 테스트와 1:1이다(`@DisplayName("#286-S…")`).

## 이슈 #286 확인

| 이슈 항목 | 시나리오 |
| --- | --- |
| 1·2 대기 중인 지원을 취소하면 참여 취소가 되고 지원자 목록에도 반영 | #286-S1, #286-S2 |
| 3 확정된 참가도 피드백 전·테스트 시작 전이면 취소 | #286-S2 |
| 4 피드백을 냈거나 테스트가 시작된 뒤에는 취소할 수 없음 | #286-S3, #286-S6 |
| 5 취소한 뒤 모집 중이면 다시 지원 | #286-S5 |

## 1. 지원 취소 (#286-R1)

| 동작 | API | 로그인 | 성공 |
| --- | --- | --- | --- |
| 지원 취소 | `POST /api/v1/tester/participations/{registerId}/cancel` | 필요 | 200 |

본문은 없다. 응답은 내 참여 상세(`ParticipationResponse`)와 같은 모양이고 `status`가 `cancelled`다.

- 취소할 수 있는 참가: 대기(`APPLIED`)·확정(`CONFIRMED`)이고, 모집이 모집 중(`RecruitmentPhase.RECRUITING`, 모집 마감 전)이며, 피드백을 내지 않았다. 선착순·선발형이 같다(가정 1)
- 선착순은 모집 중에도 피드백을 낼 수 있어서 모집 중인지만으로는 부족하다. 피드백이 있으면 막는다
- 취소하면 `Register.cancel(now)`로 `CANCELLED`가 되고 `cancelled_at`에 취소 시각을 남긴다. 보상 스냅샷은 지우지 않는다(취소된 참가는 보상 합산에서 빠진다)
- 내 참여 목록에서 참여 취소의 날짜(`keyDate`)는 참가의 취소 시각이다. 예전 행처럼 없으면 모집 취소 시각, 그것도 없으면 지원 시각이다
- 다시 지원: 지원 API는 `CANCELLED`만 남은 회원의 재지원을 이미 허용한다([test-apply.md](test-apply.md) 가정 1). 새 참가가 생긴다
- 동시 요청: 지원·확정·모집 취소와 같은 순서로 모집글 행을 먼저 잠그고(`findForApplyById`) 참가 행을 잠근다(`findMineForUpdate`). 피드백 제출도 참가 행을 잠가 둘 중 하나만 된다
- 채팅방: 확정 때 만든 채팅방은 그대로 둔다. 모집 취소(#116)도 채팅방을 건드리지 않는다(가정 2)

| 상황 | 상태 | `error.code` |
| --- | --- | --- |
| 로그인하지 않음 | 401 | `UNAUTHORIZED` |
| 없는 참가, 다른 회원의 참가 | 404 | `NOT_FOUND` |
| 테스트가 시작됨, 피드백을 냄, 거절·취소된 참가 | 409 | `PARTICIPATION_NOT_CANCELLABLE` ("모집 기간에 피드백을 내기 전에만 지원을 취소할 수 있어요") |

#286-S1 선정 대기인 지원을 취소한다 [테스트]
- Given 선발형 모집 중인 모집에 대기 중인 참가
- When  테스터가 취소한다
- Then  200이고 `status` `cancelled`, 접속 링크는 없다
- Then  참가가 `CANCELLED`이고 `cancelled_at`이 저장된다
- Then  참여했던 탭에 "참여 취소"로 보이고, 행의 날짜는 지원일이 아니라 취소일이다

#286-S2 확정된 참가도 테스트 시작 전이고 피드백을 내기 전이면 취소한다 [테스트]
- Given 선착순·선발형 각각 모집 중인 모집에 확정된 참가
- When  테스터가 취소한다
- Then  200 `cancelled`이고, 개발자의 지원자 목록에 `cancelled`로 보인다

#286-S3 테스트가 시작됐거나 피드백을 냈거나 끝난 참가는 취소할 수 없다 [테스트]
- Given 모집 마감이 지난(테스트 중) 확정 참가, 모집 중이지만 피드백을 낸 선착순 참가, 거절된 참가, 이미 취소된 참가
- Then  모두 409 `PARTICIPATION_NOT_CANCELLABLE`이고 상태가 그대로다

#286-S4 다른 회원의 참가와 비로그인 [테스트]
- Then  다른 회원의 참가는 404, 비로그인은 401이고 상태가 그대로다

#286-S5 취소한 뒤 모집 중이면 다시 지원한다 [테스트]
- Given 선착순 모집의 확정 참가를 취소했다
- When  같은 모집에 다시 지원한다
- Then  201 `confirmed`이고, 공개 모집글의 `myRegisterStatus`가 `confirmed`다

#286-S6 지원 취소와 피드백 제출이 동시에 [테스트]
- Given 모집 중인 선착순 모집의 확정 참가
- When  같은 테스터가 지원 취소와 피드백 제출을 동시에 보낸다(20번)
- Then  제출이 먼저면 취소는 409이고 참가는 확정, 피드백 1건이다
- Then  취소가 먼저면 제출은 409이고 참가는 취소, 피드백은 없다

## 범위 밖
- 운영자의 강제 취소
- 취소한 참가의 채팅방 정리(가정 2)
- 개발자에게 취소 알림 보내기

## 가정
1. 선발형에서 확정된 참가도 테스트 시작 전이면 취소할 수 있다. 개발자가 고른 테스터가 빠지는 것이지만, 모집 기간 안이라 다른 지원자를 확정할 수 있다. 팀 의견이 다르면 선발형 확정 참가만 막는다
2. 채팅방은 모집 취소와 같이 그대로 둔다. 확정이 취소된 테스터가 채팅을 계속 쓸지는 채팅 담당과 정한다
