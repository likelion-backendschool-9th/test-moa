# 프론트엔드 구독 소개 (`/subscription`)

누구나 무료와 구독을 나란히 보고 구독 결제로 넘어가는 공개 페이지다 (이슈 #76). 로그인한 회원의 내 구독 관리는 `docs/frontend/payment/subscription.md`(`/my/subscription`)에 있다.

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`만 e2e 테스트(`frontend/e2e/subscription-intro.spec.ts`)와 1:1이고, `[테스트: 파일 번호]`는 그 테스트가 대신 확인한다. `[직접]`은 사람이 화면을 보고 확인한다. 로그인 이동과 운영자 권한(S4·S7)만 E2E에 남기고, 문구·개수·배치(S2·S5·S6·S8·S9)는 `[직접]`이다(`frontend/README.md` 검증을 나누는 기준).

## 한눈에
- 끝나면: 로그인하지 않아도 `/subscription`에서 FREE와 PRO 두 카드(이름, 가격, 한 줄 설명, 혜택)를 보고, "구독하기"로 구독 결제(`/my/subscription/checkout`)에 간다. 헤더에 "구독" 탭이 생기고, 곳곳의 "구독 알아보기"가 이 페이지로 온다.
- 누가: 누구나. 버튼만 역할에 따라 다르다(비로그인 → 로그인 후 결제, 회원 → 결제, 구독 중 → 연장, 운영자 → 안내).
- 함께 바꾸는 것: `/my/subscription`에서 혜택 비교 표와 "이번 달 모집 인원"을 빼고, 결제 안내에 이 페이지로 오는 "혜택 보기"를 둔다(아래 6장). 상품 이름은 "구독"에서 "PRO"로 바꾼다
- 이번에 하지 않는 것: 실제 결제와 백엔드 연동(#69, #70), 상품 추가, 결제 화면 변경(상품 이름만 따라 바뀜)
- 결정 필요: 없음 (11-05 확정: 주소 `/subscription`, 버튼은 로그인 후 결제, 운영자는 A안, 헤더 탭은 "운영자 페이지" 왼쪽)
- 규모: 4단계, 약 2~3시간

## 맥락
- 지금 구독 혜택은 로그인해야 보이는 `/my/subscription`에만 있어서, 가입 전에는 구독이 무엇인지 알 수 없다.
- 가격과 혜택은 `/my/subscription`과 **같은 데이터**를 쓴다. 목업에서는 `demo/subscription.ts`의 무료 플랜과 구독 상품 목록이고, `AUTH_MODE=backend`에서는 서버 값이다(아래 7장, 고침 #203). 값을 따로 적지 않아서 한쪽만 바뀌는 일이 없다.
- 상품은 지금 하나(PRO, 30일 10,000원·9,000 크레딧)이고, 화면은 상품 목록을 그린다(`subscription.md` S398과 같은 원칙).
- 운영자는 구독 대상이 아니다. 문구는 `/my/subscription`(S386)과 결제(S535)의 "운영자 계정은 구독 대상이 아니에요"를 그대로 쓴다.
- 화면 참고: FREE와 PRO 카드를 나란히 두고 유료 카드를 강조하는 요금제 소개 페이지. FREE 카드에는 버튼을 두지 않는다.

## 1. 두 카드 (#76-R1)
페이지 제목과 짧은 소개 아래에 FREE와 PRO 카드를 나란히 둔다. 카드는 요금제 소개처럼 이름(크게) → 한 줄 설명 → 가격 → 체크 혜택 목록 → (구독만) 맨 아래 주 버튼 순서다. PRO 카드는 가격·혜택 굵기, 주 버튼(구독하기), 강조색 2px 테두리로 강조한다(고침 #76: 테두리를 다시 넣기로 해 DESIGN.md One Green Rule에 이 한 곳을 더함). 혜택은 서버가 준 문구 목록 그대로이고(고침 #203: 프론트가 "없음"·"일반 목록"을 거르던 것을 없앰. 보일 문구만 서버가 준다), 월간 모집 인원은 백엔드에서 없어져 카드와 비교표 어디에도 없다. 혜택 비교 표는 두지 않는다(고침 #76: 백엔드 혜택 목록으로는 행을 맞출 수 없어 뺌). 좁은 화면(768px 미만)에서는 PRO 카드가 위로 오게 세로로 쌓는다.

#76-S1 비로그인 두 카드 [직접]
- Given `demo-role=guest`, `/subscription`
- Then  h1과 짧은 소개가 보이고, "FREE"와 "PRO" 카드가 나란히 있다
- Then  FREE 카드에 가격 자리에 "무료"(숫자 "0원"이 아님), PRO 카드에 "30일 10,000원"과 "9,000 크레딧"이 보인다
- Then  PRO 카드에만 "구독하기"와 강조색 테두리가 있고, "추천" 배지는 없다. FREE 카드에는 버튼과 강조 테두리가 없다 `(고침 #76: 강조 테두리를 넣기로 함)`

#76-S2 혜택은 카드의 목록으로 보인다 [직접]
- Given `demo-role=guest`, `/subscription`
- Then  FREE 카드 혜택에 "선착순 자동 확정", "기본 보상"이 있고 "없음"·"1대1 채팅"·"일반 목록"은 없다
- Then  PRO 카드 혜택에 "지원자 중 직접 선정", "기본 + 추가 보상", "선정한 테스터와 가능", "상단 구독 영역", "피드백 AI 정리 및 분석"이 있다
- Then  "혜택 비교" 표는 없다. 혜택 항목은 카드의 목록이 전부다(고침 #203: 백엔드 `benefits` 목록을 그대로 보여 준다. 목업 모드에서는 목업 값) `(고침 #76: 비교표를 뺌)`
- Then  PRO 카드 가격이 결제 안내(S390)의 현금·크레딧 가격과 같다

#76-S3 좁은 화면 [직접]
- Given 너비 375px
- Then  PRO 카드가 위, FREE 카드가 아래로 쌓이고 가로 넘침이 없다 (넘침 자체는 `[테스트: pages.spec.ts #56-S1]`)

## 2. 구독 버튼 (#76-R2)
PRO 카드의 버튼은 역할과 구독 상태에 따라 갈 곳과 문구가 다르다.

| 누가 | PRO 카드 | 버튼 |
| --- | --- | --- |
| 비로그인 | — | "구독하기" → `/login?next=%2Fmy%2Fsubscription%2Fcheckout` |
| 회원(미구독) | — | "구독하기" → `/my/subscription/checkout` |
| 회원(구독 중) | "이용 중" 배지 | "구독 연장하기" → `/my/subscription/checkout` |
| 운영자 | — | 버튼 대신 "운영자 계정은 구독 대상이 아니에요" |

#76-S4 비로그인은 로그인 뒤 결제로 [테스트]
- Given `demo-role=guest`, `/subscription`
- When  "구독하기"를 누른다
- Then  URL이 `/login?next=%2Fmy%2Fsubscription%2Fcheckout`이다
- When  테스터로 로그인한다
- Then  URL이 `/my/subscription/checkout`이다

#76-S5 회원은 바로 결제로 [직접]
- Given `demo-role=tester`(미구독), `/subscription`
- Then  "구독하기"가 `/my/subscription/checkout`을 가리키고, "이용 중"은 없다

#76-S6 구독 중이면 연장 [직접]
- Given `demo-role=developer`(구독 중), `/subscription`
- Then  PRO 카드에 "이용 중"이 있고 버튼은 "구독 연장하기"(`/my/subscription/checkout`)다
- Then  "구독하기"는 없다

#76-S7 운영자 [테스트]
- Given `demo-role=admin`, `/subscription`
- Then  두 카드와 혜택이 보인다
- Then  "운영자 계정은 구독 대상이 아니에요"가 보이고 "구독하기"·"구독 연장하기"가 없다

## 3. 헤더 "구독" 탭 (#76-R3)
헤더 "주요 메뉴"에 "구독"(`/subscription`) 탭을 "채팅" 다음, "운영자 페이지" 앞에 둔다. 공개 페이지라 비로그인도 로그인으로 보내지 않는다. `/my/subscription`에서는 이 탭이 현재 탭이 아니다(헤더 "마이페이지"가 현재 위치). 탭 순서는 `docs/page-urls.md` 섹션 순서를 따르므로 그 문서에도 `/subscription`을 운영자 앞 섹션에 더한다.

- Given `demo-role=guest`, 그리고 `demo-role=admin`
- Then  비로그인 탭은 "참여 테스트", "내 프로젝트", "채팅", "구독"이고 "구독"은 `/subscription`을 가리킨다
- Then  운영자 탭은 5개이고 "구독"이 "운영자 페이지" 바로 왼쪽이다

#76-S9 현재 탭 [직접]

#76-S10 운영자 헤더 한 줄 [직접]

## 4. "구독 알아보기" 진입 (#76-R4)
"구독 알아보기"는 이 페이지로 오고, 이미 구독을 관리하는 링크는 그대로 둔다.

| 위치 | 링크 | 바뀜 |
| --- | --- | --- |
| 프로젝트 분석 탭 "구독 알아보기" (`projects.md` S513, `projects.spec.ts`) | `/subscription` | 고침 #76 |
| 마이페이지 대시보드 구독 카드 "구독 알아보기" (`my.md` S89) | `/subscription` | 고침 #76 |
| 피드백의 "채팅하기"·"AI 질문 받기" "구독하면 쓸 수 있어요" 링크 (`projects.md`) | `/subscription` | 고침 #76 |
| 대시보드 구독 카드 "구독 관리", 마이페이지 메뉴 "구독" | `/my/subscription` | 그대로 |

홈 구독 영역의 빈 상태 "구독 알아보기"는 #60에서 영역을 통째로 빼서 이 이슈 범위에서 빠진다. 새 번호는 받지 않고 위 시나리오에 `(고침 #76: 구독 알아보기는 공개 소개 페이지로)`를 붙인다. `subscription.md` 맥락의 "여기로 온다" 목록도 고친다.

## 7. 백엔드 연결 (#203)
`AUTH_MODE=backend`에서 카드의 이름·가격·기간·혜택과 구독 상태를 서버 값으로 그린다. 값이 없으면 목업으로 동작한다(`features/subscription/api.ts`). 카드 제목·한 줄 설명·"무료" 가격 표기는 서버 값이 아니라 프론트 문구다.

| 화면 값 | 서버 |
| --- | --- |
| FREE 카드 이름·혜택 | `GET /api/v1/plans/free`의 `tier`, `benefits` |
| PRO 카드 이름·가격·기간·혜택 | `GET /api/v1/plans`의 `tier`, `cashPrice`·`creditPrice`, `periodDays`, `benefits` |
| "이용 중"·"구독 연장하기" | `GET /api/v1/my/subscription/status`의 `active`, `planId` |

로그인이 필요 없는 두 조회(`plans`, `plans/free`)는 토큰을 붙이지 않는다. 로그아웃·정지로 토큰이 막힌 회원도 소개를 읽는다. 서버에 닿지 못하면 오류로 멈추고 목업으로 대신 채우지 않는다. 지금 앱에는 `error.tsx`가 없어 Next 기본 오류 화면이 뜬다. 앱 공용 오류 화면은 별도 작업이 필요하다([frontend-structure](../../frontend-structure/01-next-rules.md) N12, F9).

#203-S8 FREE 카드가 서버 값으로 보인다 [직접]
- Given `AUTH_MODE=backend`이고 무료 플랜이 이름 "FREE-서버", 혜택 "서버 혜택 하나", "서버 혜택 둘"이다
- Then  FREE 카드에 이 이름과 두 혜택이 보이고 가격은 "무료"다

#203-S9 PRO 카드가 서버 플랜 값으로 보인다 [직접]
- Given 서버의 구독 플랜이 PRO, 30일, 10,000원, 9,000 크레딧이고 혜택 5개다
- Then  카드에 "PRO", "30일 10,000원", "9,000 크레딧"과 혜택 5개가 서버가 준 순서로 보인다

#203-S10 내 구독 상태가 카드에 반영된다 [직접]
- Given 구독 중인 회원과 구독하지 않은 회원
- Then  구독 중인 회원의 PRO 카드에는 "이용 중"과 "구독 연장하기"가, 아닌 회원에는 "구독하기"가 보인다

## 작업 순서
1. 월간 모집 인원 삭제와 비교표 삭제 — 비교표(백엔드 혜택 목록으로는 행을 맞출 수 없어 뺌), 내 구독의 "이번 달 모집 인원", 목업 한도(`monthlyLimit`·`RecruitQuota`)를 지운다(백엔드에서 한도 칼럼이 없어짐). 프로젝트 모집 폼의 "모집 인원"(최대 인원)은 다른 기능이라 그대로 둔다
2. 페이지 — `/subscription` 공개 페이지, 두 카드, 역할별 버튼(S1~S7, S11). `pages.spec.ts`의 `PAGES`에 `["/subscription", "guest"]`를 더한다
3. 헤더 — `nav.ts`에 "구독" 탭, `page-urls.md`, 헤더 시나리오 고침(S8~S10, S323·S324·S327·S329)
4. 진입 링크 — "구독 알아보기"·"구독하면 쓸 수 있어요" 세 곳(프로젝트 분석·피드백·마이페이지)과 해당 시나리오 고침(R4)
