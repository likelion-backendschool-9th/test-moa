# 프론트엔드 모집글 상세 (`/recruitments/:slug`)

테스터가 지원 전에 일정, 인원, 보상, 조건을 확인하는 공개 페이지다 (이슈 #63).

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`만 e2e 테스트(`frontend/e2e/recruitment-detail.spec.ts`)와 1:1이고, `[직접]`은 사람이 화면을 보고 확인한다.

## 한눈에
- 누가: 누구나. 로그인하지 않아도 볼 수 있다.
- 무엇을: 상태·추가 보상·유형 배지, 모집글 제목과 설명, 프로젝트 이미지와 소개, 모집 조건, 테스트 항목, 일정·인원·선정 방식·보상 요약, 지원 버튼
- 이번에 하지 않는 것: 지원 페이지와 제출(`/recruitments/:slug/apply`는 준비 중), 실제 API

## 모집글 상세 (#63-R1)
넓은 화면(lg 이상)은 왼쪽에 이미지·소개·조건·항목, 오른쪽에 스크롤을 따라오는 요약이 있고, 좁으면 이미지 → 요약 → 소개·조건·항목 순서로 쌓인다. 요약은 기본 보상·추가 보상·인원을 크게, 일정과 선정 방식을 작게 보여 준다. 접속 링크는 참여가 확정된 테스터에게만 안내하므로 보여 주지 않는다. 소개는 프로젝트 상세 설명이 있으면 그것을, 없으면 모집 건의 한 줄 소개를 쓰고, 이미지 높이까지 보이다가 "더 보기"로 펼친다. 프로젝트 이미지가 없으면 기본 이미지가 나온다. 대표 이미지 옆에는 테스트 항목 이미지를 모아 가로로 잇고, 이미지 양쪽 가운데의 버튼으로 부드럽게 넘긴다. 스크롤바는 보이지 않는다. 같은 이미지가 항목 아래에도 그대로 보인다.

#63-S1 모집 중 [테스트]
- Given 비로그인, `/recruitments/booklog`
- Then  제목, "모집 중", "추가 보상" 배지, 모집 마감, 피드백 제출 마감, 인원, 선정 방식, 기본 보상, 추가 보상이 보인다
- Then  모집 조건과 테스트 항목(필수·선택)이 보이고 접속 링크는 없다
- When  "지원하기"를 누른다
- Then  `/recruitments/booklog/apply`의 준비 중 화면으로 간다

#63-S2 지원할 수 없음 [테스트]
- Given 정원이 찬 모집 건(`folio-builder`), 모집이 끝난 모집 건(`memo-garden`)
- Then  "정원이 모두 찼어요" 또는 "모집이 마감됐어요"가 보이고 "지원하기"가 없다
- Then  추가 보상이 없는 모집 건(`folio-builder`)에는 "추가 보상" 배지가 없다

#63-S3 상세 샘플이 없는 모집 건 [테스트]
- Given `/recruitments/moaplan`
- Then  요청 문구가 제목이 되고, 기본 이미지와 "따로 정한 조건이 없어요"가 보이며 테스트 항목은 없다
- Then  추가 보상과 "지원하기"가 있다

#63-S4 없는 모집 건 [테스트]
- Given 없는 주소, 취소된 모집 건(`folio-builder-old`)
- Then  "찾는 페이지가 없어요"가 보인다

#63-S6 항목 이미지 표시 [테스트]
- Given 이미지가 있는 항목(북로그 "책 검색해서 등록하기")
- Then  모집글 상세와 모집 관리의 항목 아래에 이미지가 고른 순서대로 나열되고, 줄이 차면 다음 줄로 내려간다
- Then  이미지가 없는 항목에는 이미지 영역이 없다

#63-S7 항목 이미지 고르기 [테스트]
- Then  모집 작성의 항목마다 "항목 n 이미지 (선택)"이 있다. PNG·JPG·WEBP, 한 장에 5MB, 항목당 5장까지이고 다른 항목과 따로 센다
- When  합쳐서 5장이 넘게 고른다
- Then  이번에 고른 파일은 넣지 않고 "이미지는 5장까지 올릴 수 있어요"가 보인다
- When  이미지를 빼거나 줄을 지운다
- Then  남은 이미지 순서는 그대로다. 제출에 실패해도 고른 이미지가 남는다

#63-S8 항목 이미지 서버 확인 [테스트]
- Given 숨은 칸의 값을 6장으로 바꿨다, 또는 이름 없이 이미지만 있다
- When  제출한다
- Then  그 항목에 오류가 보이고 등록되지 않는다

#63-S9 이미지 넘겨 보기 [테스트]
- Given 항목 이미지가 있는 모집 건(`booklog`)
- Then  제목 아래에 프로젝트 대표 이미지가 먼저 오고, 그 옆으로 테스트 항목 이미지가 항목 순서대로 가로로 이어진다
- Then  프로젝트가 등록한 대표 이미지에만 "대표 이미지" 표시가 있다. 이미지가 한 장뿐이거나 기본 이미지면 표시가 없다
- When  "다음 이미지"를 끝까지 누른다
- Then  한 장씩 넘어가 마지막 이미지가 보이고 "다음 이미지"가 꺼진다. 처음 위치에서는 "이전 이미지"가 꺼져 있다
- When  움직이는 중에 "이전 이미지"를 빠르게 여러 번 누른다
- Then  누른 만큼 넘어간다
- Given 항목 이미지가 없는 모집 건(`moaplan`)
- Then  대표 이미지만 있고 넘기는 버튼이 없다. 이미지가 여러 장이어도 모두 들어가면 버튼이 없다

#63-S10 긴 항목 설명 [직접]
- Given 설명이 300자에 가까운 항목(북로그 "책 검색해서 등록하기"), 긴 주소가 든 항목("밑줄 문장 남기기")
- Then  모집글 상세와 모집 관리에서 설명이 칸 안에서 줄바꿈되고, 375px에서도 가로로 넘치지 않는다

#63-S11 항목 이미지 확대 [테스트]
- Given 이미지가 있는 항목(북로그 "책 검색해서 등록하기")
- Then  모집글 상세와 모집 관리의 항목 이미지가 넓은 화면에서 3열, 좁은 화면에서 2열로 크게 보인다
- When  이미지를 누른다
- Then  이미지가 대화상자에 확대되어 보이고, 이름과 "1 / 2"가 나온다
- When  버튼이나 화살표 키로 넘긴다
- Then  같은 항목의 다른 이미지로 바뀐다
- When  Esc, 닫기 버튼, 바깥 클릭 중 하나로 닫는다
- Then  대화상자가 닫힌다. Esc로 닫으면 누른 이미지로 포커스가 돌아온다

#63-S5 배치와 로딩 [직접]
- Then  넓은 화면은 요약이 오른쪽에서 스크롤을 따라오고, 좁은 화면은 이미지 아래에 있으며 가로 스크롤이 없다
- Given `demo-data=slow`
- Then  스켈레톤이 먼저 보인다

## 데이터
- 항목 이미지는 시연용이라 파일을 서버로 보내지 않고 이름·크기·형식만 보내며, 등록 뒤에는 남지 않는다. 샘플은 북로그 "책 검색해서 등록하기"와 "밑줄 문장 남기기"에 2장씩 있다. 긴 설명을 확인할 수 있게 이 두 항목의 설명은 길게 두었다.
- 백엔드는 ERD의 `프로젝트 이미지`, 엔티티 `ProjectImage`(`testItem`, `sortOrder`)에 맞춘다. ERD는 `test_item_id`가 `NOT NULL`이고 엔티티는 비울 수 있어 맞춰야 한다.
- `project/api.ts`의 `findPublicRecruitment(slug)`가 역할과 상관없이 모집 건, 상세, 프로젝트를 찾는다. 실제 API를 붙이면 이 함수 본문을 바꾼다.
- 모집글 제목, 조건, 테스트 항목 샘플은 북로그와 포트폴리오 빌더의 모집 건에만 있다. 나머지는 #63-S3처럼 기본 내용으로 보인다.
- PR #31의 데이터에 기대므로 #31이 먼저 머지되어야 한다.
