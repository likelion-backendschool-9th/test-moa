# 모집 글·채팅방 신고 창 (#85)

회원이 모집 글과 채팅 상대를 사유와 증거 파일로 신고하는 창이다. 모집 상세(`/recruitments/:slug`)와 채팅방 더보기에서 함께 쓴다. 피드백 신고는 모집 관리의 피드백 탭이 따로 받는다(#120). 백엔드 API와 규칙은 [backend/auth/reports.md](backend/auth/reports.md).

- 진입
  - 모집 상세: 로그인한 회원에게 "모집 요약" 맨 아래 "모집 글 신고하기"(깃발 아이콘, 흐린 글씨 버튼). 비로그인에게는 없다
  - 채팅: 채팅함 카드와 채팅방 머리의 더보기 메뉴. "대화방 이름 변경", "신고하기", 구분선, "대화방 삭제"
- 창: 브라우저 기본 `<dialog>`. 제목("모집 글 신고"·"채팅 신고"), 무엇을 신고하는지 한 줄과 "운영자가 검토하고, 신고한 사람은 상대에게 알리지 않아요", 신고 사유(필수, 1,000자), 증거 파일(선택), 취소·신고하기
- 증거 파일: PNG·JPG·WEBP·PDF, 한 장 5MB, 5장까지. 고르자마자 확인해 규칙에 맞지 않으면 알리고 신고하기를 막는다. 문구는 백엔드와 같다
- 접수하면 "신고를 접수했어요"와 "운영자가 검토한 결과는 마이페이지의 '내 신고'에서 볼 수 있어요". 확인을 누르면 닫히고 연 버튼으로 포커스가 돌아온다
- 실패는 백엔드 문구를 창 안에 보인다. 자기 글은 "자기 자신은 신고할 수 없어요", 검토 중인 같은 대상은 "이미 신고해서 검토를 기다리고 있어요"
- 데이터: `AUTH_MODE=backend`면 서버 액션이 `POST /api/v1/reports`로 multipart를 그대로 넘긴다(모집 글은 `targetId`, 채팅은 `roomKey`). 목업은 저장하지 않고 접수한 것으로 보인다
- 서버 액션 본문 한도는 백엔드·nginx와 같은 30MB(`next.config.ts`의 `serverActions.bodySizeLimit`, `proxyClientMaxBodySize`)

## 요구사항

- #85-R6 로그인한 회원은 모집 상세와 채팅 더보기에서 신고 창을 연다
- #85-R7 사유는 필수이고, 증거 파일은 PNG·JPG·WEBP·PDF를 한 장 5MB, 5장까지 고른다
- #85-R8 접수하면 결과를 볼 곳(내 신고)을 알리고, 실패하면 이유를 창 안에 보인다

## 시나리오

#85-S22 로그인한 회원은 모집 상세에서 사유를 적어 모집 글을 신고한다 [테스트]
- When  "모집 글 신고하기"를 누르고 사유 없이 신고하기를 누른다
- Then  "신고 사유를 적어 주세요"가 보인다. 서버가 거절해도(중복 신고·서버 오류 포함) 적은 사유와 고른 파일은 지워지지 않는다
- When  사유를 적어 신고한다
- Then  "신고를 접수했어요"가 보이고, 확인을 누르면 창이 닫히고 버튼으로 포커스가 돌아온다

#85-S23 비로그인은 모집 상세에 신고 버튼이 없다 [테스트]

#85-S24 증거 파일은 PNG·JPG·WEBP·PDF만 5장까지 고를 수 있다 [테스트]
- 텍스트 파일은 "PNG·JPG·WEBP·PDF 파일만 올릴 수 있어요", 6장은 "증거 파일은 5장까지 올릴 수 있어요"이고 신고하기가 막힌다. PNG와 PDF 두 장은 신고한다

#85-S25 채팅방 더보기의 신고하기로 상대를 신고하고, 취소하면 메뉴 버튼으로 돌아간다 [테스트]
- 메뉴는 "대화방 이름 변경", "신고하기", "대화방 삭제" 순서다

#85-S26 실제 로그인에서 증거와 함께 신고하면 저장되고 내 신고에 보인다 [직접]
- Given `AUTH_MODE=backend`, 다른 회원의 모집 글
- When  PNG 한 장을 붙여 신고한다
- Then  "신고를 접수했어요"가 보이고, 마이페이지 "내 신고" 맨 위에 그 신고가 검토 대기로 보인다
- When  같은 글을 다시 신고한다
- Then  "이미 신고해서 검토를 기다리고 있어요"가 창 안에 보인다
- When  내 모집 글을 신고한다
- Then  "자기 자신은 신고할 수 없어요"가 창 안에 보인다

## 범위 밖
