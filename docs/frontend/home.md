# 프론트엔드 서비스 홈 (`/`)

지금 홈 화면이 지켜야 하는 요구사항(R)과 시나리오(S)를 모은 문서다. S번호는 `frontend/e2e`의 테스트 이름과 1:1로 맞는다. 테스트를 추가하거나 바꾸면 이 문서도 함께 고친다.

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`만 e2e 테스트와 1:1이고, `[테스트: 파일 번호]`는 그 테스트가 대신 확인한다. `[명령]`은 명령 한 번, `[직접]`은 사람이 화면을 보고 확인한다. (고침 #56: `docs/test-cleanup.md`)

## 한눈에
- 스택: Next.js 16(App Router, Cache Components), Tailwind CSS v4, TypeScript, Playwright E2E. 실행 방법은 `frontend/README.md`를 본다.
- 화면 구성(위에서부터):
  1. 한 줄 헤더: 로고, 카테고리 탭, 계정 영역 (고침 11-02: 검색창 삭제)
  2. 전체 폭 히어로 배너: 소개(+ 최근 모집 글 교정지 더미) → 진행 흐름(교정 체크리스트), 5초 순환 (고침 #60)
  3. "이런 테스트도 있어요": 구독 개발자의 모집 글 (고침 #60: 제목을 "구독 모집"에서 바꿈)
  4. 전체 테스트: 검색·카테고리·모집 중·정렬이 되는 그리드, 20개씩 페이지로 나눔 (고침 #60)
- 진행 중: #60 서비스 홈 UI 개선. 계획은 맨 아래 [#60 작업 계획](#60-작업-계획)에 있다.
- 디자인: uibowl 갤러리 문법에 교정쇄 소재(재단선, 재단 매트 격자, 교정 도장)를 입혔다. 라이트는 교정쇄 바탕, 다크는 uibowl 바탕이고, 강조는 두 모드 모두 에메랄드 계열이다. 글꼴은 Wanted Sans 하나다. 토큰과 규칙은 `frontend/DESIGN.md`와 `docs/design-tokens.html`에 있다.
- 데이터: 로그인과 API는 아직 목업이다. 쿠키 `demo-role`과 `demo-data`로 상태를 바꾼다. 개발 서버에서는 푸터의 "시연용" 선택 상자를 쓴다 (채팅방은 푸터가 없어서 다른 페이지에서 바꾼다).
- 페이지 URL: `docs/page-urls.md`

## 6. 히어로 배너 (R6)
배너는 전체 폭으로 서비스 소개 → 진행 흐름 두 장을 담고 5초마다 순환한다. hover·focus 중이거나 reduced motion이면 멈춘다. 라이트 바탕은 진한 초록 재단 매트 격자이고, 네 귀퉁이에 흰 재단선이 있다. 다크 바탕은 기존 남회색 면이다. (고침 #60: B 색 시안)

S61 첫 화면 [직접] (고침 #60: 제목·설명·배치와 B 색 시안)
- Then  제목이 "써 보고, 남기고, 받고"이고 라이트에서는 전부 흰색이며, 320~1440px 모두 한 줄이다
- Then  설명은 "새 서비스를 써 보고 피드백을 남기면 크레딧을 받아요." 한 줄이다
- Then  제목·설명은 배너 안쪽 맨 위에, "테스트 둘러보기"(`#all-tests`)는 맨 아래에 붙어 있다
- Then  조작부에 "1 / 2"가 보인다
- Then  라이트 배너 바탕이 `#0f7c4a`이고, 24px 잔눈금(흰색 9%)과 120px 굵은 눈금(흰색 20%)이 글을 읽는 데 방해되지 않는다. 주 버튼은 흰 바탕에 진한 초록 글씨다
- Then  다크 배너에는 기존의 옅은 격자가 있다
- Then  공유 이미지(`og:image`)도 같은 제목과 설명이다

#60-S8 교정지 더미 [직접]
- Given 너비 1280px 이상
- Then  소개 오른쪽에 정원이 남은 최근 모집 글 썸네일 세 장("가계부 노트", "북로그", "모아플랜")이 기울어 겹쳐 있고, 글 칸을 뺀 오른쪽 칸을 채운다 (1440px에서 한 장 약 300px)
- Given 너비 1024~1279px
- Then  같은 자리에 두 장("가계부 노트", "북로그")만 크게 겹쳐 있다
- Given 너비 768px 미만
- Then  최근 모집 글 한 장("가계부 노트")이 글과 버튼 사이에 비스듬히 있다
- Given 너비 768~1023px
- Then  썸네일 없이 소개 글만 있다
- Then  어느 폭에서도 서비스 이름이 다음 장에 가려지지 않는다
- When  썸네일에 마우스를 올린다
- Then  어느 장이든 똑같이 12px 떠오르고 맨 앞으로 온다
- When  썸네일을 누른다
- Then  그 모집 상세(`/recruitments/:slug`)로 간다

S62 진행 흐름으로 넘김 [직접] (고침 #60: 이벤트 슬라이드 대신 진행 흐름)

## 7. 진행 흐름 (R7)
배너 둘째 장은 테스터가 하는 일과 받는 보상을 교정 체크리스트로 보여 준다. (고침 #60: 마감 임박 순위 패널을 지웠다. 첫 화면을 차지해 모바일 첫 화면에 카드가 없었고, 같은 글이 세 영역에 겹쳐 나왔다. 마감이 가까운 테스트는 정렬의 "마감 임박순"으로 찾는다)

S65 (지움 #60: 마감 임박 순위 패널 삭제)

#60-S1 교정 체크리스트 [직접]
- When  배너에서 "다음"을 누른다
- Then  왼쪽 맨 위에 "이렇게 진행돼요", 맨 아래에 보상 약속 두 줄("1크레딧은 1원으로 출금할 수 있어요", "개발 경험이 없어도 느낀 점만 남기면 보상을 받아요")이 있다
- Then  오른쪽에 1° 기운 교정지 한 장이 오른쪽 끝에 붙어 있고(폭 최대 36rem), 그 위에 "지원해요", "참여가 확정되면 써 봐요", "피드백을 내요", "72시간 뒤 크레딧을 받아요"가 줄마다 앞에 교정 체크를 달고 이 순서로 있다
- Then  앞의 세 체크는 교정지 글자색 40%, 마지막 줄만 강조색 체크와 "크레딧 지급" 도장이다 (768px 이상은 그 줄 오른쪽, 그보다 좁으면 교정지 오른쪽 아래 가장자리)
- Then  768px 미만은 제목 → 교정지 → 약속 순서로 위아래에 붙고, 768~1023px은 약속 문구를 숨긴다
- Then  교정지가 오른쪽 아래 조작부와 겹치지 않고, 다크에서도 체크가 보인다

## 9. 전체 테스트 (R9)
전체 모집 글 그리드에서 검색, 카테고리, 모집 중만 보기, 정렬을 홈에서 바로 바꾸고, 상태는 URL(`q`, `type`, `open`, `sort`, `page`)에 남는다. 결과는 20개씩 페이지로 나누고, 그리드 위에 "총 N개"를 보여 준다. (고침 #60: 페이지 나누기 추가)

검색·필터·정렬은 1024px 이상에서 한 줄(왼쪽 검색창, 가운데 카테고리 칩과 "모집 중만 보기", 오른쪽 정렬 선택 상자)이고, 1024px 미만에서는 첫 줄에 검색창과 정렬, 둘째 줄에 가로로 넘기는 칩이다. (고침 #60: 한 줄에 선택지 9개가 몰리고 정렬 글자 버튼이 누를 수 있어 보이지 않았다)

S68 기본 [테스트] (고침 #60: 목업 22개, 한 페이지 20개)
- Then  카드 20개가 최신순이고 첫 카드는 "가계부 노트", 그리드 위에 "총 22개"가 보인다

- Then  URL에 `q=%EC%9D%BC%EC%A0%95`가 붙고 "모아플랜"만 보인다

S70 카테고리와 초기화 [테스트] (고침 #60: 한 페이지 20개)
- When  "게임"을 누른다
- Then  URL에 `type=game`이 붙고 "조건에 맞는 테스트가 없어요"가 보인다
- When  "조건 초기화"를 누른다

- Then  첫 카드가 "북로그"다
