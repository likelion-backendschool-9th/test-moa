# 프론트엔드 개발자 프로젝트 (`/my/projects`)

개발자 프로젝트 영역(`docs/page-urls.md`의 "개발자 프로젝트" 9개 페이지)이 지켜야 하는 요구사항(R)과 시나리오(S)를 모은 문서다. S번호는 `frontend/e2e`의 테스트 이름과 1:1로 맞는다. 홈 문서(`home.md`, S1~S82)와 겹치지 않게 처음에는 S101부터 썼고, 11-02 번호 정리에서 S483~S526이 됐다. 테스트를 추가하거나 바꾸면 이 문서도 함께 고친다.

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`만 e2e 테스트와 1:1이고, `[테스트: 파일 번호]`는 그 테스트가 대신 확인한다. `[명령]`은 명령 한 번, `[직접]`은 사람이 화면을 보고 확인한다. (고침 #56: `docs/test-cleanup.md`)

## 한눈에
- 스택과 규칙은 홈과 같다: Next.js 16(App Router, Cache Components), Tailwind CSS v4, TypeScript, Playwright E2E. 폴더 구조와 규칙은 `frontend/README.md`를 따른다.
- 범위: 아래 9개 페이지. 후보 URL도 모두 포함한다.

| 페이지 | URL | 상태 |
| --- | --- | --- |
| 내 프로젝트 목록 | `/my/projects` | 확정 |
| 프로젝트 등록 | `/my/projects/new` | 후보 |
| 프로젝트 상세 | `/my/projects/:projectKey` | 확정 |
| 프로젝트 수정 | `/my/projects/:projectKey/edit` | 후보 |
| 테스트 모집 작성 | `/my/projects/:projectKey/recruitments/new` | 확정 |
| 테스트 모집 관리 | `/my/projects/:projectKey/recruitments/:recruitmentKey` | 확정 |
| 테스터 관리 탭 | `...?tab=testers` | 후보 |
| 피드백 탭 | `...?tab=feedback` | 후보 |
| 분석 탭 | `...?tab=analytics` | 후보 |

- 용어는 README를 따른다. **프로젝트**는 테스트할 소프트웨어, **테스트 모집 건**은 한 프로젝트에서 조건·일정을 정해 테스터를 모으는 단위다. 참여자·피드백·보상은 모집 건별로 관리한다.
- 데이터: 로그인과 API는 목업이다. 홈과 같이 `features/project/`에 `types.ts`, `mock.ts`, `api.ts`를 두고, 화면은 `service.ts`만 부른다(아래 3계층 구조). 실제 API를 붙일 때는 `api.ts` 함수 본문만 바꾼다.
- 시연 상태는 홈과 같은 쿠키로 바꾼다. `demo-role=developer`(박도현, 구독 중)가 프로젝트를 가진 개발자다. `demo-data=empty`면 프로젝트가 없다.
- 디자인: 홈의 토큰과 공통 컴포넌트(`components/ui`의 Button, LinkButton, Badge, Card, EmptyState, Skeleton)를 그대로 쓴다. 새 색이나 임의 값은 만들지 않는다.

## 코드 작성 규칙
### 3계층 구조
공통 의존 규칙은 [프론트엔드 README의 의존 방향](../../frontend/README.md#의존-방향)을 따른다. 프로젝트 영역은 여기에 로직 계층(`service.ts`)을 하나 더 둔다. 위 계층만 아래 계층을 부른다(화면 → 로직 → 데이터). 아래 계층은 위 계층을 모른다.

| 계층 | 위치 | 하는 일 | 하지 않는 일 |
| --- | --- | --- | --- |
| 화면 | `src/app/my/projects/**/page.tsx`, `src/features/project/components/`, `actions.ts`(폼·버튼 요청을 받는 서버 액션) | 로직 계층을 불러 받은 값을 그린다. 버튼·폼 같은 상호작용 | 계산, 검증 규칙, 목업 직접 접근 |
| 로직 | `src/features/project/service.ts` | 모집 건 상태, 제출률, 남은 신고 시간 계산, 폼 검증, 구독 여부에 따른 기능 허용 판단 | 화면 그리기, 데이터 저장소 접근 방식 알기 |
| 데이터 | `src/features/project/api.ts` (+ `mock.ts`, `demo-decisions.ts`) | 프로젝트·지원·피드백 데이터를 가져오고 확정·거절을 저장한다. 지금은 목업과 쿠키, 나중에 실제 API | 계산, 화면 문구 |

- 공용 규칙: `types.ts`(타입·상수)와 `media.ts`(이미지 한도 검사)는 화면과 로직이 같이 쓴다. `service.ts`는 서버 전용이라 브라우저에서 바로 검사해야 하는 규칙만 `media.ts`로 뺐다.

- 라우트(`page.tsx`)는 `service.ts`만 불러서 받은 값을 컴포넌트에 넘겨 조립만 한다.
- 프로젝트 영역에서는 `service.ts`만 `api.ts`를 import하며, 페이지와 액션은 `service.ts`를 호출한다.
- 컴포넌트는 데이터를 props로만 받는다. `api.ts`나 `mock.ts`를 직접 import하지 않는다.
- 로직 계층 함수는 화면 없이 테스트할 수 있게 입력을 받아 값을 돌려주는 함수로 쓴다.

### 한글 주석
- 주석은 한글로 쓴다.
- 파일 맨 위에 그 파일이 무엇을 하는지 한두 줄로 적는다.
- export하는 함수, 컴포넌트, 타입마다 무엇을 하는지 `/** */` 한 줄 주석을 단다.
- 규칙이나 숫자의 근거가 있으면 적는다. 예: `/* README: 제출 후 72시간 동안 신고가 없으면 자동 지급 */`
- 코드를 그대로 읽어 주는 주석은 달지 않는다. 예: `// i를 1 늘린다`

## 데이터 모델
필드 이름은 `features/recruitment/types.ts`와 맞춘다.

**Project** (`features/project/types.ts`)
| 필드 | 설명 |
| --- | --- |
| `key` | URL의 `projectKey`. 영문 소문자와 `-` |
| `name` | 프로젝트 이름. 1~50자 |
| `description` | 상세 설명. 선택, 2000자까지. 없으면 빈 문자열 |
| `image` | 대표 이미지 `{ url, name }`. 선택, 1장. 없으면 `null`이고 화면에 기본 이미지(`public/sample/projects/default.svg`)가 나온다 (백엔드 `project.image_url`) |
| `createdAt` | 등록일 |
| `recruitments` | 이 프로젝트의 모집 건. `Recruitment`를 재사용하고 `slug`를 `recruitmentKey`로 쓴다 |

**Application** (지원)
| 필드 | 설명 |
| --- | --- |
| `id` | 지원 번호 |
| `testerNickname` | 테스터 닉네임. 이메일·연락처 같은 개인정보는 두지 않는다 |
| `status` | `applied`(지원), `confirmed`(확정), `rejected`(거절), `cancelled`(참여 취소: 테스터가 그만뒀거나 모집이 취소됨) |
| `appliedAt` | 지원일 |

**Feedback**
| 필드 | 설명 |
| --- | --- |
| `id` | 피드백 번호 |
| `testerNickname` | 작성한 테스터 닉네임 |
| `content` | 피드백 내용 |
| `submittedAt` | 제출 시각 |
| `status` | `waiting`(72시간 신고 대기), `reported`(신고됨), `paid`(지급 완료) |
| `testItemId` | 어느 테스트 항목에 대한 피드백인지. 기타 의견은 `null` (백엔드 `Feedback.testItem`) |
| `images` | 피드백에 붙인 스크린샷 `{ url, name }` 목록 (백엔드 `FeedbackImage`) |
| `recommended` | 개발자가 도움이 된 피드백으로 추천했는지 |

**RecruitmentDetail** (모집 건에 붙는 내용. 홈의 `Recruitment` 타입은 홈 담당이라 따로 둔다)
| 필드 | 설명 |
| --- | --- |
| `title` | 모집글 제목. 50자까지 (백엔드 `post.title`) |
| `accessUrl` | 접속 링크. `http(s)://`로 시작한다 (백엔드 `post.access_url`) |
| `selectionMode` | 선정 방식 `firstCome`(선착순)·`selection`(선발형). 선발형은 구독 모집만 (백엔드 `post.selection_mode`) |
| `conditions` | 모집 조건: 필요한 경험·관심사·사용 환경. 선택, 500자까지 |
| `testItems` | 테스트 항목 `{ id, title, description, required }` 목록. 1~10개, 이름 50자·설명 300자까지 (백엔드 `TestItem`. `required`는 백엔드에 아직 칸이 없다) |

**CancelRequest** (모집 취소 요청)
| 필드 | 설명 |
| --- | --- |
| `status` | `pending`(처리 대기), `approved`(승인), `rejected`(반려) |
| `reason` | 개발자가 적은 취소 사유. 300자까지 |
| `requestedAt` | 요청 시각 |
| `rejectReason` | 반려 사유. 운영자 화면의 문구("이미 테스트가 진행 중이에요", "취소 사유가 부족해요", 기타 메모)와 같다 |

**모집 건 상태**는 저장하지 않고 계산한다.
- `모집 중`: 모집 마감 전이고 정원이 남았다
- `모집 완료`: 모집 마감 전이고 정원이 찼다
- `테스트 중`: 모집이 마감됐고 제출 마감 전이다
- `종료`: 제출 마감이 지났다
- `취소`: 모집 취소 요청이 승인됐다. 날짜와 상관없이 취소이고, 전체 현황 숫자와 할 일에서 빠진다

## 1. 접근 (R101)
이 영역은 로그인한 회원만 쓴다. 역할은 나누지 않아서 로그인한 누구나 프로젝트를 등록할 수 있다.

S483 비로그인 [테스트: pages.spec.ts #56-S2]
- Given `demo-role=guest`
- When  9개 URL 중 아무 곳에 직접 접속한다
- Then  `/login?next=<접속한 경로>`로 이동한다

S484 탭 표시 [직접]
- When  9개 URL 중 아무 곳에 접속한다
- Then  카테고리 탭 "내 프로젝트"에 `aria-current="page"`가 있다

S485 없는 프로젝트·모집 건 [테스트]
- When  `/my/projects/nope`이나 `/my/projects/booklog/recruitments/nope`에 접속한다
- Then  맞춤 404 화면("찾는 페이지가 없어요")이다
- Then  다른 회원의 프로젝트도 같은 404 화면이다 (403으로 할지 보류)
- 참고: 세션을 읽고 나서 404를 판단하므로 화면을 스트리밍하는 중이라 HTTP 상태는 200이다. 실제 API를 붙일 때 다시 본다.

## 2. 내 프로젝트 목록 (R102)
위에서부터 "지금 확인할 일", "전체 현황", "프로젝트" 카드 순서로 보여 준다. 개발자가 들어오자마자 손이 필요한 일을 먼저 보게 하려는 순서다. 프로젝트가 없으면 앞의 두 영역 없이 빈 상태만 보여 준다.

S522 지금 확인할 일 [직접]
- Given `demo-role=developer`
- Then  제목 바로 아래 "지금 확인할 일 2건" 영역이 있다
- Then  항목은 두 종류다
  - 확정을 기다리는 지원자: 구독 모집이고, 모집 마감 전이고, 정원이 남은 모집 건만. "지원자 8명이 확정을 기다려요 · 남은 자리 7명"
  - 신고 대기 피드백: 72시간이 지나지 않은 것만, 모집 건별로 묶는다. "신고 대기 피드백 1건 · 62시간 뒤 자동 지급"
- Then  지원자 항목이 먼저, 피드백 항목은 자동 지급이 가까운 순서다
- Then  각 항목에 프로젝트 이름이 있고, 누르면 그 모집 건의 해당 탭(`?tab=testers`, `?tab=feedback`)으로 간다
- Then  탭 이름("테스터 관리", "피드백")은 일반 링크라 강조색이 아니라 보조 글씨색이다 (DESIGN.md The One Green Rule)
- Then  모집이 끝난 모집, 정원이 찬 모집, 무료 모집의 대기 지원자는 할 일에 없다
- Then  지원자를 확정해 정원이 차면(S525) 그 모집의 지원자 할 일은 사라진다
- Given 할 일이 없다
- Then  "지금 확인할 일이 없어요"가 보인다

S523 전체 현황 [직접]
- Then  "지금 확인할 일" 아래 "전체 현황" 영역에 모든 프로젝트의 진행 상황을 보여 주는 숫자 네 개가 있다
- Then  모집 건은 모든 프로젝트에서 상태별로 센다: 모집 중 1건, 모집 완료 1건, 테스트 중 1건
- Then  마지막은 신고 대기 피드백 수다: 신고 대기 1건

S524 순서 [직접]
- Then  "지금 확인할 일" → "전체 현황" → 프로젝트 카드 순서로 놓인다

S486 목록 [직접] (고침 #62: 카드에서 한 줄 소개와 유형을 뺌)
- Given `demo-role=developer`
- Then  제목 "내 프로젝트"와 "프로젝트 등록" 버튼(`/my/projects/new`)이 있다
- Then  카드 3개가 최신순이다: "할 일 메모", "포트폴리오 빌더", "북로그"
- Then  각 카드에 이름과 "모집 n건 · 모집 중 n건"이 보이고 상세(`/my/projects/:projectKey`)로 이동한다 (북로그는 "모집 2건 · 모집 중 1건")
- Then  카드는 페이지 바탕과 다른 카드 바탕(`surface-muted`)과 테두리(`line`)가 있어 다크 모드에서도 카드끼리 구분된다

S487 빈 목록 [직접]
- Given `demo-role=tester` (또는 `demo-data=empty`)
- Then  "아직 등록한 프로젝트가 없어요"와 "프로젝트 등록" 버튼이 보인다

S488 로딩 [직접]
- Given `demo-data=slow`
- Then  카드 스켈레톤이 먼저 보이고, 응답 뒤 카드가 보인다

## 3. 프로젝트 등록·수정 (R103)
등록과 수정은 같은 폼을 쓴다. 목업이라 저장되지 않고, 성공하면 안내와 함께 이동한다.

S489 등록 폼 [직접] (고침 #62: 등록 항목을 이름, 상세 설명, 대표 이미지로 줄임)
- When  `/my/projects/new`에 접속한다
- Then  "프로젝트 이름", "상세 설명 (선택)", "대표 이미지 (선택)" 입력란이 레이블과 함께 있다. 한 줄 소개, 추가 링크, 유형은 없다. 유형은 모집글에서 고른다(S352)

S490 검증 [테스트] (고침 #62: 상세 설명 2000자)
- When  이름을 비우거나 51자를 넣거나, 상세 설명을 2000자 넘게 적고 "등록"을 누른다
- Then  해당 칸 아래에 오류 문구가 보이고(`aria-describedby`로 연결), 첫 오류 칸으로 포커스가 간다
- Then  페이지는 이동하지 않는다

S491 등록 성공 [테스트]
- When  올바른 값으로 "등록"을 누른다
- Then  `/my/projects`로 이동하고 "시연용이라 실제로 저장되지는 않아요" 안내가 보인다

S492 수정 폼 [직접]
- When  `/my/projects/booklog/edit`에 접속한다
- Then  같은 폼에 북로그의 값이 채워져 있고 버튼 이름은 "저장"이다
- Then  "취소"는 `/my/projects/booklog`로 간다

S493 수정 성공 [테스트] (고침 #62: 한 줄 소개를 없앰)
- When  설명을 바꾸고 "저장"을 누른다
- Then  `/my/projects/booklog`로 이동하고 저장 안내가 보인다

### 이미지·미리보기 (R113)

### 모집 취소 요청 (R115)
운영자 화면(`docs/frontend/admin-cancellations.md`)과 맞춘 개발자 쪽 화면이다. 개발자가 테스트 시작 전에 사유를 적어 요청하면 운영자가 승인하거나 반려한다. 승인되면 모집 건이 취소되고 확정된 테스터의 참여도 함께 취소된다.

- Then  요약 오른쪽 위에 "모집 취소 요청" 버튼이 있다
- When  누른다
- Then  "모집 취소 요청" 대화상자가 열리고 "취소 사유" 칸(300자)이 있다
- When  사유 없이 "요청 보내기"를 누른다
- Then  "취소 사유를 적어 주세요"가 보이고 포커스가 사유 칸에 간다
- When  사유를 적어 보낸다
- Then  대화상자가 닫히고 "취소 요청 처리 대기" 안내와 요청 사유·요청일이 보이며 버튼이 사라진다
- Then  새로고침해도 남는다. 시연용이라 모집 건마다 쿠키(`demo-cancel-request-{모집 건 키}`)에 저장하고, 운영자 화면과는 아직 잇지 않는다

S355 요청할 수 없음

- Then  "모집 취소 요청" 버튼이 없다. 서버도 다시 확인해 "지금은 취소를 요청할 수 없어요"로 막는다

- Given 운영자가 승인한 요청(포트폴리오 빌더의 지난 모집 `folio-builder-old`)

- Then  지원자는 모두 "참여 취소"이고, 확정·거절 버튼과 취소 요청 버튼이 없다
- Then  내 프로젝트의 프로젝트 카드 모집 건 수에서 빼고("모집 1건 · 모집 중 0건"), 전체 현황 숫자와 할 일에서는 빠진다

S502 탭 [직접]
- Then  탭 3개 "테스터 관리", "피드백", "분석"이 있다
- Then  `tab`이 없거나 모르는 값이면 "테스터 관리"가 선택된다(`aria-current="page"`)
- When  "피드백"을 누른다
- Then  URL에 `?tab=feedback`이 붙고 피드백 탭이 보인다

## 7. 테스터 관리 탭 (R107)
지원자를 지원 순서대로 보여 준다. 무료 모집은 선착순 자동 확정이라 보기만 하고, 구독 모집은 개발자가 직접 확정·거절한다.

S503 지원자 목록 [테스트]
- Then  지원 순서대로 닉네임, 상태 배지("지원", "확정", "거절"), 지원일이 보인다
- Then  이메일·연락처는 보이지 않는다

S504 구독 모집 선정 [테스트]
- Given 구독 모집(북로그), 정원이 남았다
- Then  상태가 "지원"인 행에만 "확정", "거절" 버튼이 있다
- When  "확정"을 누른다
- Then  그 행의 배지가 "확정"이 되고, 버튼이 사라지고, 확정 수가 1 늘어난다 (결과는 S525처럼 저장된다)

S505 정원 참 [테스트]
- Given 확정 수가 정원과 같다 (북로그에서 7명을 확정한 뒤)
- Then  "확정" 버튼이 비활성이고 "정원이 다 찼어요"가 보인다

S506 무료 모집 [테스트]
- Given 무료 모집(포트폴리오 빌더)
- Then  "확정", "거절" 버튼이 없고 "선착순 모집이라 지원 순서대로 자동 확정돼요"가 보인다

S521 일괄 확정 [테스트]
- Given 구독 모집(북로그), 정원이 남았다
- Then  상태가 "지원"인 행에 체크박스가 있고, 목록 위에 "전체 선택" 체크박스와 "선택한 n명 확정" 버튼이 있다
- Then  아무것도 고르지 않으면 버튼이 비활성이다
- When  "전체 선택"을 누른다 (대기 8명, 남은 자리 7명)
- Then  "지원" 행이 모두 선택되고, 버튼 "선택한 8명 확정"은 비활성이며 "남은 자리는 7명이에요"가 보인다
- When  한 명의 선택을 푼다
- Then  버튼이 "선택한 7명 확정"으로 바뀌고 눌린다
- When  버튼을 누른다
- Then  고른 행이 모두 "확정"이 되고 확정 수가 20명이 되며, 결과가 `aria-live`로 읽힌다 (결과는 S525처럼 저장된다)
- Then  정원이 찼으므로 일괄 확정 영역이 사라지고 "정원이 다 찼어요"가 보인다
- Then  모집이 끝난 모집(북로그 1차)에는 대기 지원자가 있어도 체크박스, 일괄 확정, 확정·거절 버튼이 없다
- 참고: 무료 모집은 선착순 자동 확정이라 대기 지원자가 생기지 않는다. 직접 선정하지 않는 것은 S506에서 확인한다

S525 확정 결과 반영 [테스트]
- Given 북로그 모집에서 7명을 확정해 "확정 20명 · 정원 20명"이 됐다
- Then  같은 화면 위쪽 요약의 "확정 인원"이 20명이 되고 상태 배지가 "모집 완료"가 된다
- Then  분석 탭의 "확정 수"가 20명이다
- Then  내 프로젝트의 "지금 확인할 일"에서 북로그 지원자 항목이 사라지고, "전체 현황"의 모집 완료가 1건 늘어난다
- Then  새로고침해도 결과가 남는다. 시연용이라 브라우저 쿠키(`demo-applications`)에 저장하고, 쿠키를 지우면 처음 상태로 돌아간다
- Then  서버도 다시 확인한다: 이 모집 건의 "지원" 상태가 아니거나, 정원을 넘거나, 모집이 끝났으면 저장하지 않는다 (화면 처리는 S526)
- 참고: 모집 마감 검사는 화면으로 보낼 수 없는 요청이라, E2E에서 요청 본문을 1차 모집의 대기 지원자 거절로 바꿔 확인한다. 1차 모집은 정원이 차 있어 확정으로는 정원 검사와 구분되지 않는다

S526 확정 요청 실패 [테스트]
- Given 확정·거절 요청을 보내는 중 네트워크가 끊겨 응답을 받지 못했다
- Then  페이지 전체 오류 화면이 아니라 목록 위에 안내가 보인다 (`role="alert"`). 먼저 바꿔 둔 "확정" 표시는 지운다
- Then  목록을 다시 받기 전에 현재 페이지에 가벼운 요청(HEAD)을 보내 서버에 닿는지 먼저 확인한다. `router.refresh()`는 재조회가 실패해도 잡을 수 없어 오류 화면으로 넘어가기 때문이다. `navigator.onLine`은 와이파이만 연결되고 인터넷이나 서버가 안 되는 경우를 구분하지 못해 쓰지 않는다
- When  서버에 닿는다
- Then  서버의 최신 지원자 목록을 다시 받아 화면을 맞추고 "연결이 불안정해 결과를 확인하지 못했어요. 지원자 목록을 다시 불러왔으니 상태를 확인해 주세요"가 보인다. 응답만 못 받고 서버에는 저장된 경우(백엔드 연결 후)도 서버 상태대로 보이게 하기 위해서다
- When  서버에 닿지 않는다 (브라우저가 오프라인이거나, 온라인이지만 인터넷·서버가 안 된다)
- Then  현재 목록과 "서버에 연결되지 않아 결과를 확인하지 못했어요. 연결되면 지원자 목록을 다시 불러올게요"가 그대로 보인다
- Then  `online` 이벤트가 오거나 3초마다 다시 확인하고, 서버에 닿으면 위처럼 목록을 다시 받는다. 서버만 내려간 경우는 `online` 이벤트가 오지 않아서 간격으로도 확인한다
- Given 서버가 요청을 거절했다 (S525의 서버 확인. 예: 다른 탭에서 정원을 채웠거나 페이지를 연 채 모집이 끝났다)
- Then  표시를 되돌리고 "확정하지 못했어요. 그사이 정원이 찼거나 모집이 끝났을 수 있어 지원자 목록을 다시 불러왔어요"가 보인다
- Then  서버의 최신 지원자 목록을 다시 받아, 다시 눌러도 같은 실패를 반복하지 않게 한다 (서버에 닿지 않으면 위와 같이 기다린다)
- Given 요청 중 로그아웃돼 서버가 로그인 화면으로 보낸다 (`redirect`, `notFound`도 같다)
- Then  연결 안내 없이 Next가 이동을 처리한다 (`unstable_rethrow`)

S358 피드백 제출 현황 (R116)
- Given 테스트 중인 모집(북로그 1차)
- Then  목록 위에 "피드백 제출 4명 · 미제출 1명 · 미완료 0명"이 보인다

- Then  테스트 전(모집 중·모집 완료)에는 제출 현황이 없다
- 참고: 목업은 피드백에 지원 id가 없어 닉네임으로 잇는다. API를 붙이면 지원(`Register`) id로 잇는다

S359 참여 취소 (R116)

- Then  그 줄에 "참여 취소" 배지가 붙고 확정 수에서 빠진다

S370 채팅 바로가기로 이동 (R116)
- When  샘플의 "윤슬님과 채팅"을 누른다
- Then  채팅함 검색 결과에 그 테스터와의 채팅이 보인다
- 참고: 채팅 목업에는 윤슬만 있어 다른 테스터의 링크는 빈 검색 결과로 간다. 윤슬의 채팅도 다른 프로젝트(가계부 노트 등)의 채팅이다. 채팅방 API가 정해지면 해결된다

S360 채팅 바로가기 (R116)
- Given 구독 모집
- Then  확정된 테스터 줄에 "채팅" 링크가 있고, 채팅함 검색(`/my/chats?q=닉네임`)으로 간다 (README: 구독 개발자와 선정된 테스터의 1대1 채팅)
- Then  확정되지 않은 테스터와 무료 모집에는 없다
- 참고: 채팅방 키는 채팅 담당 데이터(`booklog-yunseul` 같은 영문 키)라 바로 잇지 않고 검색으로 연결한다. 채팅방을 만드는 API가 정해지면 채팅방으로 바로 보낸다

S507 지원자 없음 [직접]
- Then  "아직 지원자가 없어요"가 보인다
- 참고: 지원자가 없는 샘플 모집 건이 없어서 E2E 테스트는 아직 없다

## 8. 피드백 탭 (R108)
제출된 피드백을 최신순으로 보여 주고, 72시간 안에 신고할 수 있다.

S508 피드백 목록 [테스트]
- When  `?tab=feedback`
- Then  최신순으로 닉네임, 내용, 제출 시각, 상태가 보인다
- Then  신고 대기 중이면 "n시간 뒤 자동 지급"이 함께 보인다

S509 신고 [테스트]
- Given 상태가 신고 대기이고 72시간이 지나지 않았다
- When  "신고"를 누른다
- Then  사유 입력 대화상자(`dialog`)가 열리고 포커스가 사유 칸에 간다
- When  사유를 비우고 "신고하기"를 누른다
- Then  "신고 사유를 적어 주세요" 오류가 보인다
- When  사유를 적고 "신고하기"를 누른다
- Then  대화상자가 닫히고 그 행의 상태가 "신고됨"이 된다 (목업이라 새로고침하면 돌아온다)
- When  Esc를 누른다
- Then  대화상자가 닫히고 포커스가 "신고" 버튼으로 돌아온다

S510 신고 불가 [테스트]
- Given 상태가 "신고됨"이나 "지급 완료"다
- Then  "신고" 버튼이 없다

S511 피드백 없음 [직접]
- Then  "아직 제출된 피드백이 없어요"가 보인다

S361 항목별 피드백과 스크린샷 (R117)
- Given 북로그 1차, `?tab=feedback`
- Then  목록 위에 "항목별 책 검색하기 1건 · 저장한 문장 다시 찾기 1건 · 기타 의견 1건"이 보인다. 기타 의견은 있을 때만 센다
- Then  피드백마다 테스트 항목 이름(없으면 "기타 의견") 배지가 붙는다
- Then  스크린샷이 있으면 썸네일이 보이고, 누르면 새 탭에서 크게 본다

S362 추천 (R118)
- Then  신고되지 않은 피드백마다 "추천" 버튼이 "신고" 옆에 있다(`aria-pressed`). 이미 추천한 피드백은 "추천함"이다(북로그 1차의 박서아)
- When  "추천"을 누른다
- Then  "추천함"으로 바뀌고, 목록 위 "추천 n건"이 늘고, "n님의 피드백을 추천했어요"가 `aria-live`로 읽힌다
- When  다시 누른다
- Then  추천에서 빠진다
- Then  신고된 피드백에는 추천 버튼이 없고 추천 수에서도 빠진다
- 참고: 목업이라 신고처럼 화면에서만 바뀌고 새로고침하면 돌아온다

## 9. 분석 탭 (R109)

### AI 분석 (R112)
분석 탭의 숫자 카드 아래에 피드백을 AI가 정리한 결과를 보여 준다. 지금은 AI가 없어서 UI만 만들고 시연용 샘플을 쓴다. 나중에 `api.ts`의 `findAiSummary`만 실제 AI API로 바꾼다. 구독 모집에서만 보인다.

S517 분석 결과 [직접]
- Given 구독 모집(북로그 1차), 신고된 피드백을 뺀 피드백 3건 이상, `?tab=analytics`
- Then  숫자 카드 아래 "AI 분석" 영역에 한 줄 요약, "고칠 점 n", "좋았던 점 n"이 이 순서로 보인다 (n은 항목 수)
- Then  고칠 점은 문제마다 칸 하나로 묶고, 그 안에 해결 제안("제안 …")을 바로 붙인다. 문제와 제안을 따로 떨어진 목록으로 두지 않는다
- Then  모든 항목은 문장 바로 옆에 근거 피드백 수("피드백 n건")를 붙인다
- Then  "AI가 정리한 내용이라 틀릴 수 있어요"와 정리한 날짜가 보인다
- Then  지금은 샘플이라 "시연용 샘플" 배지가 붙는다

S518 피드백 부족 [직접]
- Given 구독 모집이고 신고된 피드백을 뺀 피드백이 3건보다 적다(북로그, 아직 모집 중이라 0건)
- Then  "피드백이 3건 이상 모이면 AI가 정리해 드려요"와 현재 피드백 수(신고된 피드백 제외)가 보인다
- 참고: 신고된 피드백은 내용이 부실하거나 문제가 있어 분석 근거로 쓰지 않는다. 제출률(S512)에는 그대로 센다. 피드백은 3건 이상이지만 신고를 빼면 3건 미만인 샘플이 없어 이 경우의 E2E 테스트는 아직 없다

S519 분석 중 [직접]
- Given `demo-data=slow`
- Then  숫자 카드가 보인 뒤 AI 분석 영역은 스켈레톤이 먼저 보이고, 응답 뒤 결과가 보인다
