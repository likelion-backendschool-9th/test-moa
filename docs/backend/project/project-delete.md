# 프로젝트 삭제 API (#287)

개발자가 잘못 만든 프로젝트를 지우는 API. 지금은 프로젝트를 지울 수 없어 잘못 만들면 목록에 계속 남는다. 도메인 전체에서 정한 것은 [README.md](README.md)에 있고, 화면은 [개발자 프로젝트](../../frontend/project/projects.md#프로젝트-삭제-287)에 있다.

시나리오 제목 끝의 태그가 확인 방법이다. `[테스트]`는 백엔드 테스트와 1:1이다(`@DisplayName("#287-S…")`).

## 이슈 #287 확인

| 이슈 항목 | 시나리오 |
| --- | --- |
| 1·2 모집글이 없으면 삭제되고 목록에서 사라짐 | #287-S1 |
| 3·4 모집글이 있으면 409로 거절 | #287-S2, #287-S4 |

## 1. 프로젝트 삭제 (#287-R1)

| 동작 | API | 로그인 | 성공 |
| --- | --- | --- | --- |
| 프로젝트 삭제 | `DELETE /api/v1/developer/projects/{projectId}` | 필요 | 200 |

본문은 없다.

- 지울 수 있는 프로젝트: 모집글이 하나도 없다. 취소한 모집글도 센다(가정 1). 실제로 행을 지운다(가정 2)
- 함께 지워지는 것: 프로젝트 행에 있는 GitHub 레포 연결과 암호화한 토큰. 프로젝트를 가리키는 다른 테이블은 모집글뿐이라 모집글이 없으면 더 지울 것이 없다
- 대표 이미지 파일은 지우지 않는다. 다른 업로드처럼 안 쓰는 파일 정리는 #225가 한다
- 동시 요청: 모집 작성의 버전 매기기(#177)와 같은 프로젝트 행 잠금(`findByIdForUpdate`)을 잡은 뒤 모집글을 센다. 작성이 먼저면 삭제가 409이고, 삭제가 먼저면 작성이 잠금을 얻을 때 프로젝트가 없어 404다(고침 #287: 전에는 잠금 결과를 보지 않아 없는 프로젝트에 모집글을 저장하려다 500이었다)

| 상황 | 상태 | `error.code` |
| --- | --- | --- |
| 로그인하지 않음 | 401 | `UNAUTHORIZED` |
| 없는 프로젝트, 다른 회원의 프로젝트 | 404 | `NOT_FOUND` |
| 모집글이 있음(취소한 모집글 포함) | 409 | `PROJECT_NOT_DELETABLE` ("모집글이 있는 프로젝트는 삭제할 수 없어요") |

#287-S1 모집글이 없는 프로젝트를 삭제한다 [테스트]
- Given 모집글이 없고 GitHub 레포를 연결한 프로젝트
- When  삭제한다
- Then  200이고 행이 없어진다. 내 프로젝트 목록에 없고 상세는 404다

#287-S2 모집글이 있으면 삭제할 수 없다 [테스트]
- Given 모집 중인 모집글이 있는 프로젝트, 취소한 모집글만 있는 프로젝트
- Then  둘 다 409 `PROJECT_NOT_DELETABLE`이고 프로젝트가 남는다

#287-S3 다른 회원의 프로젝트와 비로그인 [테스트]
- Then  다른 회원의 프로젝트와 없는 프로젝트는 404, 비로그인은 401이고 프로젝트가 남는다

#287-S4 프로젝트 삭제와 모집 작성이 동시에 [테스트]
- Given 모집글이 없는 프로젝트
- When  같은 개발자가 삭제와 모집 작성을 동시에 보낸다(20번)
- Then  작성이 먼저면 삭제는 409이고 프로젝트와 모집글이 남는다
- Then  삭제가 먼저면 작성은 404이고 아무것도 남지 않는다
- 참고: 작성의 404 확인을 빼면 같은 테스트가 500으로 실패한다

## 범위 밖
- 모집글·피드백이 있는 프로젝트의 삭제나 숨김
- 대표 이미지 파일 정리(#225)

## 가정
1. 취소한 모집글만 있어도 지우지 않는다. 취소한 모집글도 버전 번호(#177)와 참가·피드백 기록을 가지고 있어 프로젝트가 없어지면 가리킬 곳이 사라진다
2. 숨김(soft delete) 대신 실제로 지운다. 모집글이 없는 프로젝트는 다른 기록이 가리키지 않아 남길 이유가 없다
